# Graph Functional PRD

> 日期：2026-06-16
>
> 状态：Draft
>
> 职责：定义 V1 Graph 页面需要提供的功能、信息、状态和交互逻辑。本文用于交互设计输入，不展开价值论证，不写技术实现方案。

## 1. 页面目标

Graph 页面用于让用户查看自己的 Understanding 如何通过 Connection 形成结构，并从图谱回到原 Understanding 继续整理。

用户在该页面需要完成：

1. 查看 Understanding 节点。
2. 查看 Understanding 之间的 Connection。
3. 识别孤立节点。
4. 识别缺少 Context 的节点。
5. 按范围缩小图谱。
6. 查看节点详情。
7. 从节点详情打开原 Understanding。

## 2. 页面范围

### 2.1 本期包含

| 模块       | 说明                                                                               |
| ---------- | ---------------------------------------------------------------------------------- |
| Graph 画布 | 展示节点和边，支持缩放、平移、点击节点                                             |
| 顶部筛选   | 按 Domain / 状态缩小图谱范围                                                       |
| 图例       | 解释节点状态和边的含义                                                             |
| 节点详情   | 展示单条 Understanding 的标题、摘要、Context 状态、所属 Domain、连接列表和操作入口 |
| 空状态     | 处理无数据、筛选无结果                                                             |

### 2.2 本期不包含

| 不做                              | 说明                                                     |
| --------------------------------- | -------------------------------------------------------- |
| AI 自动生成 Connection            | Graph 只展示用户已确认的 Connection                      |
| 在 Graph 内创建 / 编辑 Connection | 关系管理回到 Understanding 编辑或正文双链完成            |
| Context 作为独立节点              | Context 是 Understanding 的支撑信息，不是 Graph 一级对象 |
| Domain 作为独立节点               | Domain 用作筛选和上下文，不作为图谱节点                  |
| 统计 Dashboard                    | 不展示数量卡片、掌握度评分、完成度                       |
| 时间演化视图                      | 不展示历史变化、成长轨迹、版本对比                       |
| 保存视图                          | 不支持保存筛选组合或画布位置                             |
| 搜索入口                          | V1 先不做搜索和搜索结果定位，保持图谱主流程轻量          |
| 高级查询                          | 不做复杂条件组合、布尔检索、关系路径搜索                 |

## 3. 信息对象

### 3.1 Node

Node 表示一条 Understanding。

Node 至少包含以下信息：

| 字段            | 说明                         | 展示位置                           |
| --------------- | ---------------------------- | ---------------------------------- |
| id              | Understanding 唯一标识       | 不直接展示                         |
| title           | Understanding 标题           | 节点、详情                         |
| summary         | Understanding 摘要或正文开头 | 详情                               |
| domain          | 所属 Domain                  | 节点辅助信息、详情、筛选           |
| contextPresence | 是否有 Context               | 节点状态、详情                     |
| connectionCount | 已连接数量                   | 详情和连接列表，不用于节点视觉状态 |
| updatedAt       | 最近更新时间                 | 详情                               |

### 3.2 Edge

Edge 表示两条 Understanding 之间的 Connection。

Edge 至少包含以下信息：

| 字段          | 说明                                  | 展示位置                    |
| ------------- | ------------------------------------- | --------------------------- |
| sourceNodeId  | 起点 Understanding                    | 画布                        |
| targetNodeId  | 终点 Understanding                    | 画布                        |
| relationLabel | 关系说明，如有                        | 边 hover / 节点详情连接列表 |
| createdBy     | 关系Context，必须是用户显式创建或确认 | 不一定直接展示              |

Edge 不表示系统猜测、相似度、推荐关系。

### 3.3 Domain

Domain 表示 Understanding 的归属范围。

Domain 在 Graph 中只承担：

1. 筛选范围。
2. 节点上下文。
3. 连接两端的辅助说明。

Domain 不作为图谱节点，不参与边的主叙事。

## 4. 页面布局功能

### 4.1 顶部工具区

顶部工具区用于缩小观察范围。

必须包含：

| 功能        | 说明                                                 |
| ----------- | ---------------------------------------------------- |
| 新建入口    | 创建新的 Understanding，并默认进入该节点详情         |
| Domain 筛选 | 选择一个或多个 Domain 后，只展示范围内的节点和相关边 |
| 状态筛选    | 支持查看全部、有 Context、无 Context                 |
| 重置入口    | 清空筛选，回到默认图谱                               |

交互逻辑：

1. 默认进入页面时展示全部可展示节点。
2. 用户选择 Domain 后，画布只展示命中 Domain 的节点。
3. 状态筛选和 Domain 筛选可以叠加。
4. 重置后清空 Domain 和状态筛选。

### 4.2 Graph 画布

画布是页面主体。

必须支持：

| 能力         | 说明                                      |
| ------------ | ----------------------------------------- |
| 展示节点     | 每条 Understanding 对应一个节点           |
| 展示边       | 每条 Connection 对应一条边                |
| 展示孤立节点 | 没有 Connection 的 Understanding 仍然显示 |
| 缩放         | 用户可以放大 / 缩小图谱                   |
| 平移         | 用户可以拖动画布查看不同区域              |
| 点击节点     | 打开节点详情                              |
| 选中节点高亮 | 被选中的节点和直接相连的边更突出          |
| 自动适配视图 | 首次进入或重置后，图谱适配当前画布范围    |

不要求支持：

1. 拖动节点改变长期布局。
2. 框选多个节点。
3. 在画布上新增节点或边。
4. 右键菜单。
5. 多层级展开 / 收起。

### 4.3 图例

图例只解释画布中需要额外说明的 Context 状态。

必须说明：

| 状态            | 含义                          |
| --------------- | ----------------------------- |
| 无 Context 节点 | 该 Understanding 缺少 Context |

图例只解释事实状态，不引导用户理解为评分或完成度。

## 5. 节点状态逻辑

### 5.1 Context 状态

每个节点需要判断是否有 Context。

| 状态       | 判断逻辑                           | 页面表达               |
| ---------- | ---------------------------------- | ---------------------- |
| 有 Context | Understanding 关联至少一个 Context | 普通状态               |
| 无 Context | Understanding 没有关联 Context     | 节点需要有明确视觉区分 |

无 Context 不表示错误，只表示该 Understanding 缺少形成Context。

### 5.2 Connection 表达

Connection 不作为节点视觉状态单独编码，而通过边是否存在直接表达。

| 状态   | 判断逻辑                | 页面表达                     |
| ------ | ----------------------- | ---------------------------- |
| 已连接 | 至少存在一条 Connection | 显示与其他节点之间的边       |
| 未连接 | 不存在任何 Connection   | 节点独立显示，不额外叠加样式 |

未连接不表示无效，只表示该 Understanding 尚未被整合到其他理解中。

### 5.3 多状态叠加

同一个节点可能同时满足多个状态。

例如：

| 情况                | 表达要求                               |
| ------------------- | -------------------------------------- |
| 有 Context + 已连接 | 普通节点，并显示 Connection 边         |
| 无 Context + 已连接 | 需要表达无 Context，同时保留边         |
| 有 Context + 未连接 | 普通节点，不额外叠加未连接样式         |
| 无 Context + 未连接 | 只表达无 Context，不额外叠加未连接样式 |

交互设计需要保证多状态可识别，不能让一种状态覆盖另一种状态。

## 6. 节点详情

用户点击节点后打开节点详情。

节点详情可以是侧边栏、浮层或抽屉，但需要满足：

1. 不遮挡用户理解当前节点在图中的位置。
2. 能持续显示，直到用户关闭或选择其他节点。
3. 用户选择其他节点时，详情内容同步切换。

### 6.1 详情内容

节点详情必须展示：

| 信息                 | 说明                                            |
| -------------------- | ----------------------------------------------- |
| 标题                 | Understanding 标题                              |
| 摘要                 | Understanding 摘要或正文开头                    |
| Domain               | 所属 Domain                                     |
| Context 状态         | 有 Context / 无 Context                         |
| Connection 状态      | 已连接数量 / 未连接                             |
| 连接列表             | 与当前 Understanding 已连接的其他 Understanding |
| 最近更新时间         | 帮助用户判断内容新旧                            |
| 打开原 Understanding | 跳转到原 Understanding 详情或编辑页             |

### 6.2 连接列表

连接列表展示当前节点的直接 Connection。

每条连接至少展示：

| 信息                    | 说明                                 |
| ----------------------- | ------------------------------------ |
| 对端 Understanding 标题 | 与当前节点相连的另一条 Understanding |
| 对端 Domain             | 作为上下文辅助判断                   |
| 关系说明                | 如 Connection 有说明，则展示         |
| 定位入口                | 点击后在画布中选中对端节点           |

连接列表只展示一跳关系，不展示二跳、路径分析或推荐关系。

### 6.3 操作入口

节点详情必须提供：

| 操作                 | 说明                                                                 |
| -------------------- | -------------------------------------------------------------------- |
| 打开原 Understanding | 进入原 Understanding 页面，用户可补 Context、修改正文、补 Connection |
| 在图中定位连接节点   | 从连接列表点击对端 Understanding 后，画布聚焦并选中该节点            |
| 关闭详情             | 关闭详情并取消节点选中                                               |

本期不在节点详情内直接编辑标题、正文、Context 或 Connection。

## 7. 筛选功能

### 7.1 Domain 筛选

Domain 筛选用于缩小观察范围。

逻辑：

1. 支持选择一个或多个 Domain。
2. 选择后，只展示属于这些 Domain 的节点。
3. 当边的两端节点都在可见范围内时，展示该边。
4. 当边只有一端节点在可见范围内时，默认不展示该边。

说明：

Graph V1 不需要为了展示跨 Domain Connection 而额外引入外部节点。

### 7.2 状态筛选

状态筛选用于查看特定类型节点。

必须支持：

| 筛选项     | 结果                    |
| ---------- | ----------------------- |
| 全部       | 展示当前范围内所有节点  |
| 有 Context | 只展示有 Context 的节点 |
| 无 Context | 只展示无 Context 的节点 |

状态筛选与 Domain 筛选叠加。

### 7.3 重置筛选

重置后：

1. 清空 Domain 筛选。
2. 清空状态筛选。
3. 取消节点选中。
4. 画布重新适配全部节点。

## 8. 空状态

### 8.1 全局无数据

当用户没有任何 Understanding 时，Graph 显示空状态。

空状态需要说明：

1. 当前还没有可展示的 Understanding。
2. 用户需要先创建 Understanding。

可提供入口：

1. 创建 Understanding。
2. 返回主工作区。

### 8.2 有节点但无 Connection

当用户有 Understanding，但没有任何 Connection 时：

1. 画布展示所有孤立节点。
2. 不显示边。
3. 提示这些 Understanding 尚未建立 Connection。

不能把该状态表达为错误。

### 8.3 筛选无结果

当筛选后没有节点时：

1. 保留筛选区。
2. 显示无结果说明。
3. 提供清空筛选入口。

## 9. 默认展示逻辑

用户首次进入 Graph：

1. 展示全部可展示 Understanding。
2. 展示所有两端节点均可见的 Connection。
3. 自动适配画布，使主要节点出现在可视区域。
4. 不默认选中任何节点。
5. 顶部筛选为空。

如果节点数量较少：

1. 节点可以全部展示。
2. 孤立节点也必须展示。

如果节点数量较多：

1. 仍默认展示全部节点。
2. 通过布局、缩放和筛选控制可读性。
3. V1 不引入默认折叠或分页。

## 10. 用户路径

### 10.1 查看整体结构

1. 用户进入 Graph。
2. 看到所有 Understanding 节点和 Connection 边。
3. 识别哪些节点连接较多，哪些节点孤立。
4. 通过图例理解无 Context 节点状态。

### 10.2 按 Domain 回看

1. 用户选择一个 Domain。
2. 图谱进入该 Domain / Domain 的回看范围。
3. 当前 Domain 内的 Understanding 成为主画布，用户能扫视哪些理解成组、哪些孤立、哪些缺 Context。
4. 与其他 Domain 有显式 Connection 的相关概念只作为边缘线索出现，不能抢占当前 Domain 主视觉。
5. 用户 hover / selected 某条 Understanding 后，局部连接被强化，其他连接保持克制。
6. 用户点击节点查看详情。

### 10.2.1 Domain-scoped Wander

1. 用户锁定一个 Domain。
2. 用户不依赖系统推荐，而是通过空间组织自己寻找值得回看的局部结构。
3. 用户能看到当前 Domain 内部的 cluster、孤岛和桥接关系。
4. 用户能快速望见与其他 Domain 有呼应的概念，但外部概念只作为 ghost / 边缘提示。
5. 用户点击一个局部后，局部关系强化，帮助继续游走。
6. 用户可以从当前 Understanding 回到原 Understanding继续整理。

### 10.3 处理无 Context 节点

1. 用户通过节点状态或状态筛选发现无 Context 节点。
2. 点击节点打开详情。
3. 查看该 Understanding 的摘要和连接情况。
4. 点击打开原 Understanding。
5. 在原 Understanding 中补 Context。

### 10.4 处理孤立节点

1. 用户通过没有连线的节点发现未连接节点。
2. 点击节点打开详情。
3. 判断该理解是否需要继续整理。
4. 点击打开原 Understanding。
5. 在原 Understanding 中补正文双链或 Connection。

## 11. 功能验收标准

### 11.1 Graph 画布

- 用户能看到 Understanding 节点。
- 用户能看到 Connection 边。
- 没有 Connection 的节点也会展示。
- 用户能缩放、平移画布。
- 用户点击节点后能打开详情。
- 选中节点后，该节点和直接相连的边有明确状态。
- 用户锁定 Domain 后，画布能以该 Domain 内部 Understanding 为主视觉。
- 当前 Domain 内的局部成组、孤岛和桥接关系能被扫视出来。
- 外部 Domain 相关概念只能作为边缘提示，不应与当前 Domain 内节点同等抢占注意力。

### 11.2 节点状态

- 用户能分辨有 Context 和无 Context 的节点。
- 用户能通过边的存在与否分辨已连接和未连接的节点。
- 同时无 Context 且未连接的节点只叠加无 Context 状态，不额外叠加未连接状态。
- 图例能解释无 Context 节点状态。

### 11.3 筛选

- 用户能按 Domain 筛选节点。
- 用户能按 Context 状态筛选节点。
- Domain 和状态筛选可以叠加。
- 用户能一键重置筛选。
- 筛选无结果时有明确空状态。

### 11.4 节点详情

- 用户能看到节点标题、摘要、Domain、Context 状态、Connection 状态和更新时间。
- 用户能看到当前节点直接连接的其他 Understanding。
- 用户能从连接列表定位到对端节点。
- 用户能打开原 Understanding。
- 用户能关闭详情。

## 12. 交互设计需要产出的界面

交互设计至少需要覆盖：

1. Graph 默认页。
2. 节点选中后的详情状态。
3. 无 Context 节点状态。
4. Domain 筛选展开 / 已选状态。
5. 状态筛选展开 / 已选状态。
6. 筛选无结果。
7. 全局无 Understanding 空状态。
8. 有 Understanding 但无 Connection 状态。
9. 图例常驻状态。

## 13. 设计边界

交互设计需要遵守：

1. 第一屏主对象只有 Node 和 Edge。
2. Context 不设计成一级节点。
3. Domain 不设计成一级节点。
4. 不使用统计卡片作为 Graph 的主表达。
5. 不出现掌握度、完成度、质量分等评分表达。
6. 不把孤立节点表达为错误。
7. 不把无 Context 节点表达为失败，只表达缺少Context。
8. 不展示 AI 推断但用户未确认的关系。
9. 不把 Graph 做成关系管理后台。
10. Graph 的整理动作最终回到原 Understanding。
