# React Flow Whiteboard 实现工作

> 日期：2026-08-19
>
> 对照基线：当前工作区实现（含未提交改动）与 `understanding-canvas-prd.md`
>
> 范围：仅 Whiteboard，即 M2 画布工作区、M3 元素体系、M4 关系与连线、M7 编辑体验与数据

## 1. 范围边界

本轮目标不是自行列举所有画布手势，而是让 React Flow 负责通用交互，Reflecta 只实现 PRD 明确要求的组件、业务语义和持久化边界。

不在本轮处理：M1 画布管理、M5 理解库、M6 理解详情、M8 Agent 协作。

明确不做：

- 矩形、圆形等通用图形元素；Whiteboard 只保留文本卡与 Reflecta 内部元素（理解卡、组、画布引用）。
- 元素锁定、对齐辅助线、撤销重做、智能路由、自定义框选手势。
- 用 Reflecta 自定义逻辑覆盖 React Flow 已提供的选择、框选、拖动、缩放、平移和键盘删除行为。

## 2. 当前已经成立的能力

- React Flow 已使用受控 nodes / edges / viewport，并能把位置、尺寸、删除和视口变化写回文档。
- 节点已有选中与拖动反馈；文本卡支持创建和就地编辑。
- 理解卡、文本卡、组、画布引用已有渲染；理解引用删除后有占位状态。
- 连线已有方向、标签和样式编辑，文档映射能保存 parentId 与组内相对坐标。
- MiniMap、背景、缩放控制和画布搜索入口已经存在。

这些能力无需重写，只补齐与 PRD 的差距并删除多余覆盖。

## 4. 实施工作

### W1 删除不属于产品的元素与状态

- 从工具栏、节点工厂、节点注册和空状态中删除矩形 / 圆形入口与 `ShapeNode`。
- 从 renderer、server DTO、解析、校验、搜索、fixtures 中删除 `shape` kind 与 `shapeType`。
- 从画布元素类型中删除 `locked`；这不影响“引用已删除”的占位图标。
- 删除 shape 对应 Feature 场景和 Acceptance，废弃的稳定用例 ID 不复用。
- 先检查真实非测试数据是否存在 shape。没有数据则直接移除；存在数据则先定义显式迁移，禁止解析时静默丢元素。

完成标准：产品、类型、存储与测试中不存在可创建或保存的通用图形元素，也不存在元素锁定语义。

### W2 收窄 React Flow adapter

- 编辑态删除自定义 `deleteKeyCode`，继承固定 React Flow 版本的默认键位；只读态保留禁用删除所需配置。
- 删除无行为的 `onInit`、未消费的 minimap options、无用途的 document ref 等死接口。
- 删除非产品要求的 `minZoom`、`maxZoom`、`connectionLineStyle` 覆盖；确有视觉要求时登记到 override ledger 后保留。
- 保留受控状态、只读边界、文档映射和外部拖入坐标转换，这些属于 Reflecta adapter 的职责。

完成标准：通用选择、框选、平移、缩放、拖动和删除由 React Flow 默认行为决定；adapter 只保留业务必要差异。

### W3 补齐交互反馈与理解卡缩放

- 验证并补齐节点的 selected、dragging、focus-visible 状态。
- 验证 Handle 的 idle、connecting、valid、invalid 状态，保证连接是否可落下有即时反馈。
- 保证自定义边样式不会遮蔽 React Flow 的 selected 状态。
- 仅给理解卡接入 React Flow `NodeResizer`；只读态不可调整，尺寸变更写回文档并能重载恢复。

完成标准：用户能看见当前选择、键盘焦点、拖动、连接是否合法以及边的选中状态；理解卡尺寸可持久化。

### W4 完成组的业务语义

- 组节点增加可连接 Handle，使其与 M4-1 一致。
- 节点拖入组、拖出组和组内嵌套在拖动结束时更新 parentId，并正确转换绝对 / 相对坐标。
- 阻止把组放入自身或后代，避免 parent graph 成环。
- 使用项目已有 ContextMenu 提供“删除组及成员”和“解组并保留成员”。
- 将级联删除、解组和坐标转换实现为少量纯文档变换函数，供 UI 与测试共同调用；不新增手势级服务端 API。

完成标准：创建、入组、出组、嵌套、移动、连线、删除和解组形成完整闭环，并在重载后保持结构与位置。

### W5 修正连线约束

- 创建连线时不用 `addEdge` 的同端点去重语义，改为追加带唯一 id 的 edge，以满足同一对元素存在多条不同关系。
- 使用 React Flow `isValidConnection` 在 UI 阶段禁止自环，与服务端校验一致。
- 继续使用 React Flow 标准 Handle 与 edge types，不实现吸附重路由或智能路由。

完成标准：同一 source / target 可以保存多条连线，自环在操作时即不可创建，其他连接行为沿用 React Flow。

### W6 修正画布搜索

- 修复重复注册的 keydown listener，快捷键只保留 PRD 定义的 Cmd/Ctrl+F。
- 理解卡搜索覆盖标题与正文；文本卡覆盖正文；组覆盖组名；连线覆盖标签。
- 点击节点结果时定位并选中节点；点击连线结果时聚焦其 source / target 并选中该边。

完成标准：搜索范围、快捷键、关闭方式和结果定位与 M2-6 一致，且不会因重复 listener 出现双重切换。

### W7 让持久化失败可见且可恢复

- 保存失败不能静默吞掉：保留 dirty 状态，给出错误反馈，并允许后续变更或显式重试再次保存。
- 页面卸载或画布切换前 flush 最后一批待保存变更，避免 debounce 尾部丢失。
- 恢复位置持久化的有效断言：验证模型坐标或保存后的 document，不用受 `fitView` 影响的屏幕坐标代替。
- 增加尺寸、组 parentId / 相对坐标、平行连线的保存—重载 round-trip 验收。

完成标准：用户知道保存是否失败，最后一次编辑不会无声丢失，关键 Whiteboard 文档结构都有重载证据。

### W8 补齐明确缺失的工作区功能

- 演示模式按组顺序聚焦，提供 prev / next / 退出；无组时退化为 fit view。放在组语义稳定后实现。
- PNG 导出使用 React Flow 官方客户端导出方案，导出全部内容且排除背景；仅在现有依赖无法完成时增加最小图像导出依赖。

完成标准：M2-7、M2-8 的用户流程和 Acceptance 可通过。

## 5. 测试与规格同步

- `canvas-editing.feature` 删除“辅助线 / 撤销”等未承诺描述，保留基于业务结果的编辑场景。
- `canvas-elements.feature` 从“五类元素”改为文本卡与 Reflecta 内部元素，删除图形场景。
- 为理解卡缩放、组完整闭环、平行连线、演示模式、PNG 导出补 Acceptance。
- React Flow 默认行为只保留一组基准回归测试，验证 adapter 没有意外覆盖；不把所有鼠标、键盘和触控组合复制成产品 Feature。
- Whiteboard Feature 描述业务结果；React Flow 默认键位和手势细节放在 integration principles 与基准测试中。

## 6. 建议顺序

```text
W1 删除 shape / locked
 → W2 收窄 adapter
 → W3 反馈与理解卡缩放
 → W4 组
 → W5 连线
 → W6 搜索
 → W7 持久化
 → W8 演示与导出
```

先删除错误范围，再补核心编辑闭环，最后实现依赖组结构的演示与相对独立的导出，避免为即将删除的类型继续写代码和测试。
