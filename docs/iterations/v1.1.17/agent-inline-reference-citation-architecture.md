# Agent Inline References: Citation Architecture

> 状态：Implemented
>
> 日期：2026-07-02

## 一句话

Agent 最终回答就是普通 Markdown 文本。正文里的 `[n]` 只是当前 assistant answer 内的 citation marker；真实 Reflecta entity 绑定保存在同一条 answer 的 `citationSources` 上。

```ts
type AgentCitationSource = {
  index: number;
  entity: {
    type: "understanding" | "context" | "domain";
    id: string;
    title?: string;
  };
  origin?: AgentEntityCatalogEntry["origin"];
};

type AssistantAnswer = {
  text: string;
  citationSources?: AgentCitationSource[];
};
```

`[1]` 不是 entity id，不是 handle，也不能给工具调用用。它只有和当前 answer 的 `citationSources` 放在一起才有意义。

## Pipeline

```text
User input
  -> selected @ refs enter AgentEntityCatalog
  -> read-only tools add returned entities to AgentEntityCatalog
  -> host builds numbered citation sources
  -> prompt exposes those sources as [1], [2], ...
  -> Agent streams plain markdown text
  -> frontend renders immediately
  -> renderer converts valid [n] to Reflecta entity title links
  -> host extracts actually cited indices
  -> persist assistant.turn text + citationSources
```

There is no `reflecta_final_answer`, no `AgentTextPart`, no `entity_ref`, no `assistant.final.*`, and no second LLM finalizer in the main path.

## The Three Identities

Keep these separate.

### Entity Identity

Reflecta's real object identity:

```text
understanding:u_123
context:ctx_456
domain:d_789
```

Only real ids may enter tool parameters, storage records, `AgentEntityCatalog`, and click handlers.

### Citation Marker

The text marker the model may write:

```text
[1]
[2]
```

Its scope is one assistant answer. It is display syntax only.

### Rendered Link

The renderer combines `text + citationSources`:

```text
text: "这和 [3] 有关"
citationSources: [{ index: 3, entity: { id: "u_123", title: "过程指标" } }]

rendered: "这和 过程指标 有关"
```

The persisted text keeps `[3]`; the visible link label is the entity title. Unknown markers remain plain text.

## Source Sets

Do not collapse these into one concept.

### Thread Catalog

`AgentEntityCatalog` is the thread/run material pool: entities selected by the user or returned by tools.

### Prompt Citation Sources

Sources exposed to the model in this run. v1 policy:

```text
At run start:
  promptCitationSources = threadCatalog

When read-only tools return new entities:
  append new entities to the existing source map
  do not renumber old sources
```

This is a policy, not a renderer contract. Later we can narrow it when the catalog is too large. The renderer and persistence model do not need to change.

### Answer Citation Sources

Sources actually cited by the final text.

If the prompt exposed `[1]..[57]` and the answer used `[3]` and `[10]`, persist sparse indices:

```ts
[
  { index: 3, entity: source3 },
  { index: 10, entity: source10 },
];
```

Never renumber this to `[1]` and `[2]`; the text already contains `[3]` and `[10]`.

## Streaming

Streaming stays plain text. The frontend receives text deltas immediately with the current source map.

```text
text stream: "参考 " "[" "3" "]"
source map:  [3] -> understanding:u_123
```

The renderer may upgrade a complete marker like `[3]` into a link once it can match the marker. Incomplete markers, unknown markers, and markers inside inline/fenced code stay plain text.

## Runtime Responsibilities

### Host

- Maintain `AgentEntityCatalog`.
- Build and append citation source numbers.
- Put available citation sources into the prompt.
- Stream `assistant.text.delta` with the current citation source map.
- Persist final `assistant.turn.text`.
- Extract cited indices from final Markdown outside code.
- Persist only actually cited sparse `citationSources`.

### Prompt Adapter

- Show the numbered sources the Agent may cite.
- Tell the Agent citation numbers are final-answer text only.
- Tell the Agent tools must use real ids.

### Renderer

- Render Markdown normally.
- Convert valid `[n]` markers using the current message's `citationSources`.
- Show the entity title as the link text.
- Never title-match arbitrary words.
- Never infer a source from old messages.

### Write Tools

Reject display tokens in real id fields:

```text
[1]
U1
D1
ref:*
[[...]]
```

## Migration State

Legacy persisted `blocks[].parts[].entity_ref` data was migrated directly in:

- `<projectRoot>/.local/reflecta-prod`
- `<projectRoot>/.local/reflecta-test`

The project intentionally does not keep a runtime migration path. Old clickable references survive because session JSONL files were rewritten once to `text + citationSources`.

## Hard Rules

- `[n]` is scoped to one assistant answer.
- Source maps are generated by host, never by the model.
- Model output may choose where to place `[n]`; it may not invent valid sources.
- Renderer only links known sources from the current message.
- Invalid citation markers do not fail the answer.
- Tool parameters only accept real Reflecta ids.
- No title matcher.
- No reference registry.
- No structured final answer path.
