# 个人知识 / 对话产品的「使用痕迹统计」模块调研报告

## 1. 背景介绍

本报告调研的模块是：**个人知识管理（PKM）+ AI 对话类产品中，向个人用户展示"使用痕迹"的统计模块**——即应用首页 / 仪表盘 / 侧栏上的活动统计、热力图、连续记录、年度回顾等。

**调研目的**：Reflecta 当前的 Capture 首页统计（CaptureStats）只基于一种实体——「理解笔记（Understanding）」，统计总理解数、本周新增、连续记录天数、上下文总数，并配 12 周热力图。用户认为这套展示逻辑不合理，直觉是"这里应该展示所有用这个产品的痕迹，包括对话、理解笔记以及画布等"。本报告调研行业里相似产品如何做这类统计，如实呈现行业现状与规律，供用户自行判断。

**客观信息骨架**：

- 调研模块：使用痕迹 / 活动统计（usage & activity statistics）
- 覆盖产品：Flomo、语雀、Day One、Apple Journal、ChatGPT、Claude、Gemini、Perplexity、Obsidian（插件生态）、Logseq（插件生态）、Notion、Evernote、Readwise、GitHub（范式源头）、Heptabase
- 调研时间：2026-08-16
- 信息来源：官方帮助中心 / 文档 / Changelog / 官网为主；个别产品（ChatGPT 年度回顾、语雀文档统计、语雀文稿数）仅有媒体报道或第三方教程，已在对应条目标注来源类型

**理解假设**：本报告按"个人知识 + AI 对话应用的跨实体使用痕迹统计"理解该模块；若实际指别的（例如团队级统计），请指出，将重新选品调研。

**用户产品自身的约束背景**（来自 Reflecta 项目文档，非调研结论）：value-proposition.md 明确「把知识边界做成抽象分数或仪表盘」属于 Never 方向，主张"用户需要看见具体理解、上下文、关系和空白，而不是泛化评分"；feature-set-guide.md 在图谱形态下把「数量统计 dashboard」列为 Not Now。这些是用户既有决策，作为判断背景供参考，本报告不据此替用户下结论。

## 2. 调研范围与产品

### 形态空间

「使用痕迹统计」在同一模块下有六种主流解法形态：

| 形态               | 说明                                                          | 代表产品                                                                                            |
| ------------------ | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| A. 习惯/连续性统计 | 常驻的热力图 + 连续记录（streak）+ 汇总卡，主打"保持记录节奏" | Flomo、Day One、Apple Journal、Readwise、GitHub（范式源头）                                         |
| B. 回顾式报告      | 一次性年度/月度报告（Spotify Wrapped 式），回顾使用模式       | ChatGPT（Your Year）、Claude（Monthly Recap）、语雀（年度报告）                                     |
| C. 插件生态统计    | PKM 核心无内置统计，由第三方插件/脚本补齐                     | Obsidian 插件、Logseq 插件、chatgpt-data-viewer                                                     |
| D. 配额/用量仪表盘 | 计费导向的用量与额度监控（AI 侧）                             | Claude Settings > Usage、ChatGPT 用量页                                                             |
| E. 内容/协作分析   | 单篇内容阅读量、团队/工作区级活动分析                         | Notion Page Analytics、Notion Workspace Analytics、语雀文档统计、Evernote Teams、ChatGPT Enterprise |
| F. 无统计          | 官方不做统计，仅提供历史/活动管理（偏隐私/管理视角）          | Notion（个人）、Evernote（个人）、Heptabase、Gemini、Perplexity                                     |

### 分层与入选理由

| 层                                 | 产品                    | 入选理由                                                                                 |
| ---------------------------------- | ----------------------- | ---------------------------------------------------------------------------------------- |
| 直接竞品（个人知识 + AI 对话形态） | Flomo                   | 官方**内置**热力图 + 多维度统计，是"个人知识应用统计"最完整的直接参照                    |
|                                    | 语雀                    | 官方"文稿数"按**多种内容类型**（小记/文档/表格/画板/数据表）计数，是少见的跨实体计数先例 |
|                                    | Day One / Apple Journal | 日记类 streak + 日历热力范式，官方文档明确                                               |
|                                    | ChatGPT / Claude        | AI 对话侧官方统计的现状代表（回顾报告 + 用量）                                           |
| 间接竞品（相邻形态）               | Obsidian / Logseq       | PKM 主流，但统计全靠插件生态——"官方无统计"这一事实本身是重要参照                         |
|                                    | Notion / Evernote       | 个人无统计、官方统计只有协作/管理视角的典型                                              |
|                                    | Readwise                | 复习类应用的统计（streak + 补卡 recover）                                                |
| 跨域参照（不同解法）               | GitHub                  | 贡献热力图（365 天网格）是几乎所有上述统计的视觉范式源头                                 |
|                                    | Heptabase               | 与 Reflecta 定位最接近（视觉知识库），官方未提供统计——事实性空白本身是发现               |

覆盖校验：六种形态均有代表；Heptabase 单独入选是因为它与 Reflecta 定位最近、但无统计，属于"直接竞品不足时把相邻产品计入"的情形。

## 3. 调研结果

### 3.1 调研总结论

**结论一：行业里"个人使用痕迹统计"普遍以单实体为对象，且高度收敛到同一套视觉范式。**

几乎所有做个人统计的产品都以**一种实体**（memo / 日记条目 / 笔记文件 / 对话）为计数对象，呈现为 **GitHub 式热力图 + 连续记录（streak）+ 少量汇总数字**：

- Flomo 官方：侧栏 12 周热力图（周一开头、五档深浅）+ 记录统计（累计笔记数、标签数、记录天数等八维度）。
- Day One：Journal Streaks（连续创建条目的天数）+ 日历视图。
- Apple Journal：Insights（日/周 streak + 日历）。
- Obsidian / Logseq：第三方插件（Vault Activity Heatmap、obsidian-data-analysis、Keep the Rhythm、vault-pulse、logseq-plugin-heatmap）几乎全部是"GitHub 式热力图 + 总笔记数/总字数/连续天数/平均字数 summary card + 趋势图"。
- GitHub 官方：贡献图 = 365 天网格，按天着色，是这一范式的源头。

Reflecta 现有 CaptureStats（总理解/本周新增/连续记录 + 12 周热力图）正属于这一范式——它是"单实体（理解笔记）活动统计"的行业标准做法。

**结论二：行业内没有"跨实体类型的统一痕迹统计"的成熟先例。**

检索到的所有产品中，**没有一个**把"笔记 + 对话 + 画布 + 其他实体"聚合进一个统一统计视图。最接近的两个：

- 语雀「文稿数」：按账号下的**小记、文档、表格、画板、数据表**分别计数并汇总（个人会员页/空间管理可见）——但它是**配额计数器**（每月 1 号清零、删除不释放），不是仪表盘，不呈现趋势/节奏。
- Flomo「记录统计」：宣称"八个维度"，但维度都来自 memo 单一实体（数量、标签、天数等），不是跨实体。

这意味着用户设想的"展示所有使用痕迹（对话、理解笔记、画布）"**没有现成竞品范式可抄**——这是一个真实的行业空白，也是本报告最重要的研究发现。

**结论三：AI 对话侧对个人"使用痕迹"统计极其克制，只有两种形态。**

- 一次性回顾报告：ChatGPT "Your Year with ChatGPT"（年度，展示消息数、聊天数、聊天风格、最活跃日、生成图片数等，需开启 chat history + memory，非全部用户可用）；Claude Monthly Recap（月度，beta，展示主题与使用时间模式，需开启 memory）。
- 计费导向的用量仪表盘：Claude Settings > Usage（实时用量、月度花费、5 小时/每周限额进度条）、ChatGPT 用量页。
- Gemini 只有 My Activity 活动记录管理（隐私视角，可查看/删除 prompt）；Perplexity 只有 History/Threads 管理。**没有**常驻的活动热力图或使用统计。
- 有趣的是，ChatGPT 的热力图需求由第三方补上：开源项目 chatgpt-data-viewer 用导出数据渲染 GitHub 式贡献图。

**结论四：PKM 官方普遍不做统计，统计以"插件 / 模板 / 用户自制"形式存在；官方提供的分析偏向协作或配额视角。**

- Obsidian、Logseq 官方均无统计功能，由插件生态覆盖（结论一的插件清单）。
- Notion 个人无统计；官方只有 Page Analytics（单页阅读量、编辑者，偏传播/协作）和 Workspace Analytics（Enterprise 计划，团队级）。
- Evernote 个人无统计；官方只有 Teams 的 Activity History（管理员查看成员操作日志）。
- 语雀的统计也分两轨：个人侧是年度报告 + 文稿数配额；单篇文档统计分析（阅读数/独立访客/平均阅读时长/编辑历史）偏内容运营视角。

**研究见解（基于上述事实）**：可以把行业现状概括为"**单实体统计是共识、跨实体统计是空白、AI 对话侧只有回顾与用量**"。用户对现有统计"不合理"的感受，很可能来自"拿单实体统计范式去服务一个多实体产品"——行业内对"多实体统一痕迹"既无成熟范式、也无直接竞品可参照，如何取舍是产品决策，本报告不替用户作答。

### 3.2 产品形态基础功能

#### 核心能力

**能力 1：活动热力图（GitHub 式贡献图）**

_能力解析_：把"每天有没有用、用了多少"压成一屏可扫的网格，让用户一眼看到长期节奏，而非单日结果。它是"使用痕迹统计"最核心、最常见的可视化，几乎所有个人统计都采用。分歧主要在：网格的时域（12 周 vs 365 天）、按什么计（创建数 vs 字数 vs 复合）、以及点击后能否回看当天内容。

_各家做法_：

- GitHub（源头）：365 天网格（52 周 × 7 天），按天贡献数着色，可切换公开/私有仓库。
- Flomo（官方内置）：12 周热力图，周一开头、最右是本周，四色五档深浅；**点击有记录的格子会直接筛选到当天记录**；侧栏可隐藏/显示。
- Obsidian 插件：Vault Activity Heatmap（365 天，可点某天看当天动过的文件）、obsidian-writing-heatmap（按创建笔记数与字数双维度）、vault-pulse（53×7 网格 + 点击某天列出文件）。
- Logseq 插件：logseq-plugin-heatmap（按当天 journal block 数），明确标注因 Logseq 无时间戳而"不够精确"。
- Day One：日历视图（非网格热力图，但同属按天着色的节奏可视化）。
- chatgpt-data-viewer（第三方）：对 ChatGPT 导出数据做 GitHub 式贡献图 + 全文字搜索。

**能力 2：连续记录（streak）**

_能力解析_：连续天数/周数是"养成习惯"的最强单一激励指标，也是热力图的自然补充（热力图看长周期，streak 看当下连续性）。分歧在：连续口径（日 vs 周）、断档处理（今天没记算不算断）、以及是否允许补救。

_各家做法_：

- Day One：Journal Streaks = 连续创建条目的天数，每个日记本分别计数。
- Apple Journal：Insights 显示当前 streak，iOS 27 起支持日/周/自动切换口径。
- Readwise：统计页展示每日回顾完成情况与 streak，**过去 7 天漏掉的 Daily Review 可以"recover"补回并计入 streak**（官方明确这是营销活动驱动）。
- Flomo：记录统计含连续记录相关维度。
- Obsidian 插件（Keep the Rhythm）：设置每日字数目标，达标天数构成 streak。

**能力 3：汇总指标卡（总量 / 本周 / 字数等）**

_能力解析_：热力图与 streak 之外，用几个数字回答"我总共积累了多少"。分歧在：数字的语义（量 vs 质）、粒度（累计 vs 周期）、以及数字是否可点击进入明细。

_各家做法_：

- Obsidian 插件（obsidian-data-analysis）：Summary Cards = 总笔记数、总字数、当前写作 streak、平均每天字数；另有 tag 分布与趋势折线图。
- Flomo：记录统计 = 累计笔记数、标签数、记录天数，点击数字可打开更多维度面板。
- Readwise：stats 页按天展示复习完成情况与 streak。
- Day One：官方仅 streak + 日历，总量统计靠第三方脚本（DayOne-stats：每日条目数、字符数）。

**能力 4：回顾式报告（Wrapped 式年度/月度）**

_能力解析_：一次性、强叙事、可分享的"年度/月度使用报告"，用"模式总结"代替常驻仪表盘。它是 AI 对话产品里唯一的个人统计形态，也是笔记产品的年度营销标配。分歧在：数据维度（数量 vs 主题 vs 模式）、以及是否绑定 memory/历史开关。

_各家做法_：

- ChatGPT "Your Year with ChatGPT"：年度报告，展示发送消息数、聊天数、整体聊天风格、最活跃的一天、生成的图片数等；需开启 chat history + memory，且**仅部分国家/满足使用量的用户可见**（媒体来源）。
- Claude Monthly Recap：月度报告，展示"你花时间最多的主题、什么时候最常用它、可以尝试什么新方向"；beta，Free/Pro/Max 可用，需开启 memory，web 与 Desktop 均支持。
- 语雀年度报告（2022 起）：年度记录报告，展示一年创建了多少篇文档、写下多少字；公众号/APP/Web 三入口，晒图可兑会员（营销属性）。

**能力 5：跨实体 / 跨类型计数**

_能力解析_：把不同内容类型放进同一套计数。这是与用户设想最接近的能力，但行业里只有配额计数、没有统计仪表盘形态。分歧在：计数口径（新建行为 vs 存量）、以及删除/归档是否释放。

_各家做法_：

- 语雀「文稿数」：个人账号下**小记、文档、表格、画板、数据表**各自新建数之和；每次新建 +1，删除/归档不释放，每月 1 号清零；入口在会员页/空间费用中心（配额用途）。

**能力 6：用量 / 配额仪表盘（AI 对话侧）**

_能力解析_：AI 产品需要让用户看到"这个月/这个窗口还剩多少额度"，本质是计费透明而非使用痕迹。但它是 AI 侧个人可见的唯一常驻"数字面板"。

_各家做法_：

- Claude：Settings > Usage 展示实时用量、月度花费、5 小时会话与每周限额进度条；个人与企业口径不同。
- ChatGPT：用量页监控月度额度与成本（Enterprise 另有 Workspace Analytics：活跃用户数、项目/应用/技能用量趋势、基准对比）。

**能力 7：单篇内容 / 工作区分析（协作视角）**

_能力解析_：面向"内容是否被看、被编辑、被协作"的分析，服务分享与团队场景，与"个人使用痕迹"是两套东西，但常被并称为"统计"。

_各家做法_：

- Notion Page Analytics：单页总浏览/独立浏览/编辑者与时间（需 owner/editor 权限；workspace 级为 Enterprise）。
- 语雀文档统计分析：单篇阅读次数、独立访客、平均阅读时长、最后阅读时间 + 编辑历史时间轴（官方帮助中心未直接检索到，来源为第三方教程，标注）。
- Evernote Teams Activity History：管理员查看 18 个月内的成员操作日志（创建/删除笔记等，含用户与 IP）。
- ChatGPT Enterprise / Edu Workspace Analytics：团队级采用与使用趋势。

### 3.3 不同产品的区别

#### 3.3.1 产品定位画像（逐产品）

**Flomo**

1. 定位与面向客户：面向"随手记录想法"的个人笔记（中文社群产品，"flomo = flow + memo"），官网明确"多维度统计让习惯自然养成"。
2. 差异化场景：碎片化想法速记 + 每日回顾 + 习惯养成；热力图和记录统计被官方定位为"帮你持续记录"的陪伴功能。
3. 核心差异化与护城河：低门槛记录 + 官方内置的回顾/统计闭环（每日回顾、随机漫步、热力图），统计服务于"让你继续记"的留存目标。

**语雀**

1. 定位与面向客户：阿里系文档/知识库，个人到团队全覆盖（面向学生、职场、团队协作）。
2. 差异化场景：文档承载知识沉淀 + 团队协作；统计分两轨——个人侧（年度报告、文稿数配额）与内容运营侧（单篇统计分析）。
3. 核心差异化与护城河：协作与知识库体系；文稿数是**配额计费**用途而非用户洞察，统计不是其产品主张。

**Day One**

1. 定位与面向客户：私人日记应用（多日记本、加密、时间线），面向坚持写日记的个人。
2. 差异化场景：情感/生活记录；streak 与日历是"保持写日记"的动机机制。
3. 核心差异化与护城河：私密性与长期存档（On This Day、日历回看），streak 是习惯粘性的核心。

**Apple Journal**

1. 定位与面向客户：系统级日记应用（iOS/macOS 内置），面向 iPhone 用户的轻量记录。
2. 差异化场景：系统集成（建议、照片/地点自动唤起）；Insights 负责习惯追踪。
3. 核心差异化与护城河：系统生态内免费、零摩擦；统计极简（streak + 日历），不是卖点。

**ChatGPT**

1. 定位与面向客户：通用 AI 对话助手（个人 + 企业）。
2. 差异化场景：对话即产品本体；个人统计只有年度回顾（叙事型）与用量页（计费型）。
3. 核心差异化与护城河：模型能力与生态；统计克制到"一年一次"，避免用数据打扰对话主场景。

**Claude**

1. 定位与面向客户：AI 对话助手（个人 Pro/Max + 团队/企业）。
2. 差异化场景：长对话与上下文（memory、chat search）；Monthly Recap 主打"无评判地照见使用模式"。
3. 核心差异化与护城河：上下文连续性；统计同样克制（月度回顾 + 用量仪表盘）。

**Obsidian（插件生态）**

1. 定位与面向客户：本地优先的 Markdown 双链知识库，面向重度知识工作者。
2. 差异化场景：文件即知识的自由与可迁移性；统计完全由社区插件承担。
3. 核心差异化与护城河：本地文件 + 插件生态；官方不做统计本身就是一种"核心克制"的定位选择（官方无声明，见 3.4 缺口）。

**Logseq（插件生态）**

1. 定位与面向客户：大纲式本地知识库（journal 优先），面向流程化记录者。
2. 差异化场景：journal/block 驱动；统计靠插件（heatmap、log-stats）。
3. 核心差异化与护城河：大纲与块级引用；统计同样是插件补齐，且插件作者明示数据精度受限（无块时间戳）。

**Notion**

1. 定位与面向客户：all-in-one 工作空间（笔记/数据库/项目），个人到企业。
2. 差异化场景：数据库驱动的自定义仪表盘；官方统计只有 Page/Workspace Analytics（阅读与协作视角，workspace 级需 Enterprise）。
3. 核心差异化与护城河：数据库 + 模板生态；个人"使用痕迹"统计由用户用数据库自建（Life OS 模板文化），官方不提供。

**Evernote**

1. 定位与面向客户：经典笔记应用（个人 + 团队/企业）。
2. 差异化场景：长期笔记管理；个人版无统计，官方统计只有 Teams Activity History（管理员）。
3. 核心差异化与护城河：历史存量与多端同步；统计缺席是产品老化/定位转向的信号之一（可据调研事实观察，不做价值判断）。

**Readwise**

1. 定位与面向客户：阅读摘录回顾（高亮重读、每日回顾），面向主动复习的读者。
2. 差异化场景：间隔重复式复习；stats 页展示每日复习完成 + streak + **recover 补卡**。
3. 核心差异化与护城河：回顾习惯（每日邮件/APP 提醒）；统计是"复习习惯养成"的运营杠杆。

**GitHub**

1. 定位与面向客户：代码托管与协作平台。
2. 差异化场景：个人主页的贡献图是开发者身份的"打卡墙"，被广泛复刻为热力图范式源头。
3. 核心差异化与护城河：社区与贡献记录；贡献图同时承担身份展示与自我激励。

**Heptabase**

1. 定位与面向客户：视觉化知识库（whiteboard + card + journal），面向学生/研究者/终身学习者——与 Reflecta 定位最近的产品。
2. 差异化场景：可视化理解整理；官方未提供任何使用统计（wiki 无统计文档，见 3.4 缺口）。
3. 核心差异化与护城河：白板化理解 + 期刊捕捉；统计缺席说明"理解型"产品当前普遍不把使用痕迹统计当作价值主张。

#### 3.3.2 差异化功能对比（按差异维度）

**维度 1：统计的"对象实体"——单实体 vs 跨实体**

| 产品                    | 统计对象                                               |
| ----------------------- | ------------------------------------------------------ |
| Flomo                   | memo（单一实体）                                       |
| Day One / Apple Journal | 日记条目（单一实体）                                   |
| Obsidian / Logseq 插件  | 笔记文件 / journal block（单一实体）                   |
| ChatGPT / Claude        | 对话（单一实体，且只有回顾/用量）                      |
| 语雀                    | **多类型**（小记/文档/表格/画板/数据表），但为配额计数 |
| 其余                    | 无统计                                                 |

这是差异最显著的维度：**跨实体统计只有"配额计数"这一种实现，没有统计仪表盘实现**。语雀的文稿数值得展开——它把五种内容类型放进同一个"本月新建数"，规则是"每次新建 +1，删除/归档不释放，每月 1 号清零"，服务于会员配额，而非用户洞察；这说明即便有跨实体计数的产品，其动机也是计费口径，不是使用痕迹回顾。

**维度 2：常驻 vs 一次性**

- 常驻型（热力图/streak/统计面板）：Flomo、Day One、Apple Journal、Readwise、Obsidian/Logseq 插件——统计是日常界面的一部分。
- 一次性型（年度/月度报告）：ChatGPT、Claude、语雀——统计是"一年/一月一次的事件"，强叙事、可分享。
- AI 对话产品（ChatGPT/Claude/Gemini/Perplexity）**全部没有常驻统计**，只有一次性回顾 + 用量页——这是"对话产品不做常驻统计"的鲜明行业姿态。

**维度 3：激励设计**

- 强激励：Readwise（streak + recover 补卡）、Day One/Apple Journal（streak 提示）、Flomo（官方明说"热力图帮你持续写"）、GitHub（贡献图即身份）。
- 无激励/中性：ChatGPT/Claude 回顾报告（"无评判地照见模式"是 Claude 官方表述）、语雀文稿数（配额）。
- 结论：统计与"留存/习惯养成"强绑定的产品（日记、速记、复习）才做激励设计；对话与文档产品不做。

**维度 4：官方内置 vs 社区/插件**

- 官方内置：Flomo、Day One、Apple Journal、Readwise、Claude（回顾+用量）、语雀（年度+配额+文档统计）。
- 社区/插件补齐：Obsidian、Logseq（统计完全是插件）、ChatGPT（第三方 data-viewer 补热力图）。
- 值得展开：Obsidian 的统计生态证明"官方克制 + 社区补齐"可以共存，且插件自由度高（365 天/12 周、字数/创建数、目标/streak 可组合）；但代价是统计口径碎片化、无统一入口——这与"官方内置但单一"（Flomo）形成对照。

**维度 5：个人 vs 团队/协作视角**

- 个人视角：Flomo、Day One、Apple Journal、Readwise、ChatGPT/Claude 个人报告。
- 团队/管理视角：Notion Page/Workspace Analytics、Evernote Teams Activity History、ChatGPT Enterprise、语雀文档统计。
- 值得展开：Notion Page Analytics 是"内容运营"而非"个人痕迹"的统计——单页总浏览/独立浏览/编辑者，服务"内容是否被看到"；Evernote Teams 是管理员审计日志（含用户与 IP）；两者与"个人使用痕迹"是两套语义，但都被归在"统计"名下。

### 3.4 信息缺口

1. **ChatGPT "Your Year with ChatGPT" 的具体统计项**：仅检索到媒体报道（PCWorld、Digital Trends、Smartprix），OpenAI 官方说明页未检索到；且媒体明确该功能仅部分国家、需开启 chat history + memory。缺官方一手说明。
2. **Claude Monthly Recap 的具体统计维度**：官方 help 有（主题、使用时间、可尝试方向），但 beta 且细节有限；无官方公布的完整维度清单。
3. **Heptabase 是否有统计功能**：官方 wiki/帮助中心未检索到任何统计文档，也未找到"无统计"的官方声明。缺官方口径。
4. **语雀文档统计分析**：官方帮助中心未直接检索到该功能的专门说明，现有来源为第三方教程（mizhijia）。缺官方文档。
5. **语雀「文稿数」口径**：来源为第三方博客（IDCTalk），官方帮助中心未检索到"文稿数如何计算"的专门说明。缺官方文档。
6. **Obsidian / Logseq 官方为何不做统计**：无官方声明（推测为定位取舍，但无官方依据，不写动机）。
7. **Evernote 个人版统计**：官方仅确认 Teams Activity History；个人版"是否有/无统计"无官方声明。
8. **Day One / Apple Journal 的热力图形态**：Day One 是日历视图而非网格热力图，官方未定义该视图的统计口径。

---

## 4. 结论

**覆盖情况**：15 个产品、6 种形态。个人统计成熟形态集中在"日记/速记/复习"类（Flomo、Day One、Apple Journal、Readwise）与 PKM 插件生态（Obsidian、Logseq）；AI 对话侧（ChatGPT、Claude、Gemini、Perplexity）只有一次性回顾与用量页；文档/协作侧（Notion、Evernote、语雀）的统计偏向内容运营或配额。

**一致与分歧**：

- 高度一致：个人"使用痕迹"统计 = 单实体 + GitHub 式热力图 + streak + 汇总数字（结论一）。
- 一致缺席：AI 对话产品没有常驻个人统计；PKM 官方普遍不做统计（插件/模板补齐）。
- 分歧点：统计入口常驻（侧栏）vs 一次性（年度/月度）；激励设计（streak/recover）vs 中性呈现；官方内置 vs 社区插件。
- 行业空白：跨实体（笔记+对话+画布）的统一痕迹统计，15 家无一实现；唯一的多类型计数（语雀文稿数）是配额语义。

**不延伸**：本报告只汇总行业事实与规律，不对 Reflecta 的统计模块"应该怎么做"给出建议；如何结合既有产品约束（value-proposition 的 Never 清单）做取舍，由用户自行决策。
