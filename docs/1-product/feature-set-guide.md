有了 **Value Proposition（价值主张）** 之后，PMF 里的 **Feature Set** 不是靠“头脑风暴列功能”，而是把价值主张拆成一组**最小但完整的产品能力**：这些功能必须共同证明——你的产品真的能为目标用户创造你承诺的价值。

下面用一套可落地的方法来做。

---

## 1. 先明确：Feature Set 在 PMF 里是什么

Feature Set 不是越多越好，而是为了验证 PMF 的**最小功能组合**。

它要回答三个问题：

1. **用户要完成什么关键任务？**
2. **为了完成这些任务，产品必须具备哪些能力？**
3. **哪些功能是验证价值主张必不可少的，哪些只是增强体验？**

一句话：

> **Feature Set = 兑现 Value Proposition 所需的最小功能集合。**

例如你的 Value Proposition 是：

> 帮助中小企业老板在 10 分钟内看懂公司现金流风险。

那 Feature Set 不是“财务系统所有功能”，而可能是：

- 银行流水导入
- 收支自动分类
- 现金流趋势图
- 风险预警
- 简单行动建议

而不是一开始就做：

- 发票管理
- 报销审批
- 多角色权限
- 全套会计报表
- 税务申报

这些可能以后重要，但不一定是验证 PMF 的第一批功能。

---

## 2. 从 Value Proposition 推导 Feature Set 的 5 步

### Step 1：拆出目标用户和核心场景

先把 Value Proposition 拆成清晰的结构：

> 为谁，在什么场景下，解决什么问题，带来什么结果。

可以用这个模板：

> 我们帮助 **[目标用户]** 在 **[关键场景]** 中解决 **[核心痛点]**，从而获得 **[关键收益]**。

例如：

> 我们帮助 **跨境电商卖家** 在 **每日运营复盘时** 解决 **不知道哪些商品正在亏钱的问题**，从而获得 **及时调整广告和库存的能力**。

拆完后，你会得到：

| **元素** | **示例**               |
| -------- | ---------------------- |
| 目标用户 | 跨境电商卖家           |
| 关键场景 | 每日运营复盘           |
| 核心痛点 | 不知道哪些商品正在亏钱 |
| 关键收益 | 及时调整广告和库存     |

Feature Set 必须围绕这个场景展开，而不是围绕公司想做什么展开。

---

### Step 2：列出用户完成目标必须经历的 Job

接着，把用户为了获得这个收益，必须完成的动作列出来。

继续用跨境电商例子：

用户想知道哪些商品正在亏钱，通常要完成这些 Job：

1. 汇总商品销售数据
2. 汇总广告成本
3. 汇总物流、平台、采购等成本
4. 计算单品利润
5. 找出亏损商品
6. 判断亏损原因
7. 决定下一步动作

这一步的目标是得到用户的**任务链路**，而不是功能列表。

因为功能应该从任务来，而不是从竞品截图来。

---

### Step 3：把 Job 转换成产品能力

每一个 Job 都可以映射成一个或多个产品能力。

| **用户 Job**   | **用户现在的痛苦**         | **需要的产品能力**      |
| -------------- | -------------------------- | ----------------------- |
| 汇总销售数据   | 多个平台数据分散           | 店铺数据接入 / CSV 导入 |
| 汇总广告成本   | 广告后台与销售后台分离     | 广告花费导入            |
| 计算单品利润   | 手工 Excel 容易错          | 自动利润计算            |
| 找出亏损商品   | 不知道先看哪个 SKU         | 亏损 SKU 排名           |
| 判断亏损原因   | 只知道亏，不知道为什么     | 成本结构拆解            |
| 决定下一步动作 | 不知道该降价、停广还是补货 | 简单运营建议            |

到这里，你已经有了 Feature Set 的候选池。

但注意，它还不是最终 Feature Set。

---

## 3. 用三层结构筛选 Feature Set

候选功能出来后，要分成三层：**Core / Support / Delight**。

### Core Features：核心功能

这些功能直接兑现 Value Proposition。

没有它们，产品就无法成立。

例如：

- 数据导入
- 单品利润计算
- 亏损 SKU 识别
- 成本结构拆解

判断标准：

> 如果没有这个功能，用户还相信你的价值主张吗？

如果答案是否定的，它就是 Core Feature。

---

### Support Features：支撑功能

这些功能不直接创造核心价值，但没有它们，核心功能无法顺利使用。

例如：

- 登录注册
- 店铺绑定
- 数据权限
- 基础设置
- 异常数据提醒

判断标准：

> 它是否支撑核心功能稳定、可信、可用？

Support Feature 要做，但要尽量轻。

---

### Delight Features：惊喜功能

这些功能能提升体验，但不是验证 PMF 的必要条件。

例如：

- 精美仪表盘皮肤
- AI 自动生成完整经营报告
- 多人协作审批流
- 高级图表定制
- 移动端小组件

判断标准：

> 没有它，用户是否仍然愿意使用产品来解决核心问题？

如果答案是愿意，那它先不要进入 MVP。

---

## 4. 用优先级矩阵决定 MVP Feature Set

筛选功能时，可以用一个简单评分法。

给每个功能按 4 个维度打分，1 到 5 分：

| **维度**   | **问题**                           | **权重建议** |
| ---------- | ---------------------------------- | ------------ |
| 价值相关性 | 它是否直接兑现 Value Proposition？ | 高           |
| 使用频率   | 用户是否经常需要它？               | 高           |
| 替代痛苦   | 用户不用你时，现有方案是否很痛苦？ | 高           |
| 实现成本   | 做出来是否复杂？                   | 中           |

一个简单公式：

$$
优先级 = 价值相关性 + 使用频率 + 替代痛苦 - 实现成本
$$

例如：

| **Feature**   | **价值相关性** | **使用频率** | **替代痛苦** | **实现成本** | **优先级** |
| ------------- | -------------: | -----------: | -----------: | -----------: | ---------: |
| CSV 数据导入  |              5 |            5 |            4 |            2 |         12 |
| 自动利润计算  |              5 |            5 |            5 |            3 |         12 |
| 亏损 SKU 排名 |              5 |            5 |            5 |            2 |         13 |
| AI 经营报告   |              3 |            3 |            2 |            5 |          3 |
| 多角色审批    |              2 |            2 |            2 |            4 |          2 |

所以 MVP 里应该先做：

- CSV 数据导入
- 自动利润计算
- 亏损 SKU 排名
- 基础成本拆解

而不是先做高级 AI 报告或复杂权限。

---

## 5. 最终输出一份 Feature Set 文档

你最后应该产出一份简单但清晰的 Feature Set 文档，而不是一堆零散需求。

推荐结构如下：

### 1）Value Proposition

> 我们帮助跨境电商卖家在每日运营复盘时快速识别亏损商品，从而及时调整广告和库存。

### 2）目标用户

- 1 到 10 人团队的跨境电商卖家
- 有多个 SKU
- 目前主要靠 Excel 或人工汇总利润
- 每天或每周需要看经营数据

### 3）核心场景

- 每天早上查看昨日经营结果
- 判断哪些 SKU 亏损
- 找到亏损原因
- 做出广告、定价、库存调整

### 4）MVP Feature Set

| **Feature**   | **类型** | **对应 Job**       | **验证指标**                   |
| ------------- | -------- | ------------------ | ------------------------------ |
| CSV 数据导入  | Core     | 汇总销售和成本数据 | 80% 用户能在 10 分钟内完成导入 |
| 自动利润计算  | Core     | 计算单品利润       | 用户不再依赖手工 Excel 计算    |
| 亏损 SKU 排名 | Core     | 找出亏损商品       | 用户每周查看 ≥ 3 次            |
| 成本结构拆解  | Core     | 判断亏损原因       | 60% 用户能说清主要亏损原因     |
| 基础提醒      | Support  | 发现异常亏损       | 用户点击提醒后完成分析         |

### 5）明确不做什么

这一步很重要。

PMF 阶段一定要写出 **Not Now List**：

| **暂不做的功能** | **原因**                         |
| ---------------- | -------------------------------- |
| 多人审批流       | 不直接验证核心价值               |
| 高级 BI 图表     | 提升体验，但非核心               |
| 移动端 App       | 当前场景主要在桌面完成           |
| 完整财务报表     | 会扩大产品边界                   |
| AI 长报告        | 成本高，验证价值不如亏损识别直接 |

这能防止团队被“看起来有用”的功能拖走。

---

## 6. 判断 Feature Set 是否合格的标准

一个好的 PMF Feature Set，应该满足这 5 条：

1. **每个功能都能追溯到 Value Proposition**

   不能解释它如何兑现价值主张的功能，先砍掉。

2. **能覆盖用户完成核心任务的完整闭环**

   不是只做一个亮点功能，而是让用户从问题到结果走通。

3. **足够小**

   小到团队能快速做出来并测试。

4. **足够有价值**

   用户用了以后能明显感受到变化。

5. **可验证**

   每个核心功能都有行为指标，而不是只看“做完了没有”。

---

## 7. 一个实用模板

你可以直接用这个模板来推导：

```text
Value Proposition:
我们帮助 [目标用户] 在 [关键场景] 中解决 [核心痛点]，从而获得 [关键收益]。

用户核心 Job:
1. 用户需要先……
2. 用户需要判断……
3. 用户需要完成……
4. 用户需要确认……

Feature 候选:
- Feature A：对应 Job 1
- Feature B：对应 Job 2
- Feature C：对应 Job 3

MVP Core Features:
- 必须做 1：
- 必须做 2：
- 必须做 3：

Support Features:
- 支撑功能 1：
- 支撑功能 2：

暂不做:
- 不做 1：原因
- 不做 2：原因

验证指标:
- 用户是否完成关键动作？
- 是否减少原有痛苦？
- 是否提高使用频率？
- 是否产生留存或付费意愿？
```

---

## 关键 takeaway

从 Value Proposition 到 Feature Set，核心不是“加功能”，而是做减法：

> **只保留那些能证明价值主张成立的功能。**

PMF 阶段的 Feature Set 应该像一把锋利的小刀，而不是一把瑞士军刀。小刀解决一个关键问题，足够快、足够准、足够让用户离不开，这才是找到 PMF 的正确方向。
