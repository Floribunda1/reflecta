## 6. 知识管理场景特有（同类产品的关键设计）

### Heptabase

- **卡片库 ↔ 白板**：卡片在 Card Library 中，白板只引用不复制；一张卡片可出现在多个白板，各自保留思考上下文。
- **双层白板结构**：父白板（Projects / Topics）+ 子白板；卡片超 100 用 Sections 组织。
- 白板是"结构化理解的载体"，不是临时画布。

### Obsidian Canvas

- 节点四类：file（笔记）、text、link（网页）、group（容器）。
- 连线 = 有向箭头，可加文本；画布可嵌套画布；开放 `.canvas` JSON 格式。
- 嵌入任意媒体（图片 / PDF / 视频 / 交互网页）。

### Logseq Whiteboard

- 基于 tldraw 实现；shape 与块双向关联（shape links + backlink 徽标）。
- 白板发布到网页、图片导出（v0.9.2+）。

### Scrintal

- 卡片为基本单元，可跨板复用；**可视连线与文本双链等价**，同一关系两种表达。
- 内置知识图谱视图（中心化最被引用元素）。

## 8. 对理解画布模块的启示

### 已在设计中（v1 直接覆盖）

- 无限画布、平移缩放、点阵网格（X6）
- 卡片元素（理解卡 / 文本卡）、有向带标签连线
- 参考线对齐、撤销重做、框选多选、键盘
- 左下缩放控制、右下 minimap、分组（可视容器 + 组名）
- 理解卡引用理解库（卡片库 ↔ 画布的 Heptabase 模式）

### 建议纳入（v1.x，投入产出比高）

- **连线吸附 / 重路由**：X6 manhattan router + boundary connection（已在 spike 验证）
- **画布内搜索**：Cmd+F 定位元素并平移视口（低成本，导航收益大）
- **元素锁定**：防误拖（理解卡密集时实用）
- **嵌套画布 / 画布间链接**：一张画布引用另一张画布作为子结构（Obsidian Canvas 已验证的形态）
- **演示模式**：按容器 / 选区逐段走查（把画布当演示稿，Miro 模式）
- **画布导出**：PNG 导出（分享 / 存档）

### 值得观察（later，视使用反馈）

- 自动布局：一键把选中卡片整理成树 / 流程图（Xmind / Whimsical 模式）——注意产品原则"关系来自用户显式理解"，自动布局只能整理位置，不能推导关系
- 思维导图模式视图（画布 ↔ 导图切换）
- shape backlink 徽标（卡片显示被引用 / 被连接次数）
- 卡片 → 数据库字段（连接理解库元数据）
- 命名视图书签

### 明确不做（Not Now）

- 多人协作 / presence / 评论 / 投票（本地单机应用）
- AI 生成图表（违背"用户是大脑，AI 是辅助"；位置与关系必须用户亲手标记）
- 自由绘制 / 画笔（不是本模块的核心价值，图形元素已够标记用）

## 9. 结论

画布类产品的能力谱系可以归纳为三层：**基础体验**（视口 / 选择 / 编辑 / 性能）、**组织导航**（minimap / 搜索 / 结构单元）、**关系结构**（连线语义 / 引用 / 自动布局）。理解画布模块 v1 已覆盖第一层全部与第三层核心；第二层的画布搜索、演示模式与第三层的自动布局（仅位置整理）是性价比最高的后续增量。知识管理场景最有参考价值的设计是 Heptabase 的"卡片库 ↔ 白板引用"与 Obsidian Canvas 的"节点引用外部实体 + 嵌套画布"——两者已内化为本模块的引用型理解卡与分组容器。
