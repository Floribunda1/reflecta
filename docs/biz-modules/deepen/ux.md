## 1. 用户是谁，他要做什么

### 1.1 用户目标：这次设计要消除用户的哪个障碍

**用户是谁**

已经在 Reflecta 中积累了一定数量知识记录的用户。他们会在回顾自己笔记时产生"这里还能再往下想一层"的冲动——不是想要一个通用 AI 聊天工具，而是想要一个了解自己已有记录的对话伙伴，帮他们把含糊想法拆清楚、从碎片中看出结构、在探索中发现新连接。

**障碍列表**

| 障碍名                     | 障碍描述                                                                                                                                                           | 代价                                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| 想法停留在"有道理"的口号层 | 用户记录了很多观点或感受，但表达笼统，说不清自己真正想表达的边界。比如"热爱是高效前进的强驱动力"，每次看都觉得有道理，真要解释给别人时却说不清"热爱"具体指什么状态 | 这些记录无法转化为可检验、可传达的认知资产，知识库变成了"正确的废话"集合               |
| 碎片笔记看不出结构关系     | 用户在某个领域积累了数十条零散笔记，但看不出它们之间的关系、共同前提和未解决的问题。笔记越多越混乱                                                                 | 知识库变成静态仓库，新记录只是增加噪音，用户对这个领域的"体系感"没有随记录量增加而增强 |
| 已有知识长不出新答案       | 用户有一个模糊的好奇或实际问题，不知道已有知识能长出什么答案。比如从一个概念出发好奇"它到底能解决什么问题"                                                         | 已有记录之间隐含的连接和可能性被浪费，知识库没有成为产生新认知的土壤                   |

### 1.2 本次范围：哪些目标在这次解决，哪些不在

**在这次解决的（IN）**

- 用户在 Capture 中审视 Thought 时，通过展开面板与 AI 对话澄清概念边界，全程不离开 Thought 编辑区
- 用户在 Capture 中审视 Category 时，通过展开面板让 AI 分析碎片间的结构关系，提出多维度观察
- 用户在 Contemplate 中审视节点时，通过展开面板让 AI 基于已有知识发散探索可能路径
- AI 建议的变更以预览形式呈现，用户确认后填充到对象编辑区，用户在熟悉的编辑空间中做最后调整
- 对话历史与当前知识对象（Thought / Category / 节点）绑定，支持中断后恢复

**不在这次解决的（OUT）**

| OUT 项                                                                 | 原因                                                          |
| ---------------------------------------------------------------------- | ------------------------------------------------------------- |
| AI 主动推送提醒或定时复盘                                              | 产品非目标，Deepen 是用户主动触发的增强能力，不是主动干预系统 |
| 跨模块的复杂工作流编排（如 Capture → Deepen → Contemplate 的自动流转） | 产品非目标，模块间流转由用户手动控制                          |
| AI 一次性生成完整认知体系或替用户决定"正确答案"                        | 产品非目标，Deepen 只辅助思考，不替代判断                     |
| 对话历史的分叉、回溯、复杂管理                                         | 留到 P2，当前版本聚焦单条对话上下文的基础绑定与恢复           |
| 通用自由聊天能力（不锚定任何知识对象）                                 | 产品非目标，AI 始终锚定用户当前审视的知识对象                 |

### 1.3 已知约束：来自产品决策的硬条件

| 约束                                                                         | 来源       | 对设计的影响                                                                                           |
| ---------------------------------------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------ |
| Deepen 不呈现为独立工作台，而是嵌入 Capture 与 Contemplate 的增强层          | 产品决策 1 | AI 面板必须在宿主模块的现有布局内展开，不新建页面、不跳转、不弹模态框；用户始终停留在原工作流中        |
| 对话空间采用"可展开面板"，宽度约占屏幕 1/3–1/2（桌面端）或底部抽屉（移动端） | 产品决策 2 | 面板内容密度受限，需合理分配信息层级；对话历史较长时需支持滚动；宿主对象内容需保持可见，便于对照       |
| AI 行为由用户输入驱动，不预设模式                                            | 产品决策 3 | 界面上不出现"模式选择器"（如"澄清模式""洞察模式"）或"指令语法"入口；用户直接表达意图                   |
| 知识库写入通过对象编辑区确认，不在对话流中直接执行                           | 产品决策 4 | 对话流中只展示"建议预览"，确认操作发生在宿主对象的编辑区；预览卡片与编辑区之间需要有清晰的视觉因果关联 |
| AI 追问围绕用户自己的理解，不引入外部理论（除非用户明确请求）                | 业务规则   | AI 回复的呈现方式不需要外部引用标注的默认 UI；对话体验聚焦用户自身语境                                 |
| 同一对话中用户意图可能自然转换                                               | 业务规则   | 界面不需要为"切换模式"提供任何显式控件；面板始终呈现为统一的对话空间                                   |

## 2. 用户的行动路径

### 2.1 用户能去的所有地方（信息架构）

Deepen 作为嵌入能力，所有"位置"依附于 Capture 与 Contemplate 的现有视图。

```
Capture 工作台
├── Thought 编辑区
│   └── AI 深化面板（依附于 Thought 编辑区）
│       ├── 收起态
│       └── 展开态
│           ├── 对话态（用户与 AI 多轮交流）
│           └── 建议预览态（AI 提出变更建议，等待用户确认）
│
└── Category 浏览区
    └── AI 洞察面板（依附于 Category 列表区）
        ├── 收起态
        └── 展开态
            ├── 分析呈现态（AI 展示多维度观察结果）
            ├── 对话打磨态（用户选择某个洞察方向深入对话）
            └── Insight 预览态（AI 生成 Insight Thought 预览）

Contemplate 工作台
└── 节点详情区
    └── AI 探索面板（依附于节点详情）
        ├── 收起态
        └── 展开态
            ├── 路径推荐态（AI 展示多条探索路径）
            ├── 对话探索态（用户沿某条路径深入）
            └── 涌现沉淀态（新观点生成 Thought/Connection 预览）
```

### 2.2 每条路径的完整过程

#### Journey 1：苏格拉底澄清 — 从 vague 到 precise

**用户处境**

用户正在 Capture 中审视自己记录的 Thought"热爱是高效前进的强驱动力"。这句话"有道理"，但用户说不清"热爱"在自己这里具体指什么状态，和"感兴趣"有什么区别，"高效前进"是指更快、更稳还是更少内耗。用户不期待 AI 给标准定义，而是想借追问逼自己把模糊感受拆清楚。用户的时间压力低，但注意力需要持续锚定在 Thought 内容上。

| #   | 用户做了什么                                          | 这一步注意力应在哪里                                                                                         | 系统响应                                                                                                                   | 异常                                                                                                                |
| --- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 1   | 用户在 Thought 编辑区浏览，觉得表达含糊，想进一步澄清 | Thought 正文和 Context 区域——用户在确认自己到底哪里说不清、哪些概念需要拆清楚                                | —                                                                                                                          | —                                                                                                                   |
| 2   | 用户点击"深化"按钮                                    | 按钮本身及按钮旁边的视觉反馈——用户需要确认触发成功，没有误触                                                 | Thought 右侧展开 AI 面板，面板顶部显示当前 Thought 的标题作为上下文锚点；AI 基于 Thought 正文和 Context 生成第一个澄清问题 | —                                                                                                                   |
| 3   | 用户阅读 AI 的第一条追问                              | AI 追问的具体措辞——用户在理解问题并回忆自己的真实体验，判断这个问题是否抓住了自己的含糊点                    | AI 消息出现在对话流顶部；追问围绕用户自己的理解和已有内容，不引入外部理论                                                  | AI 首次响应延迟：面板内消息区域底部显示轻量思考指示（如"正在思考…"），不阻断用户浏览 Thought 内容，不弹全局 loading |
| 4   | 用户在面板底部的输入框中回答追问                      | 输入框及自己正在写的内容——用户在组织语言回答，需要足够空间展开                                               | 输入框随内容自动增高，支持多行输入；用户输入 @ 时弹出对象选择器                                                            | 用户输入到一半放弃发送：输入内容保留在输入框中，用户切换至其他操作后返回时仍可继续编辑                              |
| 5   | 用户发送回答，AI 继续追问或指出差异                   | AI 的新回复——用户在看 AI 如何回应自己的回答，是否指出了自己没意识到的层次                                    | 用户消息和 AI 消息依次追加到对话流中；AI 可能继续追问、帮用户指出原表达包含的多层含义、或提示某个概念边界可以进一步区分    | —                                                                                                                   |
| 6   | 用户在多轮对话后逐渐澄清概念边界                      | 对话历史中的关键区分点——用户在回溯自己说过什么、AI 指出了什么差异，确认澄清的方向                            | AI 在合适时机展示"建议变更预览"卡片，如补充正文、拆出子 Thought、添加 Context                                              | —                                                                                                                   |
| 7   | 用户点击建议预览卡片                                  | 预览卡片内的变更摘要——用户在判断这个变更是否合理、依据是否充分、是否准确表达了自己的 clarified understanding | 预览卡片高亮或展开显示详细内容；用户点击"应用到编辑区"后，变更内容填充到左侧 Thought 编辑区的对应位置                      | —                                                                                                                   |
| 8   | 用户在编辑区做最后调整并保存                          | 编辑区中被填充的变更内容——用户在确认最终表达，确保 AI 的提议被转化为自己的语言                               | 系统保存 Thought；AI 面板保持展开，对话上下文保留                                                                          | 用户不保存直接离开 Thought：编辑区变更按 Capture 的现有草稿机制处理；AI 面板对话状态保持绑定                        |
| 9   | 用户关闭 AI 面板或继续其他操作                        | —                                                                                                            | 面板收起滑出，Thought 编辑区宽度自适应恢复；对话状态保持；用户再次打开同一 Thought 时自动恢复对话上下文                    | —                                                                                                                   |

**路径外异常汇总**

- **用户中途放弃对话**：用户随时可收起面板或切换至其他 Thought。面板收起后对话上下文完整保留；用户返回同一 Thought 时面板可恢复至收起前的状态。
- **用户切换至其他 Thought**：原 Thought 的对话上下文保持绑定；新 Thought 的"深化"按钮触发新的独立对话。
- **AI 响应失败**：面板内对话流底部显示轻量错误提示（如"暂时无法响应，请重试"），提供重试按钮；已发生的对话历史不受影响，用户可继续上下文发送。
- **用户在对话中误操作**：没有需要特别保护的不可逆操作（写入都通过编辑区确认），不需要额外兜底。

#### Journey 2：洞察挖掘 — 从碎片到结构

**用户处境**

用户在 Capture 中回顾"交易心理"Category 下的 15 个 Thoughts。这些记录来自不同时间、不同触发场景，有谈恐惧的、有谈贪婪的、有谈止损纪律的。单独看每条都有道理，但用户说不出"这些笔记作为一个整体，到底在解决什么问题"。用户不期待 AI 给唯一正确答案，而是想看到多个可能的解读角度，从中选择值得深入的方向。

| #   | 用户做了什么                                              | 这一步注意力应在哪里                                                                        | 系统响应                                                                                                                          | 异常                                                                                                                     |
| --- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 1   | 用户在 Category 树中选中"交易心理"，右侧显示 Thought 列表 | Thought 列表——用户在扫视这些零散记录，唤起对每条内容的记忆                                  | —                                                                                                                                 | —                                                                                                                        |
| 2   | 用户点击"洞察"按钮                                        | 按钮及面板展开区域——用户确认触发成功，同时保持对列表的感知                                  | 列表区右侧展开 AI 面板，面板顶部显示当前 Category 名称；AI 开始分析该 Category 下全部 Thought                                     | AI 分析需要较长时间：面板内显示轻量分析进度（如"正在阅读 N 条记录…"），不阻断用户继续浏览 Thought 列表，列表区保持可操作 |
| 3   | 用户阅读 AI 的多维度观察                                  | 分析结果区域——用户在逐一审视 AI 提出的各类观察，比较哪些角度是自己从未想过的                | AI 呈现至少三类维度的观察（如共同主题、共同前提、张力矛盾、可抽象洞察、待探索方向），每个观察附带 rationale，不替用户判断哪个正确 | Category 下 Thought 数量极少（如 0–2 条）：面板进入空态，显示引导文案提示用户先积累更多记录                              |
| 4   | 用户被某个洞察方向吸引，点击该方向或在输入框中追问        | 所选洞察方向的 rationale 和后续追问——用户在判断这个角度是否有价值、是否抓住了自己的真实困惑 | AI 进入对话打磨态，围绕该方向继续追问、展开论证、帮用户把结构性发现表达得更精确                                                   | —                                                                                                                        |
| 5   | 用户在对话中打磨洞察                                      | 对话流中的关键论证步骤——用户在追踪 AI 的推理过程，确认这个 Insight 是否真的成立             | AI 在合适时机生成 Insight Thought 预览卡片，包含建议正文和关联的底层 Idea                                                         | —                                                                                                                        |
| 6   | 用户点击 Insight 预览                                     | 预览中的正文和关联建议——用户在判断这个 Insight 是否准确表达了自己的发现、关联建议是否合理   | 预览高亮或展开；用户点击"应用到编辑区"后，新 Thought 出现在当前 Category 的 Thought 列表中，并自动进入编辑态                      | —                                                                                                                        |
| 7   | 用户在编辑区调整 Insight 内容并保存                       | 编辑区——用户在确认 Insight 的最终表达，确保它准确捕捉了刚才的发现                           | 系统保存新 Thought；AI 面板保持展开                                                                                               | 用户不保存直接离开：新 Thought 按 Capture 的现有草稿机制处理；AI 面板对话状态保持                                        |

**路径外异常汇总**

- **用户中途放弃**：面板收起，分析结果和对话历史保留；用户再次打开同一 Category 时可恢复至上次状态。
- **用户在 AI 分析过程中切换 Category**：原 Category 的分析任务在面板中保留（若已展开）；新 Category 的洞察按钮触发新的独立分析。
- **AI 分析失败**：面板内显示轻量错误提示和重试按钮；不弹出全局错误模态框。

#### Journey 3：问题导向探索 — 从好奇到涌现

**用户处境**

用户在 Contemplate 图谱中点击"身份认同"节点查看详情，突然产生好奇："这个概念到底能解决什么问题？"用户没有在"行动力"领域有过任何记录，这不是"从 A 到 B 的桥梁查找"，而是从一个概念出发的发散探索。用户没有明确目标答案，只有一个模糊问题，不期待 A 到 B 的直线连接，而是想发散探索可能路径，并从中选择自己想深入的方向。

| #   | 用户做了什么                                                               | 这一步注意力应在哪里                                                         | 系统响应                                                                                                      | 异常                                                          |
| --- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 1   | 用户在 Contemplate 节点详情面板中查看节点信息，产生探索欲望                | 节点详情中的概念描述和已有 Connection——用户在确认自己已有什么、哪里还有空白  | —                                                                                                             | —                                                             |
| 2   | 用户在节点详情面板底部的输入框中输入问题，如"身份认同和行动力有什么关系？" | 输入框及自己写的问题——用户在把模糊好奇转化为明确问题                         | 输入框支持多行输入；用户发送后，节点详情面板下方或右侧展开 AI 探索区域，节点内容保持可见                      | —                                                             |
| 3   | 用户阅读 AI 提出的多条探索路径                                             | 每条路径的 rationale——用户在判断哪条路径和自己最相关、哪条是自己从未想过的   | AI 基于当前节点和用户知识库提出至少两条不同路径，每条说明 rationale，不预设唯一答案，不使用"最佳""正确"等判断 | AI 响应延迟：显示轻量思考指示，节点详情保持可见               |
| 4   | 用户被某个方向吸引，点击该方向或在输入框中继续追问                         | 所选方向的推理链——用户在想沿着这个方向能发现什么、自己已有知识如何支撑这条链 | AI 进入深入对话，围绕该路径展开追问和论证；用户可随时切换话题或提出新方向                                     | —                                                             |
| 5   | 用户在对话中和 AI 共同发现涌现的结论                                       | 对话中涌现的关键判断——用户在确认这个新发现是否有价值、是否值得记录           | AI 在合适时机生成新 Thought 或 Connection 的预览，提示"这个观点看起来值得记录"但不替用户决定                  | —                                                             |
| 6   | 用户主动说"这个观点值得记下来"或点击预览                                   | 预览中的新 Thought 内容——用户在判断记录方式、归属哪个 Category               | AI 展示新 Thought 预览，包含正文和与现有节点的 Connection 建议；用户确认后创建并进入编辑态                    | —                                                             |
| 7   | 用户确认创建，新内容通过编辑区预览机制写入知识库                           | 编辑区——用户做最后调整                                                       | 新 Thought 出现在对应 Category 列表中，或在图谱中建立新 Connection                                            | 用户不保存直接离开：按 Capture/Contemplate 的现有草稿机制处理 |

**路径外异常汇总**

- **用户中途放弃探索**：面板收起，探索对话保留；再次打开同一节点时恢复。
- **节点所属 Category 下记录极少**：AI 提示探索范围有限，建议用户扩展检索范围或积累更多记录。
- **AI 响应失败**：面板内轻量错误提示，可重试。

## 3. 路径上每个节点的设计

### 3.1 每个界面的所有状态

#### AI 面板（依附于 Thought 编辑区 / Category 列表区 / 节点详情区）

| 状态            | 触发条件                                             | 呈现方式                                                                                                        |
| --------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 收起态          | 用户未触发 AI 功能，或主动收起面板                   | 面板不可见，宿主工作区占满可用空间；触发入口（"深化"/"洞察"按钮）在宿主界面中可见                               |
| 展开-对话态     | 用户点击触发入口，AI 面板展开                        | 面板占屏幕 1/3–1/2 宽度（桌面端）或底部抽屉（移动端），顶部显示当前对象标题作为上下文锚点，下方为对话流和输入框 |
| 展开-等待态     | 用户发送消息后等待 AI 响应，或 Category 洞察正在分析 | 对话流底部显示轻量思考指示（文字或轻量动画），不阻断用户操作宿主界面其他区域；输入框置灰不可编辑                |
| 展开-建议预览态 | AI 生成变更建议后                                    | 对话流中插入可交互的预览卡片，卡片内展示变更摘要和类型标签；用户点击后变更填充到宿主编辑区                      |
| 空态            | 当前对象无任何可供分析的内容（如空 Category）        | 面板内显示引导文案和轻量图示，提示用户先积累记录，不提供空洞分析或虚假洞察                                      |

#### 输入框组件

| 状态   | 触发条件                | 呈现方式                                                                             |
| ------ | ----------------------- | ------------------------------------------------------------------------------------ |
| 空态   | 无输入内容              | 显示 placeholder 文案，提示用户可输入问题、回答或追问                                |
| 输入态 | 用户正在输入文字        | 输入框随内容自动增高（设最大高度，超出后内部滚动）；支持 Shift+回车换行              |
| 引用态 | 用户输入 @ 并选择对象后 | 被引用的对象以标签形式显示在输入框中，标签可点击删除；被引用对象的内容加入对话上下文 |

### 3.2 每个核心组件的构成和交互行为

#### AI 面板

**构成：**

- 面板头部
  - 当前对象标题（常驻）：显示用户正在深化/洞察/探索的对象名称，作为上下文锚点
  - 收起按钮（常驻）：点击收起面板
  - 清空对话按钮（hover 时显示）：清空当前对象的对话历史
- 对话流区域
  - AI 消息：纯文本追问、分析、路径建议
  - 用户消息：用户输入的问题和回答
  - 系统提示消息：等待态的轻量指示、空态引导文案
  - 建议预览卡片：AI 提出的变更建议，区别于普通消息的视觉容器
- 输入区域
  - 输入框：支持多行文本、@ 引用语法
  - 发送按钮：输入非空时可用
  - @ 引用触发器：输入 @ 时激活

**交互行为：**

- 单击收起按钮：面板收起为隐藏态，对话状态保持，宿主界面宽度自适应恢复
- 单击清空对话按钮：弹出二次确认，确认后清空当前对话历史，面板回到该对象的初始触发态
- 单击建议预览卡片：卡片展开显示详细预览（若当前为收起状态）或高亮（若已为展开状态）
- 单击预览卡片的"应用到编辑区"按钮：变更内容填充到宿主对象编辑区，卡片状态变为"已应用"
- 在输入框中输入 @：弹出对象选择器（Thought / Category 列表），用户选择后对象以标签形式插入输入框
- 回车发送消息：消息追加到对话流，输入框清空，对话流自动滚动到底部
- Shift+回车：输入框内换行，不发送

#### 建议预览卡片

**构成：**

- 卡片头部
  - 变更类型标签（常驻）：如"补充正文"、"拆分 Thought"、"创建 Insight"、"添加 Connection"
- 卡片主体
  - 变更摘要（常驻）：变更内容的缩略预览
  - 详细内容（点击后展开）：变更的完整内容
- 操作区
  - "应用到编辑区"按钮（常驻，已应用后变为禁用态或消失）

**交互行为：**

- 单击卡片主体：展开/收起详细预览
- 单击"应用到编辑区"：变更填充到宿主编辑区，按钮变为"已应用"状态
- 已应用的卡片仍保留在对话流中，作为历史记录的一部分

### 3.3 界面变化时用户的感知（过渡意图）

| 过渡场景                                   | 过渡意图                                                                           | 实现方式                                                                                                                             |
| ------------------------------------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 点击"深化"/"洞察"按钮，AI 面板从收起态展开 | 用户感知到自己在同一工作台中获得了辅助空间，没有跳页、没有弹窗、没有打断思路       | 面板从右侧滑入（桌面端）或从底部滑上（移动端），宿主内容区宽度自适应收缩，不整页刷新；面板头部显示当前对象标题，强化"仍在原地"的感知 |
| AI 面板收起                                | 用户感知到辅助空间被收起，回到纯浏览/编辑状态，随时可以再次展开                    | 面板向右侧/底部滑出，宿主内容区宽度自适应恢复；收起按钮的 hover 状态提示"对话将保留"                                                 |
| AI 响应从等待态转为有内容                  | 用户感知到新内容出现，注意力自然下移阅读新内容                                     | 新消息从底部平滑进入，对话流自动滚动到底部；输入框位置保持固定，不被推出可视区域                                                     |
| 建议预览卡片出现在对话流中                 | 用户感知到 AI 提供了一个可操作的提案，与纯文本消息明显区分，提示"这里可以做些什么" | 预览卡片以区别于普通消息的视觉容器呈现，带有操作按钮和类型标签；卡片出现时有轻量入场动效                                             |
| 用户点击预览后填充到编辑区                 | 用户感知到提案被采纳，变更发生在自己熟悉的编辑空间，自己对最终内容保有控制权       | 编辑区内容平滑更新，被修改的部分有短暂的视觉强调（如高亮闪烁），然后恢复正常；若编辑区不在可视区域，轻量提示"已填充到编辑区"         |
| 切换至另一个知识对象，新面板展开           | 用户感知到自己在新的对象上开启了新的辅助对话，原对象的对话已被妥善保存             | 新面板以收起态或全新对话态展开，不显示原对象的对话内容；若用户返回原对象，对话上下文完整恢复                                         |

## 4. 路径之外会发生什么

### 4.1 数据边界

| 边界场景                             | 处理方式                                                                                                               |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| Category 下无任何 Thought（空）      | AI 面板进入空态，显示引导文案："这个分类下还没有记录，积累一些想法后再来洞察会更有价值。"不提供空洞分析                |
| Thought 正文极长                     | AI 上下文自动处理，用户无感知；追问仍围绕全文核心观点，不因长度而截断用户体验                                          |
| Category 下 Thought 数量极多（>100） | AI 分析时默认聚焦当前 Category，用户可手动扩展检索范围；分析结果按维度分组呈现，每组可折叠，避免信息过载               |
| 对话历史极长                         | 面板内对话流保持完整历史可见，采用虚拟滚动或分页加载确保性能；输入框始终固定在面板底部，不被推出可视区域               |
| AI 生成的建议预览内容极长            | 卡片默认收起详细内容，显示摘要（前 3–5 行或核心变更点）；用户可点击展开查看完整预览                                    |
| @ 引用对象数量多                     | 输入框中引用标签横向排列，超出输入框宽度时横向滚动或换行显示；不对引用数量做硬限制，但提醒用户过多引用可能稀释对话焦点 |

### 4.2 操作边界

| 操作                      | 可逆性判断 | 处理方式                                                                                                   |
| ------------------------- | ---------- | ---------------------------------------------------------------------------------------------------------- |
| 清空对话历史              | 不可逆     | 二次确认弹窗，文案说明具体后果："清空后，与该 Thought 的对话记录将无法恢复。是否继续？"                    |
| 应用建议预览到编辑区      | 实时可修改 | 直接填充到宿主编辑区，用户可在编辑区自由修改、撤销或删除；不额外弹窗确认，因为编辑区本身就是用户的控制空间 |
| 创建 Insight Thought      | 实时可修改 | 通过编辑区预览机制执行，新 Thought 进入编辑态，用户在编辑区做最后调整后保存                                |
| 删除输入框中的 @ 引用对象 | 轻量操作   | 直接点击引用标签上的删除图标移除，无需确认                                                                 |
| 收起 AI 面板              | 实时可恢复 | 直接收起，对话状态保持；再次展开时完整恢复上下文和滚动位置                                                 |
| 在宿主编辑区保存变更      | 实时可修改 | 按 Capture / Contemplate 的现有保存机制处理                                                                |

### 4.3 状态恢复

| 恢复场景                                    | 恢复策略                                                                                         |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 用户离开 Thought 后重新打开同一 Thought     | 恢复：Thought 编辑区内容 + AI 面板展开/收起状态 + 该 Thought 绑定的完整对话历史 + 面板滚动位置   |
| 用户离开 Category 后重新打开同一 Category   | 恢复：Category 选中状态 + AI 面板展开/收起状态 + 该 Category 绑定的分析和对话历史 + 面板滚动位置 |
| 用户离开 Contemplate 节点后重新打开同一节点 | 恢复：节点选中状态 + AI 面板展开/收起状态 + 该节点绑定的探索对话历史 + 面板滚动位置              |
| 用户收起 AI 面板后重新展开                  | 恢复：收起前的完整对话上下文和滚动位置                                                           |
| 应用预览到编辑区后未保存即离开宿主对象      | 编辑区的未保存变更按 Capture / Contemplate 的现有草稿机制处理；AI 面板的对话状态保持绑定         |
| 切换至其他 Thought / Category / 节点        | 原对象的对话上下文完整保留；新对象展开独立的 AI 面板和对话上下文，不互相污染                     |
| 用户在输入框中有未发送的内容时收起面板      | 输入框内容保留，再次展开时恢复未发送文本                                                         |

## 5. 怎么验证用户体验是对的

### 障碍 1：想法停留在"有道理"的口号层

| 验收条件                                                                                                     | 判断方式                     |
| ------------------------------------------------------------------------------------------------------------ | ---------------------------- |
| 从用户在 Thought 编辑区点击"深化"到 AI 面板展开并显示第一条追问，响应时间不超过 3 秒                         | 操作回归验证（计时）         |
| AI 面板的追问内容围绕用户自己的理解和当前 Thought 内容，不包含未请求的外部理论引用                           | 功能测试（检查 AI 消息内容） |
| 用户可以在不离开 Thought 编辑区、不经过任何弹窗或页面跳转的情况下，完成从对话到保存的完整澄清流程            | 操作步骤计数                 |
| AI 建议的变更通过预览卡片呈现，用户点击后填充到编辑区，而非在对话流中直接执行写入                            | 操作回归验证                 |
| 对话结束后，用户能在编辑区明确看到至少一处被澄清的概念边界（如补充的定义、拆分的新 Thought、添加的适用条件） | 数据验证                     |

### 障碍 2：碎片笔记看不出结构关系

| 验收条件                                                                                                                                | 判断方式                     |
| --------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| 用户在 Category 视图中点击"洞察"后，AI 在分析结果中至少提出三类不同维度的观察（如共同主题、共同前提、张力矛盾、可抽象洞察、待探索方向） | 功能测试                     |
| 每个观察都附有 rationale，AI 消息中不包含"这个洞察一定正确""这就是核心问题"等替用户做价值判断的措辞                                     | 功能测试（检查 AI 消息内容） |
| 用户选择某个洞察方向后，可以在面板内继续对话打磨，无需跳转、无页面刷新、无弹窗阻断                                                      | 操作步骤计数                 |
| AI 生成的 Insight Thought 预览包含建议正文和与底层 Idea 的 Connection 建议                                                              | 功能测试                     |
| 用户确认 Insight 后，新 Thought 出现在当前 Category 的 Thought 列表中，并自动进入可编辑状态                                             | 操作回归验证                 |

### 障碍 3：已有知识长不出新答案

| 验收条件                                                                             | 判断方式                     |
| ------------------------------------------------------------------------------------ | ---------------------------- |
| 用户在节点详情中输入问题后，AI 至少提出两条不同路径，每条路径说明 rationale          | 功能测试                     |
| AI 的表述中不出现"最佳路径""正确方向""应该这样做"等替用户做价值判断的措辞            | 功能测试（检查 AI 消息内容） |
| 对话中涌现的新观点可通过预览机制沉淀为新 Thought 或 Connection，且需用户显式点击确认 | 操作回归验证                 |
| 用户可以通过选择方向、自由追问来控制探索深度和走向，不感知到 AI 在强制推进某条路径   | 可用性测试                   |

### 通用验收条件

| 验收条件                                                                                                          | 判断方式     |
| ----------------------------------------------------------------------------------------------------------------- | ------------ |
| AI 面板可在 Capture / Contemplate 中展开和收起，展开/收起过程不阻断宿主界面的其他操作，不影响原有工作流和布局逻辑 | 操作回归验证 |
| 所有知识库写入操作必须经过用户在对象编辑区确认保存，系统不得在对话流中自动执行写入                                | 功能测试     |
| 对话历史与对象绑定：用户离开后再打开同一 Thought / Category / 节点，对话上下文完整恢复（包括历史消息和滚动位置）  | 端到端测试   |
| 用户通过 @ 引用的对象正确加入对话上下文，并在后续 AI 回复中被实际引用                                             | 功能测试     |
| AI 面板收起后，对话状态保持；重新展开时上下文完整恢复，不丢失已发生的对话                                         | 操作回归验证 |
| 从 Thought / Category / 节点触发 AI 时，该对象内容自动成为对话的初始上下文，AI 的第一条消息已体现对对象内容的理解 | 功能测试     |
