① 背景介绍

本报告调研的模块是 个人知识 + AI 对话类应用中的常驻实时仪表盘（首页概览页）——打开应用就能看到当前状态的看板页面，不是周期性汇总报告（如 Spotify Wrapped 式年度回顾）。

用户口述背景：Reflecta 计划把现有页内统计升级为独立 Dashboard 模块作为首页，拆两块：沉淀资产（理解、画布、上下文等成果）与 过程资产/使用痕迹（对话、活跃行为）。用户明确强调：不是「一段时间给你呈现一次」的周期性 report，而是像电商产品里的仪表盘那样，可以一直在里面看到实时内容/状态。
理解假设：本报告按「常驻实时仪表盘（非周期性报告）」理解该模块；若实际指周期性 Wrapped 式报告，请指出，将重新选品调研。
项目自身约束（非调研结论）：value-proposition 明确「把知识边界做成抽象分数或仪表盘」属 Never；feature-set 在图谱形态下把「数量统计 dashboard」列为 Not Now；「用输入量/打卡量作为核心激励」也是 Never。以下行业事实供结合这些约束自行判断。

② 调研范围与产品

形态空间（4 种主流解法）

A. 商家/工作台实时看板

电商、支付、SaaS 管理后台的第一屏：实时指标 + 历史趋势 + 待办/通知聚合。

Shopify、Zonos、Stripe、WooCommerce、SellerMagnet、Amazon Seller Central

B. 中文内容创作后台

面向个人创作者/运营者的常驻数据后台，「内容资产 + 效果数据」分离展示。

知乎创作中心、微信公众平台数据分析

C. 个人工具内嵌统计面板

个人知识/日记/复习/时间类应用的统计页或侧栏常驻面板。

Flomo、Readwise、Daylio、RescueTime、Apple Screen Time、Obsidian/Logseq 插件、GitHub

D. 工作台动态/健康概览

团队工具里以「更新流 + 健康指标」为主的概览，数字不是主角。

Linear（Pulse / Monitor）、Notion（用户自建 Dashboard view）

直接竞品 = 个人知识 + AI 对话形态（Flomo / Readwise / Daylio / Obsidian 插件 / Apple Screen Time / 语雀 / Heptabase / ChatGPT / Claude / Notion）；
间接竞品 = 相邻形态（RescueTime / 知乎 / 公众号 / GitHub）；
跨域参照 = 用户点名的电商后台形态（Shopify / Zonos / Stripe / WooCommerce / SellerMagnet / Amazon / Linear）。

③ 核心结论

结论一：常驻看板 = 「实时/当天层」+「历史/趋势层」两段结构，数字几乎都可点击下钻

电商/运营型看板的行业共识：「今天怎么样」与「最近怎么样」并置，每个数字都能点进去看明细。

证据

Zonos：顶部 live today bar（当天收入/订单/均价/Top 国家，标注「Today as of 10:30 AM」捕获时间），下方历史 KPI 卡 + 趋势图（对比期、粒度、刷新时间戳）。

Shopify：Home = 实时指标（30 天默认）+ 待处理任务 + 建议 + 最近活动；Analytics 指标卡可加/删/重排，点卡片标题跳报表。

SellerMagnet：Today's Snapshot 实时卡 + 长期趋势区同页。

微信公众号：图文分析顶部「昨日关键指标」模块与 7/30 天前对比，下方 7/14/30 天趋势图。

Amazon Seller Central：Account Health = 当前账户健康状态（达标/风险/需关注事项）。

结论二：个人知识 + 对话产品没有「电商式首页看板」先例；Obsidian 插件最接近，且已分化出三种统计语义

直接竞品的统计都以独立页或侧栏存在，不是首页第一屏；跨实体 + 首页级的看板依旧无人做（与昨日报告互相印证）。

插件生态的三种语义分化

数量统计：obsidian-data-analysis（热力图[创建+修改] + 总数/字数/streak/日均）、obsidian-dashboard（总字数/笔记数/今日/7 日均 + 365 天热力图 + 12 个月柱状图 + 星期分布环形图）。

结构/质量统计：Vault Full Statistics（own vs source、dangling sources、tangles、inbox——直接呈现「哪些是悬空的、纠缠的、没整理的」）。

参与度/使用统计：ord-dashboard（views/edits/active notes）、vault-activity（创建 + 修订，回答「是否在回看和维护」）。

结论三：健康/状态型仪表盘是明确先例——「状态 + 风险 + 行动项」而非纯数量

Amazon Account Health、Linear health indicator、Obsidian Vault Full Statistics 的 dangling/tangles/inbox：给你「现在的状态是否需要行动」，而不是更多数字。与「看见边界与空白」的价值主张有天然呼应。

结论四：中文创作后台（知乎/公众号）验证了「内容资产 + 效果数据」分离的心智

知乎创作中心（数据概览 + 回答/文章/专栏分列 + 创作等级 + 单篇深度分析）；公众号（用户分析 + 图文分析两大模块）；第三方工具补「首页当日看板」「分钟级增长」——创作者对「打开即见当天状态」有真实诉求，官方第一屏常不满足。

研究见解：电商后台看板 = 实时层 + 趋势层 + 可钻取 + 待办聚合；个人知识工具 = 独立统计面板且语义分裂（数量/质量/参与度）；健康型仪表盘是第三条路；中文创作后台确认资产-效果分离心智。Reflecta 想做的「首页 Dashboard + 两块」无同品类先例，但每个构成元素都有成熟参照。

④ 核心能力

能力 1：实时/当天状态层

回答「现在/今天怎么样」——这是常驻仪表盘与周期性报告的根本区别。分歧在：是否单独强调当天（Zonos 专门 bar），默认 30 天（Shopify），还是只给昨日（公众号）。

各家做法

Zonos：live today bar，标注「Today as of 10:30 AM」，随新数据持续更新。

SellerMagnet：Today's Snapshot 实时卡（左上）。

Shopify：Home 默认 30 天指标；Live metrics（traffic/reach/orders/revenue 实时）独立提供。

微信公众号：顶部「昨日关键指标」模块（不强调当天实时，重对比）。

知乎：数据概览第一屏即核心互动指标；分钟级实时由第三方补。

Apple Screen Time：每日「屏幕使用报告」，进入后按日/周查看。

能力 2：历史趋势层与周期对比

把「最近怎么样」可视化。分歧在：对比基准（上一期/7 天前/30 天前）、粒度、KPI 数字还是趋势图。

各家做法

Zonos：KPI 卡（总值 + 对比期 % + 方向箭头）+ 当期 vs 对比期趋势图 + 粒度控制。

微信公众号：昨日模块（与 7/30 天前对比，日/周/月百分比）+ 7/14/30 天趋势图。

Shopify：指标卡 + Orders over time；日期范围自定义 + 跨期对比。

Daylio：interval 切换（本期 vs 前期重复次数对比），mood 色码。

Obsidian 插件：12 个月柱状图、30 天日历、星期分布环形图。

RescueTime：daily/weekly/monthly/yearly + all time/work hours 开关。

能力 3：可钻取明细（数字 → 具体内容）

看板的数字能点进具体内容，才能服务判断与行动；纯数字墙会变成「泛化仪表盘」。

各家做法

Shopify：点卡片标题进报表；Home 待办直链执行页。

Zonos：KPI 卡点击打开 breakdown 页；Top SKU 行可展开。

Stripe：活动分解 = summary totals → transaction details 逐层下钻。

知乎：每篇内容点「数据」看深度分析（流量来源/读者分布/平均阅读时长）。

Flomo：点热力图格子直接筛选当天记录（复用昨日报告）。

Obsidian 插件（vault-pulse/vault-activity）：点某天列出当天动过的文件。

能力 4：健康/状态信号（非纯数量）

回答「现在状态是否健康、哪里需要行动」，与纯数量统计是不同设计哲学。

各家做法

Amazon Seller Central：Account Health = 达标/风险/需关注事项，高风险给行动项。

Linear：项目更新附带 health indicator + 文本（状态/挑战/下一步）。

Obsidian Vault Full Statistics：dangling sources / tangles / inbox（结构质量）。

知乎：创作等级 = 平台综合评分（注意是评分体系，不同于「看状态」）。

能力 5：按实体/类型分组的计数

把不同内容类型放进同一看板分别计数——「沉淀资产」块最直接的参照。

各家做法

知乎创作中心：数据概览 + 回答/文章/专栏分列计数。

微信公众号：用户分析（新增/净增/累计）与图文分析（阅读/分享/完读）两大模块分离。

语雀：小记/文档/表格/画板/数据表分列（配额语义、每月清零，复用昨日报告）。

Obsidian：notes/files/attachments/links/tags 分列。

能力 6：待办/通知/更新流聚合（首页不只是数字）

让看板从「被动查阅」变成「一天的开场」。分歧在：任务驱动 vs 动态流 vs 通知聚合。

各家做法

Shopify Home：待处理订单、每日任务、增长建议、最近销售活动。

WooCommerce：提醒/提示 + 快速访问 + 新用户任务清单。

Stripe Home：重要通知聚合（争议、身份验证）。

Linear Pulse：个性化更新 feed（For me / Recent / Popular），AI 生成周期摘要。

RescueTime Assistant：常驻当天进度 + Focus Sessions 快捷入口。

⑥ 产品定位画像（16 家）

按层筛选：

Flomo

定位：个人速记 + 回顾闭环。
做法：侧栏常驻 12 周热力图（周一开头、五档深浅）+ 记录统计八维度；点格子直接筛当天记录；可隐藏。
来源：昨日报告（2026-08-16）+ 官方

Readwise

定位：主动复习的读者（高亮重读）。
做法：stats 页 = GitHub 式活动图 + 最长/当前 streak + 全球 streak 排名；每日复习完成情况 + 补卡 recover。
来源：官方 changelog + 用户长评（Medium, 300 天回顾）

Daylio

定位：情绪/习惯记录（mood + activity 两键）。
做法：stats 页周期切换 + 本期 vs 前期对比 + mood 色码 + Influence on Mood（活动与情绪相关性）；Advanced Stats 为付费点。
来源：官方帮助中心（daylio.net/faq）

Obsidian / Logseq 插件

定位：本地优先 Markdown 知识库，统计全靠社区。
做法：分化三语义——数量（data-analysis、dashboard）、质量（Vault Full Statistics：dangling/tangles/inbox）、参与度（ord-dashboard：views/edits、vault-activity：创建+修订）。
来源：插件 README（第三方/社区，官方无统计）

Apple Screen Time

定位：系统级使用时间管理。
做法：每日/每周使用报告（app 时间、通知数、拿起次数）；可切换统计时段、按分类/设备。
来源：Apple 官方帮助中心

语雀 / Heptabase / ChatGPT / Claude / Notion

定位：均为昨日报告已覆盖事实。
要点：语雀 = 多类型文稿数（配额语义）+ 年度报告；Heptabase = 无统计；ChatGPT/Claude = 回顾 + 用量页；Notion = 个人无统计，Dashboard view 需 Business 计划（用户自建）。
来源：昨日报告（2026-08-16）

RescueTime

定位：自动时间追踪（个人 + 团队）。
做法：常驻 Dashboard（总时间 + Productivity Pulse 分数 + 分类，可切 day/week/month/year）+ weekly email 双轨；Assistant 实时当天进度。
来源：官方帮助中心

知乎创作中心

定位：中文创作者数据后台。
做法：数据概览（阅读/赞同/评论/收藏/关注增长）+ 创作等级 + 回答/文章/专栏分列 + 单篇深度分析（流量来源/读者分布/平均阅读时长）。
来源：第三方教程（jizhil.com），官方专门说明未检索到

微信公众平台

定位：公众号运营者内容后台。
做法：用户分析 + 图文分析分离；图文分析 = 昨日关键指标（对 7/30 天前，日/周/月百分比）+ 趋势图 + 图文详解；首页看板由壹伴等第三方补。
来源：腾讯客服官方 + 第三方（壹伴）

GitHub

定位：开发者身份墙。
做法：365 天贡献图常驻个人主页；官方明确定义「什么算贡献」（严格口径）。
来源：GitHub 官方文档

Shopify

定位：独立站商家后台。
做法：Home = 实时指标 + 待办任务 + 建议 + 最近活动；Analytics overview = 可定制指标卡组（加/删/重排/分节），点卡片标题跳报表；~1 分钟更新。
来源：官方帮助中心

Zonos

定位：跨境电商技术服务商。
做法：Home = live today bar（含捕获时间戳）+ 历史 KPI 层（对比期 % + 方向箭头 + 点击钻取 + Top 排行/可展开 SKU）——双层结构最完整。
来源：官方文档（zonos.com/docs）

Stripe

定位：支付基础设施操作台。
做法：Home = analytics + charts + 重要通知（争议/验证）；活动分解 = summary totals → transaction details 逐层下钻；overview 可定制。
来源：官方文档（docs.stripe.com）

WooCommerce

定位：WordPress 电商插件后台。
做法：Home = 性能指标 + 建议/提示 + 快速访问 + 新用户任务清单；同一 Home 按用户阶段切换内容。
来源：官方文档（woocommerce.com）

SellerMagnet

定位：多平台卖家生意聚合。
做法：Dashboard Home 分区：Today's Snapshot 实时卡（左上）+ 长期盈利趋势。
来源：官方文档（docs.sellermagnet.com）

Amazon Seller Central

定位：Amazon 官方卖家后台。
做法：Account Health = 健康状态仪表盘：达标/风险/需关注事项，高风险给行动项——不是展示数量。
来源：Amazon 官方（sellercentral + 官方 PDF）

Linear

定位：产品团队项目管理。
做法：Monitor/Pulse = 健康指标 + 个性化更新 feed（For me / Recent / Popular）；更新 = health indicator + 富文本；AI 生成上周摘要。
来源：官方 changelog / docs

⑦ 差异化功能对比（按差异维度）

维度 1：看板的时间分层——实时层与趋势层怎么分

加权评分 知乎创作等级、RescueTime Pulse 多个维度合成一个分数
展开：Obsidian Vault Full Statistics 的质量维度

把统计从「多少」推进到「结构是否健康」——own vs source（自己写的 vs 引用外部）、dangling sources（指向不存在笔记的链接）、tangles（纠缠的高互链簇）、inbox（未整理收件区）。这些对知识工作者是可行动信号（去补链接、拆簇、整理 inbox），而「总数 500 篇」不是。对照 Reflecta 的「看见边界与空白」，这是距离最近的一个既有做法——但从未有人把「缺口」做成首页看板。

维度 3：激励设计——打卡、排名、评分还是中性

产品 激励形态
Readwise streak + recover 补卡 + 全球排名（社交化竞争）
Daylio / Flomo / Obsidian 插件 streak / 连续记录（习惯养成）
知乎 创作等级（平台加权评分，权益解锁驱动）
RescueTime Productivity Pulse 分数（自我衡量）
Stripe / Shopify / Amazon / Linear / Apple 无激励，中性呈现或行动导向
展开：Readwise 全球 streak 排名——打卡激励的激进形态

stats 页含 global streak rank（所有用户里的连续复习天数排名）。用户长评（Medium）确认「全球排名不是重要因素，但确实是激励来源」。注意区分：streak 是自我比较，全球排名是社会比较；两者在「是否会推动无效行为」上的风险不同。

维度 4：看板载体——首页第一屏 vs 独立页 vs 侧栏

载体 产品 特点
首页第一屏 Shopify / Zonos / WooCommerce / SellerMagnet / 知乎 / 公众号 打开即见，通常伴随待办/通知聚合
独立统计页 Readwise / Daylio / RescueTime / Obsidian 插件 / GitHub 主动进入，研究性回看
侧栏常驻 Flomo 与主内容同屏，低打扰
展开：电商 Home 的「待办聚合」——首页语义是「今天需要看什么、做什么」

Shopify Home 把需要处理的事（未支付订单、任务）放第一屏；WooCommerce 新用户第一屏是任务清单；Stripe 聚合未解决争议。这说明电商看板首页的语义是数据与待办在同一个信息架构里。对「个人知识首页」是重要参照：首页可以是「沉淀状态 + 需要你继续整理的入口（如孤岛/缺上下文理解的行动入口）」，而不是纯数字墙。

维度 5：多实体计数——跨类型分列 vs 单实体聚合

产品 对象
知乎 回答/文章/专栏分列
公众号 用户/图文两大模块
语雀 小记/文档/表格/画板/数据表分列（配额语义，复用昨日报告）
Zonos live bar 收入/订单/均价/询价/国家 五项指标实时并置
Flomo / Readwise / Daylio 单实体（memo/复习/记录）
展开：Zonos live today bar 的多实体并置

实时层同时放收入、订单数、均价、询价数、Top 国家五个不同实体的当日状态——已是「多实体并置」的实时层，但所有实体共享同一业务语义（交易）。电商的多实体数量并置是被验证的 layout；Reflecta 的理解/画布/上下文是否共享「沉淀」这个统一语义，是需要用户自己想清楚的问题。

⑧ 信息缺口

  1. 知乎创作中心官方说明：数据概览的确切指标/布局仅检索到第三方教程（jizhil.com），未检索到知乎官方帮助中心专门说明。
  2. 公众号后台首页形态：「数据分析」有官方说明（腾讯客服），但「后台首页是否有数据看板」官方未声明；壹伴首页看板为第三方补充。
  3. Shopify 帮助页原文：help.shopify.com 直接抓取返回 403，Analytics overview 完整字段依赖搜索摘要，未逐字段核对原文。
  4. RescueTime Pulse 计算口径：官方确认分数存在且分四档，但合成权重未公开（官方不提供）。
  5. Heptabase 是否有统计：延续昨日缺口（2026-08-16 未检索到官方统计文档；本次未更新检索）。
  6. Obsidian 插件质量：dangling/tangles 等指标均来自插件 README（社区），非官方；Obsidian/Logseq 官方依旧无统计。

⑨ 结论

一致：常驻看板 = 数字可钻取（8/16）、时间范围切换（7/16）与对比期（4/16）是标配；「实时/今天 + 历史趋势」两段结构在电商/运营后台高度收敛。
缺失：个人知识 + 对话产品无电商式首页看板先例（Obsidian 插件最接近但没有页面 IA）；对话侧只有回顾 + 用量（复用昨日结论）。
分歧：看板是纯数量还是健康/结构状态；激励（streak/排名/评分 vs 中性）；载体（首页 vs 独立页 vs 侧栏）；是否需要待办/动态聚合。
空白：跨实体（沉淀资产 + 使用痕迹）统一首页看板，16 家无一实现——昨日报告结论二「跨实体统计是行业空白」进一步确认「做成首页」也是空白。

本报告只汇总行业事实与规律，不给出「Reflecta 应该怎么做」的建议；如何结合既有产品约束（value-proposition Never 清单、feature-set Not Now）做取舍，由用户自行决策。
