# Effect 迁移哲学：拒绝背负技术债（v2.0.0）

> 状态：Decided（迁移总纲）
> 日期：2026-08-20
> 配套决策：`index.md`（同目录）
> 约束等级：**最高**——约束所有后续迁移工作的范围与验收

## 0. 一句话原则

**拒绝背负技术债：迁移不止是"引入 Effect"，而是每动一个模块，就让该模块（及其交割边界）比迁移前更干净——不保留旧模式、不写兼容层、顺手清掉存量债务（dead code、legacy compatibility、过渡 shim）。**

## 1. 三条操作性规则

### R1 不写过渡兼容层（最重要的规则）

Inato 迁移报告（fp-ts → Effect）采用的"compat helpers + 双轨共存"策略**明确不采用**。每迁移一个模块：

- 旧实现连同其**全部调用方**在同一变更内移除；
- 不保留"旧 API 包装成新 API"的 shim、alias、deprecated 分支；
- 需要改调用方就当场改——不存在"先兼容、后清理"的中间态。

**反例（明确禁止）**：`export const legacyFoo = wrapCompat(newFoo)`、`if (legacyFlag) oldPath else newPath`、为过渡期保留的 `@deprecated` 双实现。

### R2 随手清存量债

迁移每个模块时，顺带清理该模块边界内的存量债务：

- **dead code**：未引用的导出、废弃函数、无用分支、孤立类型；
- **legacy compatibility**：为兼容旧数据格式/旧签名/旧环境保留的判断与转换代码（如历史上为 v1 数据结构留的迁移分支）；
- **重复实现**：迁移期间发现的"同一件事两个写法"（如旧的错误折叠与新的 Schema 错误通道同时消失即视为完成交接）；
- **过期注释/文档**：指向已被替换实现的注释一并删除或更新。

### R3 边界克制（防止 scope creep）

不是所有债都在迁移里清：

- **清**：迁移模块自身及其依赖链上的债（上述 R2）；
- **只登记不动**：与迁移无关的深层重构、视觉改动、无关 bug——记入模块迁移清单的"发现但不动"项，不在此次顺手改；
- **阻塞即清**：某一处存量债阻塞迁移正确性时，清理它属于迁移范围。

## 2. 对既有决策的再确认

| 既有决策               | 哲学下的含义                                                                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 无并行技术栈（约束 3） | 不并行旧实现，**也不并行兼容层**——R1 是其直接延伸                                                                                                  |
| D2 保留 React Query    | React Query 不是并行栈；但 `queries.ts` 里每个迁移模块手写的 invalidate 织网、旧封装随模块迁移一并清理                                             |
| D5 传输模块隔离        | 迁移后 `electron-ipc-decorator`、`@IpcMethod` 类、`MergeIpcService`、`createIpcProxy`、`{__isIpcError}` 包裹层**全部删除**，不留任何"还能用"的残留 |
| D6 校验统一 Schema     | CLI 的 zod 迁移是**删除式**迁移：迁移完成后 zod 依赖从 package.json 移除，不存在"两套校验库"的过渡期                                               |

## 3. 验收标准（每个迁移 PR 必须满足）

1. `grep` 旧符号（类名 / 通道名 / 包裹类型）在迁移范围外**零残留**；
2. 无 `TODO(迁移)`、无 compat shim、无 `@deprecated` 双实现；
3. 迁移模块的 dead export 清单为零（`oxlint` 与 typecheck 通过为底线）；
4. 变更说明中列出"发现但不动"的存量债登记项（如有）；
5. package.json 中迁移带走的依赖同步移除（如 zod、electron-ipc-decorator）。

## 4. 与现有规范的关系

- 本原则是 `AGENTS.md` 中"完成长任务或阶段性成果后及时 commit"的延伸：**每个迁移 PR 都是一个自洽的干净单元**，不允许"先塞进去、后补清理"。
- 迁移清单（pilot 及后续）需在每个条目下附两栏：**顺手清理项**、**发现但不动项**。
