# Storybook 组件验收原则

> 状态：Draft
>
> 日期：2026-08-13
>
> 职责：定义 Reflecta 的 Storybook 组织——哪些组件进入、每个组件展示哪些形态、页面如何分区。

## 组织

- `[MODULE]`
  - **基本组件**
    - **组件**：除「只是简单用 shadcn 进行排列组合、而且没有任何样式定制」的组件外，都要有 case。
      - 组件本身的状态过于复杂或内容过长（如 Markdown 预览）、一个页面会信息过载的——直接放在组件页面（整页直出）。
      - 否则——单独分 subsection。
  - **组合场景**
    - 展示应用内真实的组合。
    - 组合过于复杂（如 Agent 对话，存在很多种排列组合情况）——挑几个典型分 subsection。

## Case 覆盖

1. 组件的**所有状态和展示情况**都需要在 case 中展示完全；存在复杂的状态流转时，组件本身需要 interactive——在页面中通过正常操作展示出状态流转的过程。
2. 每次拆分 subsection 都遵循 **MECE** 的逻辑（同一层级单一维度划分，互斥且完备）。
