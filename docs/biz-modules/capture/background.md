# Capture 模块业务背景

> 来源：`docs/iterations/v1/Reflecta - PRD.md`
>
> 适用范围：Capture 模块的产品背景、业务价值、经典场景与核心需求。作为模块设计文档（v2.0）的前置上下文。

---

## 产品愿景

> **让每一次经历与认知，都造就更好的自己。**

当下所有的经历都是经验，只有有效地积累经验，才有可能在某一件想要达成的事情上实现突破。本产品希望成为一个**个人认知成长的载体**——将碎片化的想法、经历、洞见沉淀下来，并通过概念之间的关联与碰撞，逐步构建出属于自己的"知识网"，从而清晰地知道自己已经掌握了什么、还欠缺什么，加速个人的学习与成长进程。

---

## 业务价值

### 1. 无损捕获，不遗漏任何认知碎片

在灵感或洞见出现的第一时间完成记录，允许内容以碎片、孤立的形态存在，不强迫即时分类与整理，确保每一个有价值的想法都不被遗漏。

### 4. 经验溯源，让每个认知有根可循

每一个概念都附带其来源与上下文（个人经历、外部观点、权威资料等），使认知不悬空，有案例支撑，从而更加扎实、可信。

---

## 经典使用场景

### 场景一：碎片记录 → 沉淀 insight

> 用户看了一个关于"身份认同"的视频，当下有所触动。

用户快速记录这一 idea，打上领域标签（如 `#自制力`）。此时内容可以是一句话，无需完整。后续在整理时，系统帮助用户将其归入相关概念节点，等待进一步关联与深化。

---

### 场景三：经验印证 → 强化已有认知

> 用户在实际工作中体验到了"深度疲惫感"，联想到此前记录的"quality-driven 工作方式"。

用户将这段亲身经历作为 context 附加到对应概念上，并进一步关联"深度工作的 SOP"这一 insight，使原本抽象的概念因真实案例的加入而变得更加具体和可信。

## 核心概念

### Thought

产品的最小内容单元，分为两种类型：

**Idea**
从具体经验、输入或观察中得到的朴素结论。来源可以是个人经历、阅读、视频、他人观点等。

> 示例：`射手前期要猥琐发育`、`重复会重塑大脑`

**Insight**
通过对一个或多个 Idea 进行关联、抽象或总结而形成的更高层理解。可以独立创建，也可以在正文中通过 `[[title#id]]` 引用已有 Thought 来建立关联。

> 示例：`射手就是玻璃大炮`（由"前期猥琐发育"和"碰到刺客要出肉"推导而来）

Thought 的共同属性：

- 系统层面统一为同一种对象，type 为 Idea 或 Insight
- 正文支持 Markdown
- 可归属多个 Category
- 可挂载多个 Context
- 可在正文中通过 `[[title#id]]` 语法引用其他 Thought，系统自动维护双向关联
- 被其他 Thought 引用时，可在详情中查看 backlinks 列表

---

### Context

附属于 Thought 的背景材料，记录这个 Thought 从哪里来、当时的细节是什么。让一个 Thought 不只是一句空洞的结论，而是有迹可循、可回忆的认知。

- 一个 Thought 可以挂载多个 Context
- Context 不是独立节点，不参与图谱，不能被双向链接引用
- 来源类型：个人经历 / 书籍 / 文章 / 视频 / 他人观点

---

### Category

用户主动维护的领域分区，用于在多线学习过程中隔离、浏览和筛选不同主题下的 Thought。

- 树形结构，支持多级嵌套（如 `Finance > Trading > ICT`）
- 一个 Thought 可归属多个 Category
- 不代表 Thought 的唯一位置，而是帮助用户做局部观察的视角
- 同一个 Thought 出现在多个 Category 下是正常现象

---

### 双向链接（Double-link）

Thought 与 Thought 之间的关联关系，由系统根据用户在正文中书写的 `[[title#id]]` 语法自动解析和维护。用户不需要离开编辑上下文进行手动添加或删除，关联随写作自然产生。被引用的 Thought 会自动获得 backlinks，在图谱中呈现为连线。

---

## Capture 页面业务需求

**定位**：认知事件发生时的工作台。面向用户处于"热状态"时的完整认知闭环——从记录新的 idea 或 experience，到主动发现与已有 Thought 的关联，到就地产生并记录 insight，全程不需要离开 Capture。

> Capture 不只是"写下来"的地方，而是从记录到关联到生产的完整热路径发生的现场。

### 3.1 页面结构

左右两栏布局：

- 左侧：Category 树
- 右侧：Thought 列表 + 编辑区

---

### 3.2 左侧：Category 树

**展示**

- 根节点为「All」，展示所有 Thought
- 每个节点显示 Category 名称及其下的 Thought 总数
- 默认只计入直属 Thought，开启 Show All Descendants 后包含子节点
- 支持展开 / 折叠子节点
- 当前选中节点高亮

**操作**

- 新建 Category：指定父节点，输入名称
- 重命名 Category
- 删除 Category：其下 Thought 归入父节点，需二次确认
- 拖拽调整层级结构

---

### 3.3 右侧顶部：搜索与筛选

- **搜索框**：全文搜索当前 Category 下的 Thought 正文及 Context 内容，实时高亮匹配关键词
- **类型筛选**：All / Idea / Insight
- **展示所有**：开启后递归展示当前节点下所有子 Category 的 Thought；关闭时仅展示直属 Thought
- **排序**：最新创建 / 最近修改

---

### 3.4 右侧：Thought 列表

卡片式布局，每张卡片展示：

**卡片内容**

- 正文 Preview（超出 3 行折叠）
- 类型标签：`Idea` / `Insight`，不同颜色区分
- 所属 Category（支持多个，面包屑形式展示）
- Context 数量
- 双向链接数量（出链 + 入链），点击后跳转至 Contemplate 并高亮该节点
- 创建时间 / 最近修改时间

**卡片操作**

- 点击卡片：右侧展开 Thought 详情与编辑区
- 编辑
- 删除（二次确认）
- 修改 Category 归属
- 新增 Context
- 在 Contemplate 中查看

---

### 3.5 Thought 编辑区

点击卡片后在右侧展开，包含：

**基本信息**

- 正文输入（Markdown）
- Category 归属（多选）

**Context 区域**

- 展示该 Thought 下已有的 Context 列表
- 每条 Context 显示：内容摘要 + 来源类型 + 记录时间
- 支持展开查看完整内容
- 支持新增、编辑、删除单条 Context

**双向链接区域**

- 展示该 Thought 在正文中通过 `[[title#id]]` 引用的其他 Thought 列表（引用了谁 / 出链）
- 展示在正文中引用了该 Thought 的其他 Thought 列表（被谁引用 / 入链 / backlinks）
- 点击可跳转至对应 Thought

---

### 3.6 新增 Idea / Insight

**新增 Idea** 点击「+ Idea」，在编辑区创建新 Thought：

- Category 默认继承当前选中 Category，可修改
- 创建后可在正文中通过 `[[title#id]]` 引用已有 Thought，系统自动维护关联

**新增 Insight** 点击「+ Insight」，在编辑区创建新 Thought：

- 触发场景：用户在热状态下，已发现与已有 Thought 的关联，就地记录由此产生的更高层理解
- Category 默认继承当前选中 Category，可修改
- 创建后可在正文中通过 `[[title#id]]` 引用已有 Thought，关联关系在图谱中呈现为连线

---

### 3.7 新增 Context

**路径一：从 Thought 编辑区直接新增** 在已有 Thought 的 Context 区域点击「+ Context」，填写内容后保存。

**路径二：从新经历出发反查 Thought** 用户有了一段新经历或材料，希望找到合适的 Thought 挂载：

1. 通过搜索或浏览找到目标 Thought
2. 进入该 Thought 编辑区，新增 Context
3. 若没有找到合适的 Thought，先创建新 Thought，再挂载 Context
