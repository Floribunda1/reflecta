# v1.2.0 知识漫步价值主张

> 日期：2026-07-20
>
> 状态：产品方向已确认
>
> 职责：定义知识漫步为什么存在、为用户创造什么价值，以及改版不可走偏的边界。本文不承担技术选型与实施拆解。
>
> 上位依据：[Reflecta Value Proposition](../../references/product/value-proposition.md)

## 一句话

知识漫步让用户通过一张可探索的领域图谱，反复重新遇见自己形成过的 Understanding，并随时进入原文与 Context，逐渐看清自己在这个领域已经知道什么。

## 用户真正需要的不是阅读队列

Reflecta 已经帮助用户把学习、实践和对话沉淀为 Understanding，但“写下来”并不等于“这些理解仍然活在用户心里”。用户需要经常回到一个 Domain，重新看见自己曾经形成的判断，想起它当时对应的场景和心智，再决定是否继续深入。

之前的连续阅读方案把这个动作理解成“按顺序读完一批笔记”。它虽然提高了正文可读性，却把用户放进一条系统预先铺好的线性通道：用户只能顺着内容走，很难产生“接下来我想看看哪个”的主动选择，也缺少重新辨认整个领域的感觉。

用户真正满意的动作更接近：

```text
打开一个 Domain
  → 看见这个领域中的全部 Understanding
  → 某个节点因为位置、名称或关系引起注意
  → 主动点击并进入原始笔记与 Context
  → 想起、重述、修正或深化这条理解
  → 回到仍保持原状的图谱
  → 自己选择下一个想看的节点
```

这个循环不是阅读路径，也不是复习任务。它是一连串由用户自己发起的重新相遇。

## 图谱在这里承担什么

知识漫步中的图谱首先是一张探索界面，其次才是关系可视化。

### 让用户一眼看见领域的体量

用户打开一个 Domain 时，应该立即感受到：“我已经在这里形成过这些理解。”节点的数量和分布不是完成度，也不是成就统计，而是用户真实积累在空间中的直接呈现。

### 提供可以自主选择的视觉目标

每个节点都是一个可进入的 Understanding。用户不需要先决定搜索词，也不需要接受系统给出的下一条内容；他可以根据标题、位置和真实 Connection，自主选择此刻最想重新进入的理解。

### 保留对领域形状的感知

用户从图谱进入详情，再返回同一张图谱。稳定的空间和视口让用户始终知道自己身处哪个领域，并逐渐对其中哪些内容熟悉、哪些内容相连、哪些内容仍然独立形成直觉。

### 让知识呈现为活的对象

力导向布局的自然运动、节点 hover 后显现的邻居关系，以及点击后的聚焦状态，让图谱更像一个可以探索的知识空间，而不是静态目录。动效服务于空间形成和交互反馈，不承担装饰或奖励功能。

## 孤立 Understanding 仍然成立

图谱的价值不以存在大量 Connection 为前提。

当前知识库中很多 Understanding 是孤立的，这不代表它们无效，也不要求系统自动补全关系。一个孤立节点仍然能够：

- 让用户重新看见一条自己形成过的理解。
- 因标题或位置引起用户的辨认和好奇。
- 被点击进入原文和 Context。
- 在用户真正意识到关系时，再自然建立 Connection。

Connection 只负责如实表达用户已经建立的关系。它会让图谱逐渐丰富，但不是进入知识漫步的门槛，也不是衡量积累质量的分数。

## 用户获得的正向反馈

知识漫步不制造积分、完成率、连续天数或掌握度。正向反馈来自用户在探索中重新认出自己的内容：

- “原来我已经在这个领域想过这么多。”
- “我看到这个节点，就想起了当时那段经历。”
- “这条理解我现在已经能直接说清楚了。”
- “这两条内容原来真的有关，我现在愿意把它们连起来。”
- “这条旧表达已经不准确，我想进去改一下。”
- “我知道自己接下来还想看看哪个节点。”

产品不要求这些事情每次都发生。只要图谱持续提供重新相遇的机会，用户会随着重复探索变得更熟悉、更快，也更容易在真正有感觉的地方进入得更深。

## 借用用户熟悉的产品形态

知识漫步直接采用用户已经熟悉的 Obsidian Graph View 心智：

- 画布可以平移和缩放。
- Understanding 以节点出现，真实 Connection 以边出现。
- 图谱通过力导向布局自然展开。
- Hover 节点时突出自身、邻居与相连边，其他元素退后。
- 点击节点时保持聚焦，并在右侧打开原始笔记详情。
- 关闭详情后回到原来的图谱视口和选择上下文。

Reflecta 不在这套交互之上再创造“漫步路线”“知识旅程”“认知层级”等概念。Domain、Understanding、Context 和 Connection 已经足够表达产品模型。

## 产品原则

### 1. 图谱是知识漫步的主要表面

知识漫步打开后，用户首先面对当前 Domain 的图谱。列表、连续阅读和统计不能与图谱争夺主入口。

### 2. 节点是内容入口，不是抽象数据点

每个节点必须对应一条真实 Understanding，并能直接进入现有详情、原文和 Context。图谱不是只能观看的可视化。

### 3. 关系必须如实呈现

只显示真实 Connection。没有关系就保留孤立节点，不用 AI、时间顺序、语义相似度或视觉聚类伪造关系。

### 4. 空间连续性优先

打开详情、关闭详情以及在图谱和内容之间往返时，应尽量保留视口、缩放和当前节点，让用户不会每次都重新定位。

### 5. 动效用于建立空间

力导向动画帮助节点展开、适应增删和响应拖拽。它应当自然、可停止且不会持续扰动阅读，不用弹跳、发光或奖励动画刺激用户。

### 6. 回顾由探索自然发生

系统不规定阅读顺序、浏览数量或完成条件。用户打开哪些节点、停留多久、何时建立 Connection，都由当下兴趣决定。

### 7. 熟悉形态优先于产品创新

节点、边、缩放、平移、hover、点击和右侧详情遵循成熟图谱产品的共识。除非真实使用证明现有心智无法满足需求，否则不增加新的控制和术语。

## 明确不做

- 不把知识漫步重新做成连续阅读页、瀑布流或卡片墙。
- 不提供系统生成的阅读路径、下一条推荐或随机跳转。
- 不用时间顺序、语义相似度或 AI 猜测生成 Connection。
- 不把孤立节点表达成错误、欠债或待整理事项。
- 不引入复习计划、到期队列、已读状态、掌握评分或连续天数。
- 不用节点数量、边数量或浏览数量制造成就感。
- 不在图谱上叠加搜索、过滤、分组、图例和配置面板，除非后续真实使用表明它们不可缺少。
- 不创造 Domain、Understanding、Context、Connection 之外的新产品概念。

## 判断改版是否成功

成功不是图谱看起来复杂，而是：

- 用户进入某个 Domain 后自然产生“我想点开这个看看”的冲动。
- 用户能通过图谱感受到该领域已经存在的 Understanding，即使其中大部分仍然孤立。
- 用户在图谱与详情之间往返时不会失去位置和探索上下文。
- Hover、缩放、拖拽和力导向运动共同形成接近 Obsidian 的直接操作感。
- 用户会在没有任务和提醒的情况下，经常回来重新打开节点。
- 重新遇见旧 Understanding 会自然促成回忆、修改、补充 Context 或建立真实 Connection。

失败信号包括：图谱只是静态装饰；节点难以辨认或点击；缩放后标签行为怪异；动画缺失或持续扰动；点击后高亮逻辑不清楚；打开详情后丢失原图位置；或者产品又要求用户沿固定顺序阅读。
