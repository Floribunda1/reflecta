1. 背景介绍

本报告调研 个人知识管理（PKM）+ AI 对话类产品中，向个人用户展示"使用痕迹"的统计模块：首页 / 仪表盘 / 侧栏上的活动统计、热力图、连续记录、年度回顾等。

调研触发点（用户口述）：Reflecta 当前 Capture 首页统计（CaptureStats）只基于一种实体——理解笔记（总理解 / 本周新增 / 连续记录 / 上下文数 + 12 周热力图）。用户认为这套逻辑不合理，直觉是"应该展示所有用这个产品的痕迹，包括对话、理解笔记以及画布等"。本报告呈现行业现状，供用户自行判断。
用户产品自身的约束背景（来自 Reflecta 项目文档，非调研结论）：value-proposition 明确「把知识边界做成抽象分数或仪表盘」属 Never 方向；feature-set-guide 在图谱形态下把「数量统计 dashboard」列为 Not Now。此为既有决策，仅作判断背景。

理解假设：本报告按"个人知识 + AI 对话应用的跨实体使用痕迹统计"理解该模块；若实际指团队级统计等，请指出后将重新选品。

3.1 调研总结论

结论一：个人"使用痕迹统计"普遍以单实体为对象，收敛到同一套范式 高可信

几乎所有做个人统计的产品都以一种实体（memo / 日记条目 / 笔记文件 / 对话）为计数对象，呈现为 GitHub 式热力图 + 连续记录（streak）+ 少量汇总数字。

  • Flomo 官方：侧栏 12 周热力图（周一开头、五档深浅）+ 记录统计（累计笔记数、标签数、记录天数等八维度）。官方
  • Day One：Journal Streaks + 日历视图。官方
  • Apple Journal：Insights（日/周 streak + 日历）。官方
  • Obsidian / Logseq：插件（Vault Activity Heatmap、obsidian-data-analysis、Keep the Rhythm、vault-pulse、logseq-plugin-heatmap）几乎全是"热力图 + 汇总卡 + 趋势图"。社区开源
  • GitHub：贡献图 = 365 天网格，是范式源头。官方

Reflecta 现有 CaptureStats 正属这一范式（单实体理解笔记的活动统计），是行业标准做法。

结论二：行业内没有"跨实体统一痕迹统计"的成熟先例 高可信

检索到的 15 家产品中，没有一家把"笔记 + 对话 + 画布 + 其他实体"聚合进统一统计视图。最接近的两个：

  • 语雀「文稿数」：按小记 / 文档 / 表格 / 画板 / 数据表分别计数并汇总——但是配额计数器（每月 1 号清零、删除不释放），不是仪表盘，不呈现趋势/节奏。
  • Flomo「记录统计」：宣称"八个维度"，但全部来自 memo 单一实体。

用户设想的"展示所有使用痕迹（对话、理解笔记、画布）"没有现成竞品范式可抄——这是真实的行业空白，也是本报告最重要的发现。

结论三：AI 对话侧对个人"使用痕迹"统计极其克制，只有两种形态 高可信
  • 一次性回顾报告：ChatGPT "Your Year"（年度：消息数、聊天数、风格、最活跃日、图片数；需开启 chat history + memory，部分国家/用户可见）媒体来源；Claude Monthly Recap（月度，beta，主题 + 使用时间模式，需 memory）官方。
  • 计费导向用量仪表盘：Claude Settings > Usage（实时用量、月度花费、限额进度条）官方；ChatGPT 用量页。
  • Gemini 只有 My Activity 活动管理（隐私视角）；Perplexity 只有 History/Threads 管理。均无常驻热力图或统计。
  • ChatGPT 的热力图需求由第三方补齐：chatgpt-data-viewer 用导出数据渲染 GitHub 式贡献图。第三方
结论四：PKM 官方普遍不做统计；官方分析偏向协作或配额视角 中可信
  • Obsidian、Logseq 官方均无统计，由插件生态覆盖（官方未声明原因，见信息缺口）。
  • Notion 个人无统计；官方只有 Page Analytics（单页阅读/编辑，协作视角）与 Workspace Analytics（Enterprise）。官方
  • Evernote 个人无统计；官方只有 Teams Activity History（管理员审计）。官方
  • 语雀：个人侧年度报告 + 文稿数配额；单篇文档统计偏内容运营。部分官方
研究见解：行业现状可概括为"单实体统计是共识、跨实体统计是空白、AI 对话侧只有回顾与用量"。用户对现有统计"不合理"的感受，很可能来自"拿单实体统计范式去服务一个多实体产品"；如何取舍是产品决策，本报告不替用户作答。

3.2 核心能力（能力解析 + 各家做法）

能力 1：活动热力图（GitHub 式贡献图）

能力解析：把"每天有没有用、用了多少"压成一屏可扫的网格，让用户一眼看到长期节奏。分歧：时域（12 周 vs 365 天）、计数口径（创建数 vs 字数）、点击是否回看当天。

  • GitHub（源头）：365 天网格，按天贡献数着色，可切公开/私有。
  • Flomo（官方内置）：12 周、周一开头、四色五档；点击有记录的格子直接筛选到当天记录；可隐藏/显示。
  • Obsidian 插件：Vault Activity Heatmap（365 天，点某天看文件）、writing-heatmap（笔记数+字数双维度）、vault-pulse（53×7 网格）。
  • Logseq 插件：heatmap 按当天 journal block 数，作者明示因无时间戳而"不够精确"。
  • Day One：日历视图（非网格，同属按天着色）。
能力 2：连续记录（streak）

能力解析：连续天数/周数是"养成习惯"的最强单一激励，热力图看长周期、streak 看当下连续性。分歧：口径（日/周）、断档处理、是否允许补救。

  • Day One：Journal Streaks，每个日记本分别计数。
  • Apple Journal：Insights streak，iOS 27 起支持日/周/自动切换。
  • Readwise：过去 7 天漏掉的 Daily Review 可 recover 补回并计入 streak。
  • Flomo / Obsidian 插件（Keep the Rhythm 按字数目标计 streak）。
能力 3：汇总指标卡（总量 / 本周 / 字数等）

能力解析：用几个数字回答"我总共积累了多少"。分歧：量 vs 质、累计 vs 周期、数字是否可点击进明细。

  • obsidian-data-analysis：Summary Cards = 总笔记、总字数、写作 streak、平均每天字数 + tag 分布 + 趋势折线图。
  • Flomo：累计笔记数、标签数、记录天数，点击可开更多维度面板。
  • Readwise：stats 页按天展示复习完成情况与 streak。
  • Day One 总量统计靠第三方脚本（DayOne-stats）。
能力 4：回顾式报告（Wrapped 式年度/月度）

能力解析：一次性、强叙事、可分享的年度/月度报告，用"模式总结"代替常驻仪表盘；是 AI 对话产品唯一的个人统计形态。

  • ChatGPT "Your Year with ChatGPT"：年度，消息数/聊天数/风格/最活跃日/图片数；需 history + memory，部分用户可见。媒体
  • Claude Monthly Recap：月度，beta，主题 + 使用时间模式 + "可以尝试什么新方向"。官方
  • 语雀年度报告（2022 起）：文档数 + 字数，三入口 + 晒图兑会员（营销属性）。官方公众号
能力 5：跨实体 / 跨类型计数

能力解析：把不同内容类型放进同一套计数——与用户设想最接近的能力，但行业里只有配额计数、没有统计仪表盘形态。

  • 语雀「文稿数」：小记/文档/表格/画板/数据表各自新建数之和；新建 +1、删除/归档不释放、每月 1 号清零；会员页/空间费用中心可见（配额用途）。
能力 6：用量 / 配额仪表盘（AI 对话侧）

能力解析：让用户看到"还剩多少额度"，本质是计费透明而非使用痕迹，但它是 AI 侧个人可见的唯一常驻"数字面板"。

  • Claude：Settings > Usage 实时用量、月度花费、5 小时会话与每周限额进度条。
  • ChatGPT：用量页监控额度与成本；Enterprise 另有 Workspace Analytics（活跃用户、项目/应用/技能趋势、基准对比）。
能力 7：单篇内容 / 工作区分析（协作视角）

能力解析：面向"内容是否被看、被编辑、被协作"，服务分享与团队场景；与"个人使用痕迹"是两套东西，但常被并称"统计"。

  • Notion Page Analytics：单页总浏览/独立浏览/编辑者（owner/editor 权限；workspace 级为 Enterprise）。
  • 语雀文档统计分析：单篇阅读次数、独立访客、平均阅读时长、编辑历史时间轴（来源为第三方教程，标注）。
  • Evernote Teams Activity History：管理员查看 18 个月内成员操作日志（含用户与 IP）。

3.3.1 产品定位画像

产品焦点：

Flomo

定位

面向"随手记录想法"的个人笔记（"flomo = flow + memo"），官网明确"多维度统计让习惯自然养成"。

差异化场景

碎片速记 + 每日回顾 + 习惯养成；热力图与统计被官方定位为"帮你持续记录"的陪伴功能。

核心差异

低门槛记录 + 官方内置回顾/统计闭环（每日回顾、随机漫步、热力图），统计服务留存目标。

语雀

定位

阿里系文档/知识库，个人到团队全覆盖（学生、职场、团队协作）。

差异化场景

文档承载知识沉淀 + 团队协作；统计分两轨——个人侧（年度报告、文稿数配额）与内容运营侧（单篇统计分析）。

核心差异

协作与知识库体系；文稿数是配额计费用途而非用户洞察，统计不是其产品主张。

Day One

定位

私人日记应用（多日记本、加密、时间线），面向坚持写日记的个人。

差异化场景

情感/生活记录；streak 与日历是"保持写日记"的动机机制。

核心差异

私密性与长期存档（On This Day、日历回看），streak 是习惯粘性的核心。

Apple Journal

定位

系统级日记应用（iOS/macOS 内置），面向 iPhone 用户的轻量记录。

差异化场景

系统集成（建议、照片/地点自动唤起）；Insights 负责习惯追踪。

核心差异

系统生态内免费、零摩擦；统计极简（streak + 日历），不是卖点。

ChatGPT

定位

通用 AI 对话助手（个人 + 企业）。

差异化场景

对话即产品本体；个人统计只有年度回顾（叙事型）与用量页（计费型）。

核心差异

模型能力与生态；统计克制到"一年一次"，避免用数据打扰对话主场景。

Claude

定位

AI 对话助手（个人 Pro/Max + 团队/企业）。

差异化场景

长对话与上下文（memory、chat search）；Monthly Recap 主打"无评判地照见使用模式"。

核心差异

上下文连续性；统计同样克制（月度回顾 + 用量仪表盘）。

Gemini

定位

Google 的 AI 对话助手（个人/工作账号）。

差异化场景

与 Google 账号体系集成；统计缺位，只有 My Activity 活动记录管理（查看/删除 prompt，隐私视角）。

核心差异

账号生态与隐私控制；无任何使用痕迹统计。

Perplexity

定位

AI 搜索对话助手。

差异化场景

会话即搜索；只有 History/Threads 管理（临时线程过期机制），无统计。

核心差异

检索能力与引用；统计完全缺位。

Obsidian（插件生态）

定位

本地优先的 Markdown 双链知识库，面向重度知识工作者。

差异化场景

文件即知识的自由与可迁移性；统计完全由社区插件承担。

核心差异

本地文件 + 插件生态；官方不做统计本身是"核心克制"的定位选择（官方无声明，见缺口）。

Logseq（插件生态）

定位

大纲式本地知识库（journal 优先），面向流程化记录者。

差异化场景

journal/block 驱动；统计靠插件（heatmap、log-stats）。

核心差异

大纲与块级引用；统计由插件补齐，且插件作者明示数据精度受限（无块时间戳）。

Notion

定位

all-in-one 工作空间（笔记/数据库/项目），个人到企业。

差异化场景

数据库驱动的自定义仪表盘；官方统计只有 Page/Workspace Analytics（阅读与协作视角，workspace 级需 Enterprise）。

核心差异

数据库 + 模板生态；个人"使用痕迹"统计由用户用数据库自建（Life OS 模板文化），官方不提供。

Evernote

定位

经典笔记应用（个人 + 团队/企业）。

差异化场景

长期笔记管理；个人版无统计，官方统计只有 Teams Activity History（管理员审计）。

核心差异

历史存量与多端同步；统计缺席是产品老化/定位转向的信号之一（据调研事实观察，不做价值判断）。

Readwise

定位

阅读摘录回顾（高亮重读、每日回顾），面向主动复习的读者。

差异化场景

间隔重复式复习；stats 页展示每日复习完成 + streak + recover 补卡。

核心差异

回顾习惯（每日邮件/APP 提醒）；统计是"复习习惯养成"的运营杠杆。

GitHub

定位

代码托管与协作平台。

差异化场景

个人主页的贡献图是开发者身份的"打卡墙"，被广泛复刻为热力图范式源头。

核心差异

社区与贡献记录；贡献图同时承担身份展示与自我激励。

Heptabase

定位

视觉化知识库（whiteboard + card + journal），面向学生/研究者/终身学习者——与 Reflecta 定位最近的产品。

差异化场景

可视化理解整理；官方未提供任何使用统计（wiki 无统计文档，见缺口）。

核心差异

白板化理解 + 期刊捕捉；统计缺席说明"理解型"产品当前普遍不把使用痕迹统计当作价值主张。

3.3.2 差异化功能对比

维度 1：统计的"对象实体"——单实体 vs 跨实体

产品统计对象
Flomomemo（单一实体）
Day One / Apple Journal日记条目（单一实体）
Obsidian / Logseq 插件笔记文件 / journal block（单一实体）
ChatGPT / Claude对话（单一实体，且只有回顾/用量）

其余（Notion/Evernote/Heptabase 等）无统计

这是差异最显著的维度：跨实体统计只有"配额计数"一种实现，没有统计仪表盘实现。语雀的文稿数把五种内容类型放进同一个"本月新建数"，规则为"新建 +1、删除/归档不释放、每月 1 号清零"，服务会员配额而非用户洞察——即便有跨实体计数的产品，动机也是计费口径。

维度 2：常驻 vs 一次性

产品形态

ChatGPT、Claude、语雀一次性型：年度/月度报告，强叙事可分享

4. 结论

覆盖情况：15 个产品、6 种形态。个人统计成熟形态集中在"日记/速记/复习"类（Flomo、Day One、Apple Journal、Readwise）与 PKM 插件生态（Obsidian、Logseq）；AI 对话侧只有一次性回顾与用量页；文档/协作侧（Notion、Evernote、语雀）的统计偏向内容运营或配额。

一致与分歧：

  • 高度一致：个人"使用痕迹"统计 = 单实体 + GitHub 式热力图 + streak + 汇总数字。
  • 一致缺席：AI 对话产品没有常驻个人统计；PKM 官方普遍不做统计（插件/模板补齐）。
  • 分歧点：统计入口常驻（侧栏）vs 一次性（年度/月度）；激励设计（streak/recover）vs 中性呈现；官方内置 vs 社区插件。
  • 行业空白：跨实体（笔记+对话+画布）的统一痕迹统计，15 家无一实现；唯一的多类型计数（语雀文稿数）是配额语义。
