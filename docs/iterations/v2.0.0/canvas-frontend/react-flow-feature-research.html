按主题综合发现

高可信Core 默认Core 配置

默认手势是地图式，不是设计工具式

直接拖 pane 平移；Shift+拖拽框选；默认 Full 命中；macOS Meta / 其他 Ctrl 追加多选；默认删除键是 Backspace。

证据与含义

ReactFlow API 记录全部默认 props。设计工具式配置是官方展示的一组可选值，不是默认。

高可信Core 默认Core 配置

选择状态由 Core 管，选择视觉由自定义节点负责

React Flow 会给自定义节点注入状态并添加公开 class，但节点样式本身属于应用。没有视觉反馈不代表 selection 没发生。

证据与含义

见 Custom Nodes 与 Theming。

高可信Core 配置

受控模式是最容易阻断默认行为的接缝

应用必须完整应用 NodeChange / EdgeChange。只保留“需要落库”的 change，会连 selection 等 UI 状态一起过滤掉。

证据与含义

Adding Interactivity 要求受控 flow 接入 change handlers。

高可信官方配方Pro外部

撤销、布局、参考线与协作都不是 Core 默认

undo/redo、copy/paste、helper lines、协作属于 Pro 示例；布局依赖外部引擎。采用后由应用维护完整行为。

证据与含义

见 Pro Examples 与 Layouting。

高可信官方配方Pro

React Flow 不是白板产品

rectangle、eraser、lasso 是 OSS 配方，freehand 是 Pro；官方明确说 React Flow 并非为 whiteboard app 设计。

证据与含义

见 Whiteboard Features。

高可信React Flow UI

React Flow UI 是源码分发层，不是 Core

它基于 shadcn/ui 与 Tailwind，通过 CLI 把代码复制进项目。复制后可改，也由项目自己维护。

证据与含义

见 React Flow UI。

高可信工程约束

真实浏览器才是交互验收环境

React Flow 依赖 DOM 尺寸和 transforms；官方推荐 Playwright/Cypress，Jest 需补浏览器 API mocks。

证据与含义

见 Testing。

多人协作是完整同步系统，不是打开一个 prop

需要持久/临时状态划分、网络、冲突、离线与同步引擎；官方示例以 Yjs 展示一种路径。

缺口与判断规则

判断公式：固定版本 Core 默认 + 当前 props = 可继承基准；任何 adapter、样式、自定义节点、配方或外部依赖 = Reflecta 责任。

可以完整枚举官网产品层和本地集成接缝，不能用有限用例数学证明无限长的交互序列。工程上的完整保证应落到 import、props、handlers、instance API、自定义节点/边、CSS 和数据映射这组有限接缝。规范详见 React Flow 集成与行为基准原则。
