## 待定：滚轮行为（8.4，与产品确认后落实现）

X6 3.1.8 两条链路都可配置，行为完全由配置决定：

- `mousewheel` 插件（enabled / factor / zoomAtMousePosition / **modifiers** / guard）—— 决定「哪些滚轮手势触发缩放」；
- `panning`（eventTypes 含 **mouseWheel**，且 `!ctrlKey`）—— 决定「滚轮平移」。

### 候选方案

- **A（现状）**：滚轮 = 缩放（任意滚轮，以鼠标位置为中心）；中键拖拽 = 平移；Space+拖拽 = 平移。
  - 优点：画布快速 zoom 顺手；实现零改动。
  - 缺点：触控板双指滚动也会触发缩放，容易误触；与主流白板（Figma / Miro / Excalidraw 默认滚轮=平移，⌘/Ctrl+滚轮=缩放）不一致。
- **B（推荐）**：普通滚轮 / 双指滚动 = 平移（panning 加 `mouseWheel`）；**⌘(mac)/Ctrl(win) + 滚轮 = 缩放**（mousewheel.modifiers `['meta']` / `['ctrl']` 分平台，或以 guard 判定）；保留中键 / Space 平移。
  - 优点：触控板友好，贴近主流白板习惯；缩放仍以鼠标位置为中心。
  - 缺点：纯鼠标用户的直觉（滚轮=缩放）要改；需要在编辑区内对「输入框/编辑态」做 guard，防编辑时误平移。
- **C**：滚轮 = 缩放（保持），Shift+滚轮 = 水平平移（panning.mouseWheel 原生按 deltaX/deltaY 平移）。
  - 介于两者之间，视觉工程师常用，但用户难以发现。

### 需要你拍板的点

1. 选 A / B / C？
2. 若选 B：触控板双指滚动要不要和鼠标滚轮一致？（X6 不区分两者，都走 wheel 事件；要区分需 guard 自行判断 deltaMode）
3. 若选 B：缩放快捷键用 ⌘(mac)/Ctrl(win) 双平台都支持，还是只支持其中一个？
