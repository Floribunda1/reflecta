> 本文职责：定义 PMF MVP 的信息架构，也就是用户能到达哪些位置、这些位置之间是什么关系、用户注意力应如何流动。本文不定义数据字段、业务规则、边界条件或视觉样式；这些分别由 product spec 和 design detail 负责。

## 1. 文档边界

本文只回答三个问题：

1. Reflecta PMF MVP 里有哪些主要信息空间？
2. 用户在这些空间之间如何移动？
3. 每个空间应该让用户注意什么？

本文不回答：

- 数据模型是什么。
- 某个操作具体如何落库。
- 双链如何解析。
- 来源如何增删改。
- 关系异常如何处理。
- 页面颜色、阴影、圆角、排版细节。

这些内容以 `../product/domain-workspace-product-spec.md` 和 `./design-detail.md` 为准。

## 2. 信息架构判断

PMF MVP 采用 **Domain Workspace** 作为根空间。

用户不是先进入“捕获”“图谱”“来源”“关系”这些功能模块，而是先进入一个领域语境，然后围绕这个领域里的个人理解工作。

核心判断：

- **领域是语境**：用户进入领域，是为了回到某个思考现场，不是为了管理分类系统。
- **理解是主对象**：用户真正要回看的不是资料、来源、关系数量，而是“我形成了什么理解”。
- **来源贴着理解出现**：来源解释理解从哪里长出来，不作为一级管理空间。
- **关系贴着正文出现**：关系来自正文双链，不作为独立管理空间。
- **图谱不是主入口**：图谱可以在后续作为观察模式，但 PMF MVP 的主路径不是看图谱。

## 3. 顶层结构

```text
Reflecta
└── Domain Workspace
    ├── Domain Navigation
    ├── Understanding Index
    └── Understanding Document
```

三栏是一个连续工作区，不是三个互相独立的页面。

- `Domain Navigation` 负责领域方位。
- `Understanding Index` 负责当前领域里的理解指针。
- `Understanding Document` 负责当前理解的阅读、编辑、来源追溯和关系观察。

## 4. 信息空间

### 4.1 Domain Navigation

用户问题：

> 我现在在哪个领域里？

应该承载：

- 领域列表或领域树。
- 当前选中领域。
- 未归类入口。
- 新建领域入口。

不应该承载：

- 来源统计面板。
- 关系健康度。
- 掌握度评分。
- AI 总结。

注意力规则：

- 它是方位层，不是主内容层。
- 它应该帮助用户稳定当前语境，而不是抢走 Document 的注意力。
- 未归类应该存在，但低权重；它是暂放空间，不是长期主空间。

### 4.2 Understanding Index

用户问题：

> 我在这个领域里已经形成了哪些理解？

应该承载：

- 当前领域下的理解条目。
- 每条理解的标题或临时标题。
- 正文摘要。
- 来源摘要。
- 双链关系摘要。
- 更新时间。
- 新建理解入口。
- 当前选中指针。

不应该承载：

- 大卡片墙。
- 来源全文。
- 关系管理表单。
- 图谱替代视图。
- 系统评分。

注意力规则：

- Index 是高密度扫描区。
- 理解摘要是主信息。
- 来源和关系是辅助线索，用来帮助用户恢复记忆。
- 没有来源、没有关系的理解仍正常出现，不被表达成错误。

### 4.3 Understanding Document

用户问题：

> 这条理解完整表达了什么？它从哪里长出来？它和哪些理解通过正文发生了连接？

应该承载：

- 当前理解的标题。
- 当前理解的正文。
- 正文中的 `[[双链]]`。
- 来源摘要。
- 单条来源详情 overlay 的入口。
- 领域归属。
- outgoing / incoming 关系展示。
- 未解析双链的轻量状态。

不应该承载：

- 独立关系管理器。
- 手动添加关系入口。
- 手动删除关系入口。
- 来源管理后台。
- 保存状态面板。
- 草稿状态。

注意力规则：

- 第一视觉焦点是标题和正文。
- 来源在正文之后出现，帮助用户追溯，不淹没正文。
- 双链作为正文的一部分出现，不被转译成单独关系任务。
- 关系展示区只解释正文双链产生的连接，不创造新的关系入口。

### 4.4 Source Detail Overlay

用户问题：

> 我刚刚点开的这条来源具体是什么？

应该承载：

- 来源类型。
- 来源名称。
- 来源内容。
- 字数或轻量元信息。
- 关闭入口。

不应该承载：

- 全部来源管理。
- 来源库。
- 来源筛选器。
- 与当前理解无关的来源。

注意力规则：

- 它是从某条来源摘要临时打开的阅读层。
- 关闭后回到原 Understanding Document。
- 它可以比普通 surface 更强，但不能改变底层三栏结构。

### 4.5 Graph Observation

用户问题：

> 当前领域里的双链关系形成了怎样的结构？

MVP 判断：

- 图谱不进入默认主 IA。
- 图谱可以作为后续观察模式。
- 图谱只呈现双链解析出的关系。

不应该承载：

- 手动建边。
- 自动建边。
- 关系管理后台。
- 日常新建理解的主入口。

## 5. 主路径

### 5.1 新建理解

```text
选择领域
  -> 点击新建理解
  -> 当前领域中立即出现空理解
  -> Document 选中这条空理解
  -> 用户直接写标题和正文
  -> 可继续添加来源
  -> 可在正文里输入 [[双链]]
```

注意力变化：

1. 领域让用户确认“我把这个理解放在哪个语境里”。
2. 空理解出现在 Index，让用户确认它已经进入当前领域。
3. Document 成为主要写作表面。
4. 来源和双链是贴着正文发生的补充动作。

IA 约束：

- 不跳到独立新建页面。
- 不出现复杂创建表单。
- 不要求用户先填来源或关系。
- 不出现保存流程作为路径节点。

### 5.2 回看领域

```text
选择领域
  -> 扫描 Understanding Index
  -> 选中某条理解
  -> 阅读 Understanding Document
  -> 看到来源摘要和双链关系
  -> 必要时继续跳转到来源或相关理解
```

注意力变化：

1. Domain Navigation 给出回看范围。
2. Index 给出“这个领域里有哪些理解”的盘点感。
3. Document 让用户恢复单条理解的完整表达。
4. 来源摘要帮助用户恢复“这条理解从哪里来”。
5. 双链和 relation area 帮助用户继续走到相关理解。

IA 约束：

- 回看主路径不是图谱。
- 回看主路径不是来源库。
- 回看主路径不是关系管理。
- 独立理解仍在 Index 中正常出现。

### 5.3 追溯来源

```text
阅读 Understanding Document
  -> 扫到来源摘要
  -> 点击某条来源
  -> 打开 Source Detail Overlay
  -> 阅读完整来源
  -> 关闭 overlay 回到原理解
```

注意力变化：

1. Document 正文仍是起点。
2. 来源摘要只提供足够线索，不展开长文。
3. Overlay 只服务当前被点击的来源。
4. 关闭后回到原理解，不让用户掉进来源管理空间。

IA 约束：

- 点击单条来源只打开单条来源。
- 不进入全部来源 reader。
- 不创建独立 Source 一级页面。

### 5.4 通过双链走到相关理解

```text
阅读正文
  -> 看到 [[双链]]
  -> 点击双链
  -> Document 切换到目标理解
  -> Index 更新当前选中指针
```

注意力变化：

1. 双链首先是正文表达。
2. 用户点击它，是想去看那条理解。
3. 跳转后仍留在 Domain Workspace，而不是进入关系页面。

IA 约束：

- 不打开关系管理面板。
- 不要求用户确认关系。
- 不提供手动建关系入口。

### 5.5 调整领域语境

```text
阅读当前理解
  -> 看到领域归属
  -> 添加或移除领域
  -> Index 根据当前领域刷新
```

注意力变化：

1. 领域归属服务当前理解的回看语境。
2. 用户调整归属后，当前领域列表随之变化。
3. 如果理解离开当前领域，用户回到当前领域的下一条理解或空状态。

IA 约束：

- 领域归属不是复杂分类管理。
- 未归类不是错误状态。
- 多领域归属允许存在，但不把新建路径变成分类选择流程。

## 6. 空状态

### 6.1 当前领域没有理解

用户应该看到：

- 当前领域名称。
- 轻量空状态。
- 新建理解入口。

不应该出现：

- 大段教育说明。
- 功能介绍页面。
- 图谱空画布。

### 6.2 新建后的空理解

用户应该看到：

- Index 中的“未命名理解”。
- Document 中的空标题和空正文。
- 来源入口。
- 正文双链能力自然可用。

不应该出现：

- 创建向导。
- 必填字段警告。
- 保存提示。

### 6.3 理解没有来源

用户应该看到：

- 理解仍正常展示。
- 来源区域提供添加入口。

不应该出现：

- 错误状态。
- 质量评分。
- 强制补来源。

### 6.4 理解没有关系

用户应该看到：

- 理解仍正常展示。
- 关系区域表达“暂时独立”。

不应该出现：

- 补关系任务。
- 手动关系创建表单。
- 连接数焦虑。

### 6.5 双链未解析

用户应该看到：

- 未解析双链的轻量状态。
- 可以回到正文修改。
- 如果需要，可以从未解析目标创建新理解。

不应该出现：

- 自动猜测关系。
- 静默建立错误关系。
- 关系管理后台。

## 7. IA 验收

满足以下条件，IA 才成立：

- 用户一进入产品，就能理解自己处在某个领域工作台里。
- 用户能从 Index 获得“这个领域里有哪些理解”的盘点感。
- 用户选中理解后，第一注意力落在 Document 的标题和正文。
- 来源不抢正文，但用户能自然发现和打开。
- 双链不变成独立管理任务。
- 无来源、无关系、未归类都不是错误状态。
- 图谱、来源库、关系后台都没有进入 MVP 主路径。
- 具体功能规则只在 product spec 中定义，IA 不重复定义业务逻辑。
