## 1. 用户是谁，他要做什么

### 1.1 用户目标：这次设计要消除用户的哪个障碍

**用户是谁**

Reflecta 的高频用户是持续学习、复盘和整理判断的人。他会在外部阅读、工作、交易复盘或日常观察中不断产生 Thought，也会周期性回到某个 Category 重新进入已有知识语境。

#### 障碍 1：热状态下的想法容易在记录流程中丢失

用户刚看完一段视频、踩过一个坑、或突然形成一个判断时，记录窗口很短。如果打开工具后还要选空间、填表单、选类型、再进入编辑器，30 秒内没有完成捕捉，用户就会回到外部任务，放弃记录。

**代价**：丢失的不是一条笔记，而是一个刚被触发、还能追溯到具体语境的认知判断。

#### 障碍 2：回到某个领域时，很难快速想起自己已经知道什么

用户在某个 Category 下积累了多条 Thoughts，但过一段时间后只记得自己“写过一些东西”，不记得每条判断的内容、性质和丰富度。如果只能靠时间流、全文搜索或逐条打开详情，用户无法快速恢复思考语境。

**代价**：已有知识不能在新一轮思考中被调用，用户会重复阅读、重复判断，甚至误以为自己没有积累。

#### 障碍 3：旧 Thought 脱离来源后会变成无法判断的口号

用户打开半年前写下的 Thought，记得它重要，但忘了当时基于什么材料、经历或证据。如果来源和背景不在当前阅读语境里，用户需要重新搜索、翻外部材料，或者直接怀疑这条 Thought 的价值。

**代价**：Thought 失去可信度和可延展性，用户可能错误删除、错误修改，或无法继续深化。

### 1.2 本次范围：哪些目标在这次解决，哪些不在

#### IN

- 用户在热状态下快速把新 Thought 放入当前 Category 语境，直接进入可输入状态。
- 用户在某个 Category 下以合适密度浏览 Thoughts，通过卡片线索快速唤起记忆。
- 用户打开 Thought 后，在同一工作台中阅读正文并扫描 Context，快速理解来源和背景。
- 用户在 Capture 中完成轻量整理：修改 Category、管理 Context、查看双向链接和 backlinks。
- 用户离开详情、搜索、筛选或中断后，能回到原 Category、筛选条件和浏览位置。

#### OUT

- 长时间写作、Markdown 精排、专注写作室：交给后续写作能力或 P2 专注模式。
- 图谱探索、关系网络审视、大范围沿双向链接漫游：交给 Contemplate。
- AI 认知深化对话、观点追问和抽象总结：交给 Deepen。
- 完整分类管理后台：Capture 只提供轻量维护入口，避免把管理动作变成主任务。
- Context / 双向链接的系统整理中心：本次只服务当前 Thought 的理解和轻量延伸。

### 1.3 已知约束：来自产品决策的硬条件

| 约束                                                | 来源       | 对设计的影响                                                                       |
| --------------------------------------------------- | ---------- | ---------------------------------------------------------------------------------- |
| Capture 是 `Navigation + Main Content` 的高频工作台 | 模块定位   | 左侧 Category 只能作为常驻导航和轻量维护区，不能升级为独立管理主界面               |
| Primary Focus 是右侧单一内容区                      | 模块定位   | 浏览态和详情态共享右侧主内容区，界面切换要保持同一工作台感                         |
| 核心状态只有 Thought 浏览态和 Thought 详情态        | 模块定位   | 新建、搜索、筛选、Context 管理都必须嵌入这两个核心状态，不能新增独立创建页或管理页 |
| Category 树常驻左侧                                 | 产品决策 1 | 用户选中 Category 后右侧立即更新；新建 Thought 默认继承当前 Category               |
| Thought 卡片不是缩小版详情页                        | 产品决策 2 | 卡片只承担回忆线索，不放完整正文、完整 Context 或正文编辑能力                      |
| 详情态左右分栏，正文为主、Context 为辅              | 产品决策 3 | 详情态必须让正文和 Context 同屏可见，Context 的 visual weight 低于正文             |
| 新建 Thought 直接进入详情态                         | 产品决策 4 | 不允许插入创建前表单、弹窗或独立创建页；创建即编辑                                 |
| 双向链接的大范围探索交给 Contemplate                | 版本边界   | Capture 只展示链接列表和跨模块出口，不在详情态展开图谱                             |

## 2. 用户的行动路径

### 2.1 用户能去的所有地方（信息架构）

```text
Capture
├── Category 导航区
│   ├── All
│   ├── Category 节点
│   │   ├── 展开 / 折叠子节点
│   │   ├── 选中当前 Category
│   │   └── 轻量维护入口：新建 / 重命名 / 删除 / 拖拽调整层级
│   └── 未分类入口
└── 主内容区
    ├── Thought 浏览态
    │   ├── Category 标题与路径
    │   ├── 工具条：新建 Idea / Insight、搜索、类型筛选、子分类范围、排序
    │   ├── Thought 卡片列表
    │   ├── 搜索结果态
    │   ├── 筛选结果态
    │   └── 空态 / 无结果态
    └── Thought 详情态
        ├── 正文编辑区
        │   ├── 标题
        │   ├── 类型
        │   ├── Markdown 正文
        │   └── Category 归属
        ├── 整理延伸区
        │   ├── Context 列表
        │   │   ├── Context 摘要
        │   │   ├── Context 展开态
        │   │   └── 新增 / 编辑 / 删除 Context
        │   └── 双向链接列表
        │       ├── 引用了谁（出链）
        │       ├── 被谁引用（入链 / backlinks）
        │       └── 跳转 Contemplate / 跳转 Thought
        └── 返回浏览态
```

---

### 2.2 每条路径的完整过程

#### Journey 1：在某个 Category 下快速创建 Thought

**用户处境**

用户刚从视频、工作问题或复盘中得到一个判断，当前仍处于外部任务的热状态。他知道这个想法大致属于哪个 Category，需要立刻写下核心内容，并确信之后能按这个 Category 找回。

| #   | 用户做了什么                                  | 这一步注意力应在哪里                                                           | 系统响应                                                                        | 异常                                                                      |
| --- | --------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 1   | 用户打开 Capture，确认当前是否在正确 Category | 左侧选中 Category 和主内容标题路径，因为用户需要确认“这条想法要落在哪里”       | 当前 Category 高亮，主内容标题显示完整路径，右侧展示该 Category 下的 Thoughts   | 如果没有选中 Category，默认落到 All 或最近使用 Category，并提示可修改归属 |
| 2   | 用户点击 `+ Idea` 或 `+ Insight`              | 新建入口和当前 Category 路径，因为用户只需要确认类型和归属，不应被额外表单分散 | 系统立即创建 Thought，进入详情态，默认继承当前 Category，光标进入标题或正文首行 | —                                                                         |
| 3   | 用户输入标题和核心内容                        | 正文编辑区的输入位置，因为热状态下主要任务是把判断写下来                       | 详情态左侧保持主焦点，右侧 Context / 双向链接保持低权重                         | —                                                                         |
| 4   | 用户确认内容已记录，返回列表或直接离开        | Category 归属和返回入口，因为用户需要确认这个 Thought 落在正确语境里           | 返回浏览态后新 Thought 出现在当前 Category 列表顶部或对应排序位置               | 如果用户创建空 Thought 后离开，空内容不进入列表                           |

**路径外异常汇总**

- 用户中途放弃：如果 Thought 为空，离开详情时不进入列表；如果已有输入，则按一条普通 Thought 出现在当前 Category 中。
- 当前 Category 被删除：正在编辑的 Thought 归入被删除 Category 的父节点，并在详情态显示归属变更提示。
- 用户误选类型：类型可在详情态实时修改，不触发确认弹窗。

---

#### Journey 2：快速浏览 Category 下的 Thoughts 并回忆知识

**用户处境**

用户隔了一段时间回到某个领域，想快速想起自己已经知道什么。他不是来管理对象，而是想通过标题、Preview、类型、Context 数量和双向链接数量重新进入思考语境。

| #   | 用户做了什么                             | 这一步注意力应在哪里                                                               | 系统响应                                                                | 异常                                                          |
| --- | ---------------------------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------- |
| 1   | 用户在 Category 树中选择目标 Category    | Category 名称、层级路径和数量，因为用户需要确认自己进入的是哪个领域                | 主内容区标题更新为 Category 路径，列表展示该 Category 下的 Thought 卡片 | —                                                             |
| 2   | 用户扫描 Thought 卡片列表                | 卡片标题、3 行 Preview、类型标签、Context / 双向链接数量，因为这些线索用于唤起记忆 | 单屏展示足够数量的卡片，卡片之间保持可扫描密度；重要 meta 信息稳定出现  | 如果卡片内容为空或极短，显示类型、时间和 Context 作为替代线索 |
| 3   | 用户用搜索、类型筛选或子分类范围缩小范围 | 工具条中的当前条件和结果变化，因为用户需要知道自己正在看哪个子集                   | 列表在原地更新，标题区或工具条显示当前条件，可一键清除                  | 搜索无结果时显示无结果态，并保留搜索词和清除入口              |
| 4   | 用户打开一条 Thought 查看详情            | 被点击卡片和详情标题，因为用户需要感知“我从这张卡片进入详情”                       | 主内容区切换到详情态，左侧 Category 保持不变，详情展示当前 Thought      | —                                                             |
| 5   | 用户关闭详情回到列表继续浏览             | 原卡片位置和列表上下文，因为用户需要继续刚才的扫描过程                             | 恢复原 Category、搜索词、筛选条件、排序和滚动位置，原卡片可短暂高亮     | —                                                             |

**路径外异常汇总**

- 用户切换到其他 Category 后返回：恢复每个 Category 最近一次的筛选条件和滚动位置，至少在当前会话内保留。
- 搜索过程中离开：返回后保留搜索词和结果集，提供清除入口。
- 列表数量很大：使用虚拟滚动或分段呈现，不因卡片数量造成滚动卡顿。
- 子分类范围切换后结果变化过大：工具条明确显示“仅当前 / 含后代”，避免用户误以为内容丢失。

---

#### Journey 3：阅读 Thought 正文后快速扫描 Context

**用户处境**

用户从 Category 列表打开一条旧 Thought，正在判断这条内容从哪里来、在什么背景下成立。他的目标是补足理解，不是进入系统化整理或关系探索。

| #   | 用户做了什么                            | 这一步注意力应在哪里                                                            | 系统响应                                                                                        | 异常                                            |
| --- | --------------------------------------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 1   | 用户打开 Thought 详情，先阅读标题和正文 | 正文标题、类型和正文首屏，因为当前主任务是理解 Thought 本身                     | 详情态左侧为主阅读 / 编辑区，右侧 Context 和双向链接同屏但弱于正文                              | —                                               |
| 2   | 用户扫右侧 Context 列表                 | Context 摘要、来源类型和时间，因为用户要判断这条 Thought 的来源和背景           | Context 以摘要卡片展示，可展开查看完整内容；不需要切换 tab                                      | 无 Context 时显示轻量空态和新增入口，不遮挡正文 |
| 3   | 用户展开某条 Context 查看完整内容       | 当前 Context 与正文的并列关系，因为用户需要保持“这条背景解释当前 Thought”的感知 | Context 在右侧原地展开或抽屉内展开，正文位置不被挤走                                            | —                                               |
| 4   | 用户新增一条 Context 补充背景           | 新增入口、来源类型和内容输入，因为用户是在给当前 Thought 补背景                 | 新 Context 归属当前 Thought，并出现在 Context 列表中                                            | —                                               |
| 5   | 用户查看双向链接或跳转关联 Thought      | 双向链接列表和跨模块出口，因为这是延伸动作，不应抢走正文理解主线                | Capture 内展示出链与入链列表；图谱探索通过入口跳转 Contemplate；点击关联 Thought 可进入对应详情 | —                                               |

**路径外异常汇总**

- Context 很多：右侧列表可滚动，正文区域不被压缩；提供折叠分组或“显示更多”。
- 用户从关联 Thought 跳到另一条 Thought：保留返回链路，返回时回到上一条 Thought 的详情位置。

## 3. 路径上每个节点的设计

### 3.1 每个界面的所有状态

#### Category 导航区

| 状态                      | 触发条件                    | 呈现方式                                                |
| ------------------------- | --------------------------- | ------------------------------------------------------- |
| 空态                      | 用户还没有任何自建 Category | 显示 All 和未分类入口，并提供新建 Category CTA          |
| 正常态                    | 有 Category 数据            | 展示树形层级、展开折叠状态、当前选中节点和 Thought 数量 |
| 交互子状态：hover / focus | 鼠标移入或键盘聚焦节点      | 显示轻量操作入口，选中态和 hover 态视觉区分             |
| 交互子状态：拖拽中        | 用户调整 Category 层级      | 显示目标插入位置和不可放置反馈，右侧当前内容不跳转      |

#### Thought 浏览态

| 状态       | 触发条件                     | 呈现方式                                                                  |
| ---------- | ---------------------------- | ------------------------------------------------------------------------- |
| 空态       | 当前 Category 下没有 Thought | 显示“这个 Category 还没有 Thought”的语义空态，提供 `+ Idea` / `+ Insight` |
| 正常态     | 当前条件下有 Thoughts        | 展示 Category 路径、工具条和卡片列表                                      |
| 搜索结果态 | 输入搜索词                   | 工具条显示搜索词，卡片高亮匹配内容，保留 Category 语境                    |
| 无结果态   | 搜索或筛选后无结果           | 显示当前条件无结果，提供清除搜索 / 重置筛选                               |

#### Thought 详情态

| 状态     | 触发条件                            | 呈现方式                                         |
| -------- | ----------------------------------- | ------------------------------------------------ |
| 新建空态 | 新建 Thought 刚进入详情             | 标题 / 正文输入位就绪，Category 已填入当前选中值 |
| 正常态   | 用户打开已有 Thought                | 左侧正文为主，右侧 Context / 双向链接为辅        |
| 编辑态   | 用户修改标题、正文、Category 或类型 | 内容在原位置直接变化，不出现额外系统状态         |

#### Context 列表

| 状态   | 触发条件                  | 呈现方式                                    |
| ------ | ------------------------- | ------------------------------------------- |
| 空态   | 当前 Thought 没有 Context | 显示轻量提示和新增 Context 入口，不遮挡正文 |
| 正常态 | 有 Context                | 列表展示摘要、来源类型、时间，可展开        |
| 展开态 | 用户展开单条 Context      | 当前条原地展开完整内容，其他条保持摘要      |
| 编辑态 | 新增或编辑 Context        | 在右侧列表区域内编辑，正文区不位移          |

#### 双向链接列表

| 状态   | 触发条件                  | 呈现方式                                                                              |
| ------ | ------------------------- | ------------------------------------------------------------------------------------- |
| 空态   | 当前 Thought 没有双向链接 | 显示轻量提示和跳转 Contemplate 的弱入口                                               |
| 正常态 | 有双向链接                | 分区展示“引用了谁”（出链）和“被谁引用”（入链 / backlinks），每条显示目标 Thought 标题 |

### 3.2 每个核心组件的构成和交互行为

#### Category 树

**构成**

- 根节点 All：始终显示。
- Category 节点：显示名称、Thought 数量、展开折叠图标；有子节点时显示层级。
- 当前节点高亮：选中时显示。
- 节点操作入口：hover、focus 或右键时显示。
- 未分类入口：存在未归类 Thoughts 时显示数量。

**交互行为**

- 单击节点：主内容区切换到该 Category 的浏览态，标题显示完整路径。
- 双击节点名称：进入重命名输入态，确认后原地更新。
- hover 节点：显示轻量操作入口，不改变选中状态。
- 右键节点：打开新建子 Category、重命名、删除、移动等菜单。
- 拖拽节点：调整层级，拖拽中显示插入位置；非法目标给出不可放置反馈。
- 键盘操作：方向键移动焦点，Enter 选中，Space 展开 / 折叠。

#### Thought 卡片

**构成**

- 标题：始终显示；为空时显示正文首句或 Untitled。
- Preview：最多 3 行，超出折叠。
- 类型标签：Idea / Insight，始终显示。
- Category 面包屑：在 All、搜索结果或含后代范围中显示；当前单一 Category 下可弱化。
- Context 数量、双向链接数量：数量大于 0 时高亮，0 时弱化。
- 创建 / 修改时间：作为回忆线索低权重显示。
- 操作入口：hover / focus 时显示删除、修改类型、在 Contemplate 查看。

**交互行为**

- 单击卡片主体：进入 Thought 详情态。
- 双击标题或 Preview：进入详情态并聚焦正文编辑区。
- hover 卡片：显示操作入口，卡片高度不变化。
- 右键卡片：打开轻量菜单。
- 点击 Context 数量：进入详情态并定位右侧 Context 列表。
- 点击双向链接数量：提供在详情内查看列表或跳转 Contemplate。
- 键盘操作：Tab 聚焦卡片，Enter 打开详情，Delete 触发删除流程。

#### 详情正文编辑区

**构成**

- 返回入口：返回原浏览上下文。
- 标题输入：始终显示。
- 类型选择：Idea / Insight，可修改。
- Category 归属选择：显示当前归属，可多选修改。
- Markdown 正文编辑区：主焦点。

**交互行为**

- 输入标题 / 正文：内容在当前编辑区直接更新，不打断输入。
- 修改类型：实时更新，列表返回后卡片标签同步。
- 修改 Category：实时更新归属，返回列表时根据当前 Category 决定是否仍显示该 Thought。
- 点击返回：回到原 Category、筛选条件和滚动位置。

#### Context 卡片

**构成**

- 来源类型：个人经历 / 书籍 / 文章 / 视频 / 他人观点。
- 摘要：默认 50 字以内。
- 记录时间：低权重显示。
- 展开入口：有长内容时显示。
- 操作入口：hover / focus 时显示编辑、删除。

**交互行为**

- 单击 Context：展开或收起完整内容。
- 点击新增：在列表区域进入新增态。
- 编辑 Context：原地编辑，完成后回到摘要态。
- 删除 Context：直接从列表移除。

#### 双向链接列表项

**构成**

- 目标 Thought 标题。
- 链接方向：引用了谁（出链）/ 被谁引用（入链 / backlinks）。
- 跨模块入口：在 Contemplate 中查看。

**交互行为**

- 单击目标 Thought：在 Capture 中打开目标 Thought 详情。
- 点击 Contemplate 入口：跳转 Contemplate 并高亮该节点。
- 出链和入链均只读展示，增删通过修改正文中的 `[[title#id]]` 语法完成，不在列表中提供直接删除入口。

### 3.3 界面变化时用户的感知（过渡意图）

| 过渡场景                 | 过渡意图                                                    | 实现方式                                               |
| ------------------------ | ----------------------------------------------------------- | ------------------------------------------------------ |
| 选择 Category 后列表更新 | 用户感知到自己仍在同一工作台，只是切换了语境                | 左侧选中态先更新，右侧标题路径同步，列表区原地更新     |
| 搜索 / 筛选触发列表更新  | 用户感知到当前 Category 被临时缩小范围，而不是离开 Category | 工具条保留条件标签，列表原地更新，提供一键清除         |
| 点击卡片进入详情         | 用户感知到自己从某张卡片展开到详情，而不是跳到另一个产品    | 主内容区切换为详情态，左侧 Category 保持，返回入口明确 |
| 从详情返回列表           | 用户感知到回到刚才的浏览位置                                | 恢复滚动位置和筛选条件，原卡片短暂高亮                 |
| 新建 Thought 进入详情    | 用户感知到新内容已在当前 Category 下创建，可以直接写        | 立即进入详情态，Category 已填入，光标就位              |
| Context 展开 / 收起      | 用户感知到背景信息在当前 Thought 旁边展开，不打断正文       | 右侧原地展开，正文区域不位移                           |
| 跳转 Contemplate         | 用户感知到从 Capture 的轻量整理进入关系探索模块             | 使用明确的跨模块入口，跳转后高亮当前 Thought 节点      |

## 4. 路径之外会发生什么

### 4.1 数据边界

| 边界场景                              | 处理方式                                                                        |
| ------------------------------------- | ------------------------------------------------------------------------------- |
| 没有任何 Category                     | 左侧保留 All 和未分类入口，提示新建第一个 Category；右侧可直接新建 Thought      |
| 当前 Category 没有 Thought            | 浏览态显示语义空态，说明当前 Category 还没有内容，并提供 `+ Idea` / `+ Insight` |
| 搜索 / 筛选无结果                     | 保留搜索词和筛选条件，提示当前条件无结果，提供清除搜索和重置筛选                |
| Thought 标题为空                      | 卡片使用正文首句或 Untitled 占位；详情态提示可补标题但不阻塞继续编辑            |
| Thought 正文极长                      | 卡片 Preview 固定 3 行；详情态正文区独立滚动，不挤压 Context                    |
| Category 名称极长                     | 左侧节点单行截断，hover 显示完整名称；标题区可换行或使用面包屑折叠              |
| Category 层级极深                     | 左侧保留缩进上限，超过层级使用紧凑缩进；拖拽时仍显示目标父节点                  |
| Category 数量极多                     | 支持树内搜索或虚拟滚动；展开状态按会话保留                                      |
| 当前 Category 下 Thoughts 超过 100 条 | 列表使用虚拟滚动或分段呈现；筛选和搜索优先响应，卡片高度稳定                    |
| Context 数量为 0                      | 右侧显示轻量空态和新增入口，不把空态做成大面积提示                              |
| Context 数量极多                      | Context 区域独立滚动，默认显示摘要列表，可折叠或显示更多                        |
| 双向链接数量极多                      | Capture 只显示摘要列表和入口，引导到 Contemplate 做大范围探索                   |

---

### 4.2 操作边界

| 操作                    | 可逆性判断                 | 处理方式                                                                |
| ----------------------- | -------------------------- | ----------------------------------------------------------------------- |
| 新建 Thought 后立即离开 | 实时可修改                 | 有输入则作为普通 Thought 留在当前 Category；无输入则不进入列表          |
| 编辑标题 / 正文         | 实时可修改                 | 内容直接更新，不弹确认                                                  |
| 修改 Thought 类型       | 实时可修改                 | 直接更新，列表卡片同步                                                  |
| 修改 Thought Category   | 实时可修改但影响列表可见性 | 直接更新；若移出当前 Category，返回列表时提示该 Thought 已移至新位置    |
| 删除单条 Thought        | 中等风险                   | 如果包含 Context / 双向链接，在确认文案中说明影响；确认后从列表移除     |
| 删除 Category           | 不可逆结构操作             | 二次确认，文案说明其下 N 条 Thought 将归入父节点，Category 删除不可撤销 |
| 拖拽调整 Category 层级  | 实时可修改                 | 直接调整层级，Thought 跟随新的 Category 结构                            |
| 删除 Context            | 中等风险                   | 确认后直接删除                                                          |
| 删除双向链接引用        | 轻量操作                   | 从正文中移除对应的 `[[title#id]]` 语法，系统自动更新关联列表            |
| 跳转 Contemplate        | 可返回                     | 明确跨模块跳转，保留 Capture 返回上下文                                 |

---

### 4.3 状态恢复

| 恢复场景                            | 恢复策略                                                                         |
| ----------------------------------- | -------------------------------------------------------------------------------- |
| 从详情关闭回列表                    | 恢复：原 Category 选中状态、原搜索词、原筛选条件、原排序、原滚动位置、原卡片位置 |
| 切换 Category 后返回上一个 Category | 当前会话内恢复：该 Category 的展开状态、筛选条件和滚动位置                       |
| 搜索中打开详情再返回                | 恢复：搜索词、搜索结果、匹配高亮和滚动位置                                       |
| 刷新页面                            | 恢复：最近选中 Category、详情态或浏览态、搜索 / 筛选条件                         |
| 新建 Thought 未完成后重新进入       | 有输入则作为普通 Thought 恢复；无输入则不恢复空内容                              |
| 从 Contemplate 返回 Capture         | 恢复：离开前的 Thought 详情或 Category 列表状态                                  |
| Category 被删除后返回               | 恢复到父 Category；提示原 Category 已删除，其下 Thought 已归入父节点             |

## 5. 怎么验证用户体验是对的

### 障碍 1：热状态下的想法容易在记录流程中丢失

| 验收条件                                                                            | 判断方式     |
| ----------------------------------------------------------------------------------- | ------------ |
| 从点击 `+ Idea` / `+ Insight` 到进入可输入状态不超过 2 步，且不经过弹窗或创建前表单 | 操作步骤计数 |
| 新建 Thought 默认继承当前选中 Category，创建前不要求用户手动选择分类                | 操作回归验证 |
| 新建详情态进入后，光标自动落在标题或正文首个输入位置                                | 界面量测     |
| 创建后立即离开，已输入内容和 Category 归属可以恢复                                  | 操作回归验证 |

### 障碍 2：回到某个领域时，很难快速想起自己已经知道什么

| 验收条件                                                                                                | 判断方式     |
| ------------------------------------------------------------------------------------------------------- | ------------ |
| Category 树当前选中节点和主内容标题共同显示用户所在 Category 路径                                       | 界面量测     |
| Thought 卡片单屏至少能展示 6-8 条，并包含标题、3 行 Preview、类型标签、Context / 双向链接数量和时间线索 | 界面量测     |
| 用户关闭详情后，原 Category、搜索词、筛选条件、排序和滚动位置全部恢复                                   | 操作回归验证 |
| 搜索和筛选结果始终保留当前 Category 语境，并能一键清除条件                                              | 操作回归验证 |
| 当前 Category 无内容或无结果时，界面提供明确下一步，不出现空白列表                                      | 异常场景验证 |

### 障碍 3：旧 Thought 脱离来源后会变成无法判断的口号

| 验收条件                                                                     | 判断方式     |
| ---------------------------------------------------------------------------- | ------------ |
| Thought 详情态中正文和 Context 在同一屏可见，不需要切换 tab 才能看到 Context | 界面量测     |
| 每条 Context 默认展示摘要、来源类型和记录时间，用户不展开也能判断来源性质    | 界面量测     |
| Context 展开时正文区域不位移，用户仍能保持当前 Thought 的阅读参照            | 操作回归验证 |
| 新增 Context 后，该 Context 立即归属当前 Thought 并出现在右侧列表中          | 数据验证     |

### 通用验收条件

| 验收条件                                                                      | 判断方式     |
| ----------------------------------------------------------------------------- | ------------ |
| 删除 Category 前必须出现二次确认，并说明其下 Thought 将归入哪个父节点         | 操作回归验证 |
| 删除 Context 后，列表立即反映删除结果                                         | 操作回归验证 |
| 正文中 `[[title#id]]` 引用增删后，Capture 链接列表和 Contemplate 图谱呈现一致 | 端到端测试   |

## 自检清单

**第 1 节**

- [ ] 每个障碍都有代价描述。
- [ ] IN / OUT 使用用户目标语言，而不是功能名堆叠。
- [ ] 每条约束都有来源和对设计的影响。

**第 2 节**

- [ ] 信息架构区分了浏览态和详情态。
- [ ] 三条 Journey 分别对应三个用户障碍。
- [ ] 每条 Journey 都写了注意力焦点和异常承接。

**第 3 节**

- [ ] 每个用户可停留位置都有空态、正常态和必要的交互子状态。
- [ ] 核心组件的构成说明了显示条件。
- [ ] 过渡意图描述的是用户感知，不只是动效。

**第 4 节**

- [ ] 数据边界覆盖空、极长、极多。
- [ ] 删除和创建后离开都有明确策略。
- [ ] 状态恢复逐项说明恢复哪些维度。

**第 5 节**

- [ ] 每条验收条件都能回答是 / 否。
- [ ] 每个障碍至少有 3 条验收条件。
- [ ] 异常场景进入验收条件，而不只验证 happy path。
