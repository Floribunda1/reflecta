# 常驻实时仪表盘（首页概览）模块调研报告

## 1. 背景介绍

本报告调研的模块是：**个人知识 + AI 对话类应用中的常驻实时仪表盘（首页概览页）**——即打开应用就能看到当前状态的看板页面，不是周期性汇总报告（如 Spotify Wrapped 式年度回顾）。

**调研目的**：Reflecta 计划把现有页内统计（CaptureStats）升级为一个独立的 Dashboard 模块作为首页，并拆成两块统计：①**沉淀资产**（理解、画布、上下文等成果）②**过程资产/使用痕迹**（对话、活跃行为）。用户明确强调：**这不是"一段时间给你呈现一次"的周期性 report，而是像电商产品里的仪表盘那样，可以一直在里面看到实时的内容/状态**。本报告调研行业里"常驻实时仪表盘"这一页面形态的常见做法，如实呈现行业现状与规律，供用户自行判断如何在 Reflecta 落地。

**客观信息骨架**：

- 调研模块：常驻实时仪表盘 / 首页概览（real-time always-on dashboard）
- 覆盖产品：Shopify、Zonos、Stripe、WooCommerce、SellerMagnet、Amazon Seller Central（电商/商家后台）；知乎创作中心、微信公众号平台（中文内容创作后台）；Flomo、Readwise、Daylio、Apple Screen Time、Obsidian/Logseq 插件、GitHub（个人工具统计）；RescueTime（时间追踪）；Linear（团队工作台）；Notion、Heptabase、ChatGPT/Claude、语雀（复用 2026-08-16 既有报告的事实）
- 调研时间：2026-08-17
- 信息来源：官方帮助中心/文档/Changelog 为主（Shopify、Stripe、WooCommerce、Zonos、RescueTime、Apple、Daylio、Readwise、Linear、Notion、GitHub、微信公众平台腾讯客服）；个别产品（知乎创作中心数据细节）仅有第三方教程，已标注来源类型；Flomo/语雀/Day One/Apple Journal/ChatGPT/Claude/Obsidian 插件/GitHub/Heptabase 等事实直接复用昨日报告 `usage-stats-benchmark.md`（2026-08-16）。

**理解假设**：本报告按"常驻实时仪表盘（非周期性报告）"理解该模块；若实际指的是周期性 Wrapped 式报告（或纯统计模块而非首页级看板），请指出，将重新选品调研。

**用户产品自身的约束背景**（来自 Reflecta 项目文档，非调研结论）：value-proposition.md 明确「把知识边界做成抽象分数或仪表盘」属于 Never 方向，主张"用户需要看见具体理解、上下文、关系和空白，而不是泛化评分"；feature-set-guide.md 在图谱形态下把「数量统计 dashboard」列为 Not Now；「用输入量、打卡、收藏量作为核心激励」也是 Never。这些是用户既有决策，作为判断背景供参考，本报告不据此替用户下结论。

## 2. 调研范围与产品

### 形态空间

「常驻实时仪表盘」在同一模块下有四种主流解法形态：

| 形态                    | 说明                                                                   | 代表产品                                                                                         |
| ----------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| A. 商家/工作台实时看板  | 电商、支付、SaaS 管理后台的第一屏：实时指标 + 历史趋势 + 待办/通知聚合 | Shopify、Zonos、Stripe、WooCommerce、SellerMagnet、Amazon Seller Central                         |
| B. 中文内容创作后台     | 面向个人创作者/运营者的常驻数据后台，"内容资产 + 效果数据"分离展示     | 知乎创作中心、微信公众平台数据分析                                                               |
| C. 个人工具内嵌统计面板 | 个人知识/日记/复习/时间类应用里的统计页或侧栏常驻面板                  | Flomo、Readwise、Daylio、RescueTime、Apple Screen Time、Obsidian/Logseq 插件、GitHub（个人主页） |
| D. 工作台动态/健康概览  | 团队工具里以"更新流 + 健康指标"为主的概览，数字不是主角                | Linear（Pulse / Monitor）、Notion（用户自建 Dashboard view）                                     |

## 3. 调研结果

### 3.1 调研总结论

**结论一：常驻仪表盘普遍采用"实时/当天层 + 历史/趋势层"的两段结构，且数字几乎都可以点击下钻。**

- Zonos：Home 顶部一个 **live today bar**（当天实时收入/订单/均价/Top 国家，标明"Today as of 10:30 AM"数据捕获时间），下方历史 KPI 卡 + 趋势图（支持对比期、粒度控制、刷新时间戳）。
- Shopify：Home 页 = 实时指标（sales/traffic，默认近 30 天）+ 待处理任务 + 增长建议 + 最近销售活动；Analytics overview 的指标卡可加/删/重排/分节，**点卡片标题直接跳到对应报表**。
- SellerMagnet：Dashboard Home = 左上角 Today's Snapshot 实时卡 + 长期盈利趋势区。
- 微信公众平台：图文分析页顶部有"昨日关键指标"模块，**与前一天、7 天前、30 天前对比**，体现为日/周/月的百分比变化，下方可选 7/14/30 天趋势图。
- Amazon Seller Central：Account Health = 当前账户健康状态（是否达标、是否有风险、哪些事项需处理）——健康型仪表盘代表。

这是电商/运营型看板的行业共识：**"今天怎么样"（实时层）与"最近怎么样"（趋势层）并置，每一个数字都能点进去看明细**。

**结论二：个人知识 + 对话类产品里，没有"电商式首页 dashboard"的成熟先例；最接近的是 Obsidian 插件生态，且插件内部已经分化出三种统计语义。**

- 直接竞品（Flomo/Readwise/Daylio/Obsidian/Due）里，统计都以**独立统计页或侧栏面板**存在，不是首页第一屏；没有一家把"资产 + 使用痕迹"聚合进一个首页看板（与昨日报告结论二"跨实体统一统计是行业空白"互相印证）。
- Obsidian 插件生态是"知识库 dashboard"最完整的集合，且分化明显：
  - **数量统计**：obsidian-data-analysis（GitHub 式热力图[创建+修改] + 卡片[总数/总字数/streak/日均]+趋势）、obsidian-dashboard（总字数/笔记数/今日/7 日均 + 365 天热力图 + 12 个月柱状图 + 30 天日历 + 星期分布环形图）。
  - **结构/质量统计**：Vault Full Statistics（counts + ratios + trends；**own vs source split、dangling sources、tangles、inbox queue**——直接呈现"知识库里哪些是悬空的、哪些纠缠不清、哪些还没整理"）。
  - **参与度/使用统计**：ord-dashboard（total notes/views/edits/active notes——统计"哪些笔记被看/被改"）；vault-activity（创建 + 修订活动，回答"你是否在回看和维护"）。
- 这说明"仪表盘放什么是产品决策"：纯数量卡、结构质量状态、使用参与度，是三套不同语义，插件生态把它们做成了不同插件。

**结论三：健康的/状态的仪表盘（而非纯数量）是有明确先例的形态，且与"看见边界与空白"的价值主张有天然呼应。**

- Amazon Account Health（达标/风险/需关注事项）、Linear 的 health indicator（项目/计划的高层状态信号）、Obsidian Vault Full Statistics 的 dangling/tangles/inbox（结构质量），都是"**不是给你更多数字，而是告诉你现在的状态是否需要行动**"的呈现。
- 这与知识管理里"哪些理解缺上下文、哪些是孤岛、哪些还没整理"是同一类问题——但 Reflecta 是否采用、如何采用，是产品决策。

**结论四：中文内容创作后台（知乎/公众号）是"内容资产 + 效果数据"分离展示的天然近邻，且用户对"实时/当日"有真实诉求。**

- 知乎创作中心：数据概览（阅读/赞同/评论/收藏/关注增长 = 当日可见的核心互动指标）+ 创作等级（综合评分）+ 单篇深度分析（流量来源/读者分布/平均阅读时长）。回答数据（内容类型）分别计数。
- 微信公众平台：用户分析 + 图文分析两大模块分离；图文分析 = 昨日关键指标（与 7/30 天前对比）+ 趋势图 + 图文详解（读者属性）。
- 第三方工具（壹伴助手、知乎数据监控中心）做的正是官方缺的部分：**在后台首页直接显示当日的取关率/打开率/阅读完成度看板**、以及知乎每 10 分钟的数据增长趋势——说明创作者对"打开首页即看到当天状态"有明确需求，官方第一屏常不满足。

**研究见解（基于上述事实）**：行业现状可以概括为"**电商后台看板 = 实时层 + 趋势层 + 可钻取 + 待办聚合；个人知识工具 = 独立统计面板且语义分裂（数量/质量/参与度）；健康型仪表盘是第三条路；中文创作后台验证了'内容资产与效果数据分开看'的心智**"。Reflecta 想做的"首页 Dashboard + 两块（沉淀资产 / 过程资产）"没有现成同品类先例可抄，但每个构成元素（实时层/趋势层/可钻取/健康状态/资产-效果分离）都有成熟参照。如何取舍是产品决策，本报告不替用户作答。

### 3.2 产品形态基础功能

#### 核心能力

**能力 1：实时/当天状态层（live today bar）**

_能力解析_：回答"现在/今天怎么样"——这是常驻仪表盘与周期性报告的根本区别。电商场景有真实时需求（订单/收入是分钟级变量）；个人工具场景的"实时感"更多是"今天创建了什么、聊了什么"。分歧在：是否单独强调当天（Zonos 有专门 bar），还是默认 30 天（Shopify），还是只给昨日（公众号）。数据刷新方式也有分歧（Zonos 显示捕获时间 + 手动刷新；Shopify 约 1 分钟延迟）。

_各家做法_：

- Zonos：Home 顶部 live today bar——当天收入/订单数/均价卡/价格询价数/Top 目的地国家（带旗帜与单量），标注"Today as of 10:30 AM"，随新数据持续更新。
- SellerMagnet：Dashboard Home 左上角 Today's Snapshot 实时卡。
- Shopify：Home 指标默认展示最近 30 天（sales/traffic/orders/conversion rate），但实时性和"今天"未被单独强调；另设 Live metrics（traffic/reach/orders/revenue 实时）作为独立能力。
- 微信公众号：图文分析顶部"昨日关键指标"模块——不强调当天实时，而是前一天 + 与 7/30 天前的对比。
- 知乎创作中心：数据概览 = 核心互动指标一目了然（创建后台首页即当日状态），但当天实时增长只有第三方工具补（minute 级）。
- Apple Screen Time：每天会出"屏幕使用报告"通知，进入后可按日/周查看。

**能力 2：历史趋势层与周期对比**

_能力解析_：把"最近怎么样"可视化，让用户判断方向。分歧在：对比基准（与上一期/7 天前/30 天前/去年同比）、粒度（日/周/月/自定义区间）、以及是 KPI 卡数字还是趋势图。

_各家做法_：

- Zonos：历史 KPI 卡（总值 + 对比期百分比变化 + 方向箭头）+ inline 趋势图（当期 vs 对比期并置）+ 粒度控制。
- 微信公众号：图文分析 = 昨日关键指标模块（与前天/7 天前/30 天前对比，日/周/月百分比）+ 趋势图（7/14/30 天可切）。
- Shopify：指标卡组 + Orders over time 图表；日期范围自定义 + 跨期对比。
- Daylio：统计页随 interval 切换（本期 vs 前期重复次数对比），mood 色码对应。
- Obsidian 插件（obsidian-data-analysis / obsidian-dashboard）：12 个月创作量柱状图、30 天日历、星期分布环形图。
- RescueTime：Dashboard 可切 daily/weekly/monthly/yearly，另有 all time / work hours 开关。

**能力 3：可钻取明细（数字 → 具体内容）**

_能力解析_：常驻看板的数字如果只是数字，就会变成"泛化仪表盘"；能点进具体明细的看板才能服务判断与行动。分歧在：钻取深度（一层报表页 vs 直达单条内容）与钻取方式（点卡片标题/点数字/点热力图格子）。

_各家做法_：

- Shopify：点指标卡标题直接进入对应报表页；Home 的待办直链到执行页。
- Zonos：KPI 卡点击打开 breakdown 页（Revenue breakdown / Orders and quotes breakdown）；Top SKU 行可展开看细节。
- Stripe：活动分解 = summary totals → transaction details 的逐层下钻。
- 知乎：数据概览的每篇内容可点进"数据"按钮看单篇深度分析（流量来源拆解、读者分布、平均阅读时长）。
- Flomo（复用昨日）：**点热力图格子直接筛选到当天记录**。
- Obsidian 插件（vault-pulse / vault-activity）：点热力图某天列出当天动过的文件。

**能力 4：健康/状态信号（非纯数量的看板）**

_能力解析_：不回答"有多少"，回答"现在状态是否健康、哪里需要行动"。这是电商后台（账户健康）与团队工具（项目健康）里成熟的形态，与纯数量统计是不同的设计哲学。

_各家做法_：

- Amazon Seller Central：Account Health 仪表盘 = 账户是否达标、是否有风险、具体哪些事项需处理（对照绩效目标），高风险直接给出行动项。
- Linear：项目/计划更新附带 health indicator（高层的当前状态信号）+ 文本说明（状态/挑战/下一步）。
- Obsidian Vault Full Statistics：结构质量维度——own vs source 拆分、dangling sources（悬空链接）、tangles（纠缠）、inbox（未整理待办区）。
- 知乎：创作等级 = 平台对账号的持续价值综合评分，分项构成暴露平台对不同互动行为的加权（偏评分体系，与"看状态"不同，注意区分）。

**能力 5：按实体/类型分组的计数**

_能力解析_：把不同内容类型放进同一套看板分别计数。电商看板本质是多实体（订单/商品/客户/渠道）；中文创作后台按内容类型分列。这是"沉淀资产"块最直接的参照。

_各家做法_：

- 知乎创作中心：数据概览 + 回答数据、文章数据、专栏数据（**按内容类型分列计数**）。
- 微信公众号：用户分析（新增/净增/累计/属性）与图文分析（阅读/分享/完读）两大模块分离。
- 语雀（复用昨日）：小记/文档/表格/画板/数据表分别计数（但为配额语义、每月清零）。
- Obsidian（Vault Full Statistics）：notes/files/attachments/links/tags 分列计数。

**能力 6：待办/通知/更新流聚合（首页不只是数字）**

_能力解析_：电商/团队 Home 页往往不只是指标，还聚合"需要你处理的事"与"最近的动态"。这让看板从"被动查阅"变成"一天的开场"。分歧在：任务驱动（Shopify/WooCommerce）vs 动态流（Linear Pulse）vs 通知聚合（Stripe）。

_各家做法_：

- Shopify Home：待处理订单（需 capture 的未支付单）、每日任务、增长建议、最近销售活动。
- WooCommerce Home：最有用的提醒/提示 + 快速访问 + 新用户任务清单（引导开通）。
- Stripe Home：重要通知聚合（未解决的争议、身份验证等）。
- Linear Pulse：个性化更新 feed（"For me"）+ Recent/Popular，AI 可生成上周更新摘要（周期补充，非常驻数字）。
- RescueTime Assistant：常驻侧边显示当天进度、Focus Sessions 快捷入口（把"看数据"变成"继续动作"）。

#### 基本用户体验功能

口径声明：以下"已确认具备"以官方来源为准（帮助中心/文档/Changelog）；仅第三方来源的标注"未检索到官方确认"。

**分组 1：展示结构**

### 3.3 不同产品的区别

#### 3.3.1 产品定位画像（逐产品）

**Shopify**

1. 定位与面向客户：面向独立站商家的全功能电商管理后台（帮助中心明确"central hub for managing your online store"）。
2. 差异化场景：Home 是每日开场（实时指标 + 待办任务 + 建议），Analytics overview 是可定制指标卡组——"开箱即用的看板 + 可自定义的报告体系"双轨。
3. 核心差异化与护城河：指标卡可加/删/重排/分节/调整大小是少见的自定义能力；点卡片标题跳报表形成"看板 → 报表"的链路（官方文档明确）。

**Zonos**

1. 定位与面向客户：跨境电商技术服务商（关税/跨境履行），Dashboard Home 面向商家。
2. 差异化场景：文档对 Home 的描述最完整——live today bar + 历史分析 + 三组过滤，是"实时层 + 历史层"双层结构的教科书样例。
3. 核心差异化与护城河：把"今天"单独拎成一个 bar（含捕获时间戳），历史层 KPI 卡带对比期百分比与方向箭头、可点击钻取、Top 排行/可展开 SKU——信息架构完整、颗粒分明。

**Stripe**

1. 定位与面向客户：面向开发与业务团队的支付基础设施，Dashboard 是其日常操作台。
2. 差异化场景：Home = analytics + charts + 重要通知（争议/验证）；活动分解支持 summary totals → transaction details 逐层下钻（官方明确"from summary totals to individual transaction details"）。
3. 核心差异化与护城河：钻取体系是"金额汇总 → 单笔交易"的标准示范；通知聚合（未解决事项）让首页兼作"待办台"。

**WooCommerce Home**

1. 定位与面向客户：WordPress 生态的电商插件，Home 是其后台首页。
2. 差异化场景：性能指标 + 建议/提示 + 快速访问 + 新用户任务清单并存——"新手引导与运营看板混排"的典型。
3. 核心差异化与护城河：新用户第一屏是任务清单而非数据，成熟用户看指标——同一 Home 按用户阶段切换内容（官方文档明确）。

**SellerMagnet**

1. 定位与面向客户：面向多平台（1-20 个 marketplace）卖家的 Amazon 生意聚合工具。
2. 差异化场景：Dashboard Home 组织为多个 section，Today's Snapshot 实时卡在最左。
3. 核心差异化与护城河：把"今天的实时脉搏"和"长期盈利趋势"放同一页，是电商看板"实时+长期"并置的典型（官方文档明确分区布局）。

**Amazon Seller Central**

1. 定位与面向客户：Amazon 官方卖家后台。
2. 差异化场景：Account Health 是独立的"健康状态"仪表盘——对照绩效目标检查是否达标、是否有风险、哪些事项需处理。
3. 核心差异化与护城河：健康型（compliance 导向）仪表盘的代表：不是展示数量，而是给出"状态 + 风险 + 行动项"，高风险直接引导处理。

**知乎创作中心**

1. 定位与面向客户：面向知乎创作者（回答/文章/专栏作者）的数据后台。
2. 差异化场景：数据概览（阅读/赞同/评论/收藏/关注增长）+ 创作等级（综合评分）+ 单篇深度分析（流量来源/读者分布/平均阅读时长）。
3. 核心差异化与护城河：内容资产按类型分列计数（回答/文章/专栏）；创作等级是加权评分体系（多个互动维度计分，"近 7 日明细"可查）；当天实时数据官方缺、第三方工具补齐（每 10 分钟增长趋势）。

**微信公众平台**

1. 定位与面向客户：面向公众号运营者（个人/企业）的内容后台。
2. 差异化场景：用户分析 + 图文分析两大模块分离；图文分析 = 昨日关键指标（与 7/30 天前对比）+ 趋势图（7/14/30 天）+ 图文详解（读者属性）。
3. 核心差异化与护城河：官方对"对比维度"做得细（日/周/月百分比变化）；但首页无数据看板，由第三方插件（壹伴）在首页加当日看板补齐——官方克制、生态补齐的又一例。

**RescueTime**

1. 定位与面向客户：面向个人与团队的自动时间追踪工具。
2. 差异化场景：常驻 Dashboard（总时间 + Productivity Pulse 分数 + 时间去向分类，可切 day/week/month/year）+ 周期性 weekly email 双轨；Assistant 实时追踪当天进度。
3. 核心差异化与护城河：Pulse 是把多维时间数据压成一个分数（"生产力"）的代表——与面对"把使用痕迹抽象成分数"的产品哲学（value-proposition Never 清单）形成对照的案例。

**Readwise**

1. 定位与面向客户：面向主动复习的读者（高亮重读、每日回顾）。
2. 差异化场景：stats 页 = GitHub 式活动图 + 最长/当前 streak + **全球 streak 排名**；每日复习完成情况 + 补卡 recover。
3. 核心差异化与护城河：全球排名（Global streak rank）是少见的社交化激励——把个人习惯统计变成可比拼的排行榜（用户长评确认其激励效果），也是"打卡激励"走向极致的案例。

**Daylio**

1. 定位与面向客户：情绪/习惯记录应用（mood + activity 两键记录）。
2. 差异化场景：stats 页 = 周期切换 + 本期 vs 前期对比 + mood 色彩编码 + 活动频率 + **Influence on Mood**（活动与情绪的相关性分析）。
3. 核心差异化与护城河：相关性分析（哪些活动影响心情）是"统计数据 → 提供洞察"的进阶做法；Advanced Stats 是 premium 付费点（免费/付费在统计深度上分层）。

**Apple Screen Time**

1. 定位与面向客户：系统级使用时间管理（iOS/macOS 内置）。
2. 差异化场景：每日/每周使用报告（app 时间、通知数、拿起次数），可切换统计时段、分类、设备。
3. 核心差异化与护城河：系统级数据源（不靠用户手记）；注意力管理定位使统计服务于限额与提醒，而非展示量。

**Obsidian / Logseq 插件生态**

1. 定位与面向客户：本地优先 Markdown 知识库，统计由社区插件承担。
2. 差异化场景：插件分化出三套语义——数量统计（obsidian-data-analysis、obsidian-dashboard）、结构/质量统计（Vault Full Statistics 的 dangling/tangles/inbox）、参与度统计（ord-dashboard 的 views/edits）。
3. 核心差异化与护城河：数量/质量/参与度三种统计被做成不同插件的事实，说明"统计仪式感"本身是知识工作者的真实需求，且"看板显示什么"是各有取舍的设计决策。

**GitHub**

1. 定位与面向客户：代码托管与协作平台，个人主页贡献图是"身份墙"。
2. 差异化场景：365 天贡献图常驻个人主页，官方文档明确定义"什么算贡献"（严格口径）。
3. 核心差异化与护城河：贡献图同时承担身份展示与自我激励，是常驻实时个人数据可视化的范式源头（复用昨日报告）。

**Linear**

1. 定位与面向客户：面向产品团队的 issue 跟踪/项目管理工具。
2. 差异化场景：Monitor/Pulse = 健康指标 + 个性化更新 feed（"For me" + Recent/Popular）；更新 = 健康指示器 + 富文本状态描述；AI 可生成上周更新摘要。
3. 核心差异化与护城河：项目健康用 health indicator 表达（高层信号 + 文本详情），数字让位于"状态 + 叙事"；Pulse feed 是按关注度的动态流而非指标墙。

#### 3.3.2 差异化功能对比（按差异维度）

**维度 1：看板的时间分层——实时层与趋势层怎么分**

| 产品                      | 分层方式                                                                  |
| ------------------------- | ------------------------------------------------------------------------- |
| Zonos                     | 显式双层：live today bar（实时）+ historical analytics（可调范围/对比期） |
| SellerMagnet              | Today's Snapshot 卡 + 长期趋势区（同页分区）                              |
| Shopify                   | Home（30 天默认 + 实时）+ Analytics（自定义日期）双页                     |
| 微信公众号                | 昨日模块（对 7/30 天前）+ 趋势图（7/14/30 天）在**同一页上下**            |
| 知乎                      | 数据概览（当日核心指标）为第一屏                                          |
| Readwise / Daylio / Flomo | 无实时层，周期视图为主                                                    |

值得展开——**公众号的"昨日对比模块"**：这是"不强调实时、强调对比"的典型。位置在图文分析页顶部，展示**昨天**的阅读/转发/分享与**前天、7 天前、30 天前**的百分比变化（日/周/月三种口径），下方再给 7/14/30 天趋势图。它的逻辑是：对内容运营者，"今天"的绝对值意义不大（文章传播是滞后变量），**相对对比**才是判断信号——这与 Shopify 强调实时形成鲜明对照，也提示"实时层该放什么"取决于业务变量的时效性。

**维度 2：看板内容是数量、质量状态，还是参与度**

| 类别          | 产品                                                                 | 呈现                                                       |
| ------------- | -------------------------------------------------------------------- | ---------------------------------------------------------- |
| 纯数量        | Shopify/Zonos/Stripe/RescueTime/Obsidian 数量插件                    | 指标卡、趋势图、KPI 对比                                   |
| 质量/结构状态 | Amazon Account Health、Linear health、Obsidian Vault Full Statistics | 达标/风险/行动项、health indicator、dangling/tangles/inbox |
| 参与度        | ord-dashboard、vault-activity、RescueTime（按 app 分类）             | views/edits/active、创建+修订、时间去向                    |
| 加权评分      | 知乎创作等级、RescueTime Pulse                                       | 多个维度合成一个分数                                       |

值得展开——**Obsidian Vault Full Statistics 的质量维度**：它把统计从"多少"推进到"结构是否健康"——own vs source 拆分（自己写的 vs 引用外部）、dangling sources（悬空链接：指向不存在笔记的链接）、tangles（互相纠缠的高互链簇）、inbox（未整理的收件区）。这些问题对知识工作者是**可行动的信号**（去补链接、去拆簇、去整理 inbox），而"总数 500 篇"不是行动信号。对照 value-proposition 的"看见边界与空白"，这是距离最近的一个既有做法——但它把"缺口"做成插件统计，从未有人做成首页看板。

**维度 3：激励设计——打卡 vs 排名 vs 中性**

| 产品                                       | 激励形态                                       |
| ------------------------------------------ | ---------------------------------------------- |
| Readwise                                   | streak + recover 补卡 + **全球排名**（社交化） |
| Daylio / Flomo / Obsidian 插件             | streak/连续记录（习惯养成）                    |
| 知乎创作等级                               | 平台加权评分（解锁权益驱动）                   |
| RescueTime                                 | Productivity Pulse 分数（自我衡量）            |
| Stripe / Shopify / Amazon / Linear / Apple | 无激励，中性呈现或行动导向                     |

值得展开——**Readwise 的全球 streak 排名**：stats 页除了活动图，还有 longest/current streak 与 global streak rank（你在所有用户里的连续复习天数排名）。用户长评（Medium, 300 天使用回顾）明确说"全球排名不是重要因素，但确实是激励来源"。这是"打卡激励"的最激进形态——把个人习惯变成可比较的竞争。注意它与"连续记录"的差别：streak 是自我比较，全球排名是社会比较；两者在"是否会推动无效行为"上的风险不同。

**维度 4：看板载体——首页第一屏 vs 独立页 vs 侧栏**

| 载体         | 产品                                               | 特点                            |
| ------------ | -------------------------------------------------- | ------------------------------- |
| 首页第一屏   | Shopify/Zonos/WooCommerce/SellerMagnet/知乎/公众号 | 打开即见，通常伴随待办/通知聚合 |
| 独立统计页   | Readwise/Daylio/RescueTime/Obsidian 插件/GitHub    | 主动进入，研究性回看            |
| 侧栏常驻     | Flomo                                              | 与主内容同屏，低打扰            |
| 插件侧边面板 | Obsidian 部分插件                                  | 常驻但可关                      |

值得展开——**电商 Home 的"待办聚合"**：Shopify Home 不只是数据——它把需要你处理的事（未支付订单、任务）也放第一屏；WooCommerce 新用户第一屏是任务清单；Stripe Home 聚合未解决争议。这说明电商看板首页的语义是"**今天需要看什么、做什么**"，数据与待办在同一个信息架构里。这对"个人知识首页"是重要参照：首页可以是"沉淀状态 + 需要你继续整理的入口"（如孤岛/缺上下文的理解的行动入口），而不是一张纯数字墙。

**维度 5：多实体计数——跨类型分列 vs 单实体聚合**

| 产品                  | 对象                                       |
| --------------------- | ------------------------------------------ |
| 知乎                  | 回答/文章/专栏分列                         |
| 公众号                | 用户/图文两大模块                          |
| 语雀（复用昨日）      | 小记/文档/表格/画板/数据表分列（配额语义） |
| Shopify               | 订单/商品/客户/渠道（本质多实体）          |
| 电商实时单            | 常见多实体并存（销售额+订单数+均价+国家）  |
| Flomo/Readwise/Daylio | 单实体（memo/复习/记录）                   |

值得展开——**Zonos live today bar 的多项指标**：实时层同时放收入、订单数、均价、询价数、Top 国家五个不同实体的指标，每个都是不同"资产"的当日状态；这实际上已经是"多实体并置"的实时层，只是所有实体同属"交易"一个业务。对 Reflecta 的启发维度（不替用户决定）：如果"沉淀资产"块要跨理解/画布/上下文，Zonos 的 live bar 说明"多实体实时并置"在电商行业是被验证的 layout——但电商的所有实体共享同一业务语义（卖货），Reflecta 的实体是否有统一语义（沉淀），是用户要自己想清楚的。

### 3.4 信息缺口

1. **知乎创作中心的官方帮助中心说明**：数据概览的确切指标与布局细节仅检索到第三方教程（jizhil.com），未检索到知乎官方帮助中心对"数据概览"的专门说明。
2. **微信公众号后台的首页形态**：官方后台"数据分析"模块有官方说明（腾讯客服），但"后台首页是否有数据看板"官方未声明；壹伴助手首页看板是第三方补充，非官方。
3. **Shopify 帮助页内容细节**：help.shopify.com 直接抓取返回 403，Analytics overview 的完整字段（卡片类型列表、insights 生成规则）依赖搜索摘要，未逐字段核对原文。
4. **RescueTime Pulse 分数的计算口径**：官方说明分数存在且分四档，但合成算法的具体权重未公开（官方不提供）。
5. **Heptabase 是否有统计**：2026-08-16 调研未检索到官方统计文档（复用昨日缺口；本次未更新检索）。
6. **Obsidian 插件质量**：Vault Full Statistics 的 dangling/tangles 等指标均来自插件 README（第三方/社区），非官方；Obsidian/Logseq 官方依旧无统计（复用昨日结论）。

## 4. 结论

**覆盖情况**：16 个产品（含复用昨日报告的 Flomo/语雀/ChatGPT/Claude/Notion/Heptabase/Apple Journal 等事实）、4 种形态。商家/工作台实时看板（电商/支付/运营）形态最成熟，"实时层 + 趋势层 + 钻取 + 待办聚合"是共识结构；中文创作后台（知乎/公众号）验证了"内容资产 + 效果数据"分离展示的心智；个人知识工具（Flomo/Readwise/Daylio/Obsidian 插件）的统计以独立页/侧栏为主、无首页看板先例；团队工具（Linear）以健康指标 + 更新流为主、数字让位。

**一致与分歧**：

- 高度一致：常驻看板 = 数字可钻取（8/16 家）；时间范围切换（7/16）与对比期（4/16）是标配；"今天/实时"与"历史趋势"分层的两段结构在电商/运营后台高度收敛。
- 一致缺失：个人知识 + 对话产品无"电商式首页看板"先例（Obsidian 插件最接近但无页面 IA）；对话侧只有回顾 + 用量（复用昨日结论）。
- 分歧点：看板内容是纯数量还是健康/结构状态（Amazon/Linear/Vault Full Statistics 是第三条路）；激励设计（streak/全球排名/评分 vs 中性呈现）；看板载体（首页第一屏 vs 独立页 vs 侧栏）；是否需要待办/动态聚合（Shopify 有、Flomo 无）。
- 空白：跨实体（沉淀资产 + 使用痕迹）统一首页看板，检索产品中无一实现（复用昨日结论二：跨实体统计是行业空白，本次进一步确认"做成首页"也是空白）。

**不延伸**：本报告只汇总行业事实与规律，不对 Reflecta 的首页 Dashboard"应该做成什么样"给出建议；如何结合既有产品约束（value-proposition 的 Never 清单、feature-set 的 Not Now）做取舍，由用户自行决策。
