## 1. 产品范围

Domain Workspace 是 PMF MVP 的主页面。它让用户在一个领域语境里查看、创建、编辑和连接个人理解。

MVP 页面结构：

```text
Domain Navigation | Understanding Index | Understanding Document
```

MVP 支持：

- 选择领域。
- 查看当前领域下的理解列表。
- 新建空理解。
- 编辑理解标题和正文。
- 添加、查看、编辑、删除来源。
- 查看和调整理解所属领域。
- 通过正文双链建立理解关系。
- 查看当前理解引用了谁，以及谁引用了当前理解。
- 允许理解暂时独立存在。

MVP 不做：

- AI 自动提炼理解。
- AI 自动构建关系网。
- 手动添加关系。
- 手动删除关系。
- 关系管理后台。
- 来源管理后台。
- 草稿状态。
- dirty 状态。
- 网络错误处理。
- 显式保存流程。
- 复杂模板系统。
- 掌握度评分。
- 自动领域总结。

## 2. 核心对象

### 2.1 Domain

领域是用户回看理解的语境。

字段：

- `id`
- `name`
- `parentId`

规则：

- `parentId` 用于表达领域层级。
- Domain 不维护 `children` 字段；子领域由查询 `parentId` 得到。
- 一个理解可以属于多个领域。
- 用户从某个领域中新建理解时，默认归属当前领域。

### 2.2 Understanding

理解是用户沉淀的核心内容，不是资料、摘录或任务。

字段：

- `id`
- `title`
- `body`
- `domainIds`
- `createdAt`
- `updatedAt`

规则：

- Understanding 不维护 `sourceIds`。
- 来源通过 `Source.understandingId` 反查。
- `title` 可以为空。
- `body` 可以为空。
- 新建理解时立即创建一条空 Understanding。
- 理解可以没有来源。
- 理解可以没有关系。
- 理解可以同时属于多个领域。

### 2.3 Source

来源解释一条理解从哪里长出来。

字段：

- `id`
- `understandingId`
- `type`
- `name`
- `content`
- `createdAt`
- `updatedAt`

规则：

- 来源必须依附于某条理解。
- 来源不是一级知识节点。
- Source 不维护 `trigger` 字段。
- 来源可以很长，默认只在 Document 里展示摘要。

### 2.4 Relation

关系表示正文双链解析出来的理解连接。

字段：

- `id`
- `fromUnderstandingId`
- `toUnderstandingId`
- `createdAt`
- `updatedAt`

规则：

- Relation 只能从 Understanding 正文里的双链解析产生。
- 用户不能在关系面板里手动添加 relation。
- 用户不能在关系面板里手动删除 relation。
- 删除关系的方式是编辑正文，移除对应双链。
- 同一组 `fromUnderstandingId + toUnderstandingId` 不重复建关系。
- incoming relation 由其他理解正文里的双链派生。
- 系统不根据标题相似、来源相似、同领域等条件自动建关系。

## 3. 页面状态

### 3.1 领域回看

用户选中某个领域后，页面展示：

- Domain Navigation。
- 当前领域的 Understanding Index。
- 当前选中理解的 Understanding Document。

规则：

- 如果当前领域有理解，默认选中最近更新或最近选中的理解。
- 如果当前领域没有理解，Index 展示空状态，Document 展示新建入口。
- 切换领域不需要保存确认。

### 3.2 理解编辑

用户在 Document 中编辑当前理解。

规则：

- 标题和正文默认可直接编辑。
- 不区分查看页和编辑页。
- 不存在 composing 模式。
- 不存在 dirty 状态。
- 不存在草稿状态。
- 本地变更按 local-first 方式持久化。
- 新建理解后立即成为当前选中理解。

### 3.3 来源查看

用户打开某条来源详情。

展示：

- Source Detail Overlay。
- 底层仍保持当前 Understanding Document。

规则：

- 关闭 overlay 后回到原理解。
- 来源编辑按 local-first 方式持久化。
- 关闭 overlay 不需要保存确认。

### 3.4 关系解析

用户在正文中输入或删除双链。

规则：

- 正文中的 `[[...]]` 是关系的唯一输入方式。
- 双链解析成功后，Relation 自动更新。
- 双链删除后，对应 Relation 自动移除。
- 解析异常时，在正文或关系展示区给出轻量状态。

## 4. 模块规格

### 4.1 Domain Navigation

职责：

- 让用户选择当前领域。
- 展示领域层级。
- 支持基础领域管理。

展示内容：

- 领域树。
- 当前选中领域。
- 可选的理解数量。

用户动作：

- 选择领域。
- 新建领域。
- 重命名领域。
- 调整领域层级。
- 删除领域。

交互逻辑：

- 点击领域后，Index 切换为该领域下的理解。
- 新建领域后，领域出现在当前层级，并进入可命名状态。
- 重命名领域时，字段为空则不能完成。
- 删除领域前需要确认。

业务规则：

- 领域层级由 `parentId` 表达。
- 删除领域不删除理解，只移除理解和该领域的归属关系。
- 如果理解只属于被删除领域，删除后进入未归类状态。
- 当前领域被删除后，页面选中父领域；没有父领域时选中默认根领域。

边界情况：

- 没有任何领域：展示创建领域入口。
- 领域名为空：不允许完成重命名。
- 同级领域重名：允许，但给轻量提示。

### 4.2 Understanding Index

职责：

- 展示当前领域里的理解。
- 帮助用户快速判断每条理解的内容、来源和关系状态。
- 提供新建理解入口。

展示内容：

- 理解标题。
- 正文摘要。
- 来源摘要。
- 关系摘要。
- 更新时间。
- 当前选中状态。

条目展示规则：

| 条件                   | 展示                                |
| ---------------------- | ----------------------------------- |
| 有标题                 | 展示标题                            |
| 无标题但有正文         | 用正文第一句生成临时标题            |
| 无标题也无正文         | 展示“未命名理解”                    |
| 有来源                 | 展示来源数量 + 首个来源名 / 类型    |
| 无来源                 | 不展示来源摘要，或展示轻量“无来源”  |
| 正文解析出 outgoing    | 展示“连接到 N 个理解”或首个连接标题 |
| 没有 outgoing relation | 展示“暂时独立”                      |
| 当前条目 selected      | 展示弱选中状态                      |
| 当前领域没有任何理解   | 展示空状态和“写下个人理解”入口      |
| 搜索无结果             | 展示无匹配状态，保留新建入口        |
| 当前理解被移出当前领域 | 从 Index 移除，并选中下一条可见理解 |

用户动作：

- 搜索当前领域理解。
- 选择理解。
- 新建理解。
- 从关系摘要跳转到相关理解。
- 从来源摘要进入来源详情。

交互逻辑：

- 点击条目后，Document 展示该理解。
- 点击新建后，立即创建一条空 Understanding。
- 新建 Understanding 默认归属当前领域。
- 新建后该 Understanding 立即出现在 Index，并成为当前选中理解。
- 搜索只过滤当前领域的理解。
- 搜索结果为空时，不删除当前选中理解。

业务规则：

- Index 只展示属于当前领域的理解。
- 属于子领域的理解是否展示在父领域，由后续筛选规则决定；MVP 默认只展示当前领域直接归属的理解。
- 独立理解不是错误状态，不使用警告语义。

边界情况：

- 当前领域为空：展示空状态和新建入口。
- 新建空理解后：Index 展示“未命名理解”。
- 理解被移出当前领域：Index 立即移除该条；Document 切换到下一条或空状态。
- 理解被删除：从 Index 移除；Document 切换到下一条或空状态。

### 4.3 Understanding Document

职责：

- 展示和编辑当前理解。
- 承载来源、领域归属和关系展示。

展示内容：

- 当前领域语境。
- 更新时间。
- 标题。
- 正文。
- 来源摘要区。
- 领域归属区。
- 关系展示区。

编辑规则：

- 标题和正文默认可直接编辑。
- 不区分查看态和编辑态。
- 不展示保存按钮。
- 不展示未保存状态。
- 不展示保存失败状态。
- 用户输入按 local-first 方式持久化。

用户动作：

- 编辑标题。
- 编辑正文。
- 添加来源。
- 打开来源详情。
- 调整领域归属。
- 通过正文双链连接已有理解。
- 删除正文双链以移除关系。
- 跳转到相关理解。
- 删除当前理解。

交互逻辑：

- 编辑标题后，Index 标题同步更新。
- 编辑正文后，Index 摘要同步更新。
- 正文里的 `[[...]]` 会被解析为关系。
- 解析成功后，关系展示区同步更新。
- 删除正文双链后，关系展示区同步移除对应关系。
- 删除理解需要确认。

业务规则：

- 空标题 + 空正文允许存在，因为新建理解就是立即创建空理解。
- 标题为空但正文不为空时，Index 使用正文第一句作为临时标题。
- 标题和正文都为空时，Index 展示“未命名理解”。
- 理解内容本地持久化，不经过远端保存状态。

边界情况：

- 当前理解被移出当前领域：从当前 Index 消失，并选中下一条。
- 当前理解没有来源：Source Area 展示添加来源入口。
- 当前理解没有关系：Relation Area 展示暂时独立。
- 当前理解正文存在未解析双链：Relation Area 展示未解析状态。

### 4.4 Source Area

职责：

- 展示当前理解的来源摘要。
- 支持添加、查看、编辑和删除来源。

展示内容：

- 来源类型。
- 来源名或场景。
- 内容摘录。
- 字数或轻量元信息。
- 添加来源入口。

展示规则：

| 条件         | 展示                           |
| ------------ | ------------------------------ |
| 有来源       | 展示 source trace 列表         |
| 无来源       | 展示添加来源入口               |
| 来源较长     | 只展示摘要，完整内容进 overlay |
| 来源名为空   | 用来源类型作为 placeholder     |
| 来源内容为空 | 展示内容 placeholder           |

用户动作：

- 添加来源。
- 打开来源详情。
- 编辑来源类型。
- 编辑来源名称。
- 编辑来源内容。
- 删除来源。

交互逻辑：

- 点击来源摘要打开 Source Detail Overlay。
- 新增来源从 Document 的 Source Area 触发。
- 新增来源时创建一条绑定当前 Understanding 的 Source。
- 删除来源需要确认。
- 来源编辑按 local-first 方式持久化。

业务规则：

- 来源必须绑定当前理解。
- 来源删除后，从当前理解的 source query 结果中消失。
- 来源不是全局独立页面，不提供来源库管理。

边界情况：

- 来源很多：MVP 按更新时间或创建顺序展示，不做复杂排序。
- 来源内容很长：Document 中只展示摘要。
- 最后一条来源被删除：Source Area 回到无来源状态。

### 4.5 Domain Assignment

职责：

- 展示和调整当前理解所属领域。

展示内容：

- 当前领域。
- 其他所属领域。
- 未归类状态。
- 添加领域入口。

展示规则：

| 条件           | 展示              |
| -------------- | ----------------- |
| 属于当前领域   | 展示当前领域      |
| 属于多个领域   | 展示所有领域      |
| 新建理解       | 默认展示当前领域  |
| 无领域归属     | 展示“未归类”      |
| 从当前领域移除 | 从当前 Index 移除 |

用户动作：

- 添加领域归属。
- 移除领域归属。
- 跳转到某个所属领域。

交互逻辑：

- 添加领域时，用户从已有领域中选择。
- 移除当前领域时，该理解从当前 Index 消失。
- 如果理解仍属于当前领域，保持当前选中。
- 如果理解不再属于当前领域，Index 选中下一条。

业务规则：

- 一个理解可以属于多个领域。
- 一个理解可以没有领域归属。
- 未归类理解后续可以从未归类视图或全局搜索找回。

边界情况：

- 移除最后一个领域：允许，理解进入未归类。
- 添加重复领域：不重复添加。

### 4.6 Relation Area

职责：

- 展示当前理解正文双链解析出的关系。
- 展示 incoming / outgoing。
- 展示未解析双链状态。

展示内容：

- 当前理解引用了哪些理解。
- 哪些理解引用了当前理解。
- 每个相关理解的标题、摘要、所属领域。
- 当前理解是否暂时独立。
- 未解析双链。

展示规则：

| 条件                 | 展示                   |
| -------------------- | ---------------------- |
| 有 outgoing relation | 展示“引用了”列表       |
| 有 incoming relation | 展示“被引用”列表       |
| 两者都没有           | 展示“暂时独立”         |
| 双链标题唯一匹配     | 展示已连接关系         |
| 双链标题匹配多个理解 | 展示需要选择目标       |
| 双链标题不存在       | 展示未解析             |
| 关系目标不在当前领域 | 仍展示，并标明所属领域 |

用户动作：

- 跳转到相关理解。
- 处理重名双链目标。
- 从未解析双链创建新理解。
- 回到正文修改或删除双链。

不支持：

- 不支持手动添加关系。
- 不支持手动删除关系。
- 不支持在 Relation Area 搜索并连接已有理解。
- 不支持将当前理解手动标记为独立。

交互逻辑：

- Relation Area 从正文双链解析结果读取关系。
- 点击相关理解时，Document 切换到目标理解。
- 重名双链需要用户选择具体目标。
- 不存在的双链目标可以创建新理解；创建后双链绑定到新理解。
- 删除关系必须回到正文删除对应双链。

业务规则：

- outgoing relation 来自当前理解正文。
- incoming relation 来自其他理解正文。
- 同一对理解只保留一条 relation。
- 关系随正文双链变化自动更新。

边界情况：

- 目标理解被删除：关系失效，Relation Area 展示失效状态。
- 目标理解被移出当前领域：关系保留，展示目标所属领域变化。
- 双链链接到自己：不建立关系，并展示无效状态。

### 4.7 Body Double Link

职责：

- 让用户在正文写作中自然建立理解关系。

语法：

```text
[[理解标题]]
```

交互逻辑：

- 用户输入 `[[` 后，可以出现理解搜索建议。
- 用户选择建议后，插入 `[[目标理解标题]]`。
- 用户手动输入完整 `[[...]]` 后，系统解析。
- 解析成功后建立 relation。
- 用户删除双链后，对应 relation 自动移除。

解析规则：

| 条件             | 处理                                   |
| ---------------- | -------------------------------------- |
| 标题唯一匹配     | 建立到该理解的关系                     |
| 标题匹配多个理解 | 要求用户选择目标                       |
| 标题不存在       | 标记为未解析，可创建新理解或修改文本   |
| 双链为空         | 标记为无效，不建立关系                 |
| 链接到自己       | 不建立关系，并提示不能连接当前理解本身 |

业务规则：

- 双链是建立 relation 的唯一入口。
- 关系保存为 `fromUnderstandingId -> toUnderstandingId`。
- 正文显示仍保持双链表达。
- relation 不需要 `origin` 字段，因为只有双链一种来源。

边界情况：

- 目标理解重命名：MVP 可以保留原双链文本，relation 绑定目标 `id`。
- 目标理解删除：双链标记为失效关系，用户通过修改正文解决。

### 4.8 Local Persistence

职责：

- 让页面编辑结果直接进入本地状态。
- 避免把 local-first app 做成远端保存模型。

规则：

- 新建理解时立即创建空 Understanding。
- 标题、正文、来源、领域归属和关系解析结果都按 local-first 方式持久化。
- 页面不展示保存按钮。
- 页面不展示未保存、保存中、已保存、保存失败。
- 页面不处理网络错误。
- 页面不需要离开确认。

边界情况：

- 本地存储异常属于底层系统错误，不在本页面 PRD 中展开。
- 用户撤销、历史版本、冲突处理不属于 MVP。

### 4.9 Graph Observation

职责：

- 辅助观察当前领域的关系结构。

MVP 状态：

- 非默认主入口。
- 可以作为后续观察模式。

展示内容：

- 当前领域内理解节点。
- 由正文双链解析出的关系边。
- 暂时独立节点。
- 选中节点的来源摘要。

业务规则：

- 图谱只呈现双链关系。
- 图谱不自动生成关系。
- 图谱不提供手动建边。
- 图谱不替代 Index 和 Document。

## 5. 核心流程

### 5.1 新建理解

```text
选择领域
  -> 点击“写下个人理解”
  -> 立即创建空 Understanding
  -> 新理解出现在当前领域 Index
  -> Document 选中新理解
  -> 用户直接编辑标题 / 正文
```

边界：

- 新建后标题和正文可以都是空。
- 空理解在 Index 展示为“未命名理解”。
- 新建理解默认归属当前领域。

### 5.2 回看领域

```text
选择领域
  -> 浏览 Index
  -> 选择理解
  -> 阅读 Document
  -> 查看来源摘要和关系
  -> 必要时直接编辑
```

边界：

- 当前领域为空：展示空状态和新建入口。
- 搜索无结果：保留搜索词，展示无匹配状态。
- 切换理解不需要保存确认。

### 5.3 补来源

```text
打开理解
  -> 点击添加来源
  -> 创建 Source
  -> 编辑来源类型、名称、内容
  -> Source Area 更新摘要
  -> Index 更新来源摘要
```

边界：

- 来源内容为空：允许存在。
- 来源名称为空：用来源类型作为 placeholder。
- 删除最后一个来源：Source Area 回到无来源状态。

### 5.4 建立关系

```text
编辑正文
  -> 输入或选择 [[已有理解标题]]
  -> 系统解析双链
  -> 建立 relation
  -> Relation Area 更新 outgoing
```

边界：

- 双链目标不存在：标记未解析，可创建新理解或修改文本。
- 双链目标重名：要求用户选择目标。
- 目标是当前理解：不允许建立关系。
- 关系已存在：不重复创建。
- 删除双链：对应 relation 自动移除。

### 5.5 调整领域归属

```text
打开理解
  -> 编辑领域归属
  -> 添加或移除领域
  -> Index 根据当前领域归属刷新
```

边界：

- 移除当前领域：当前 Index 移除该理解。
- 移除最后一个领域：理解进入未归类。
- 添加重复领域：忽略重复添加。

## 6. 全局展示条件

| 场景                 | 页面行为                                        |
| -------------------- | ----------------------------------------------- |
| 当前领域为空         | Index 展示空状态，Document 展示新建入口         |
| 当前领域有理解       | Index 展示理解列表，Document 展示当前选中理解   |
| 没有选中理解         | Document 展示当前领域的新建入口                 |
| 新建空理解           | Index 展示“未命名理解”，Document 展示空标题正文 |
| 当前理解无来源       | Source Area 展示添加来源入口                    |
| 当前理解无关系       | Relation Area 展示暂时独立                      |
| 当前理解有 incoming  | Relation Area 展示被引用列表                    |
| 当前理解有 outgoing  | Relation Area 展示引用了列表                    |
| 当前理解被删除       | Index 移除条目，Document 选中下一条或进入空状态 |
| 当前理解移出当前领域 | Index 移除条目，Document 选中下一条或进入空状态 |
| 搜索无结果           | Index 展示无匹配状态，保留新建入口              |
| 双链目标不存在       | Relation Area 展示未解析状态                    |
| 双链目标重名         | Relation Area 展示需要选择目标                  |

## 7. 验收标准

### 7.1 功能验收

- 用户可以从领域进入当前领域的理解列表。
- 用户点击新建后，立即创建空 Understanding。
- 空 Understanding 会出现在当前领域 Index。
- 用户可以直接编辑理解标题和正文。
- 用户可以给理解添加来源，并从摘要进入来源详情。
- 用户可以通过正文双链连接已有理解。
- 用户删除正文双链后，对应关系消失。
- 用户可以看到当前理解引用了谁，以及谁引用了当前理解。
- 用户可以把理解归属到多个领域。
- 用户可以从当前领域移除理解，并看到列表同步变化。
- 用户可以保留没有来源、没有关系的理解。

### 7.2 边界验收

- Domain 没有 `children` 字段。
- Understanding 没有 `sourceIds` 字段。
- Source 没有 `trigger` 字段。
- Relation 没有 `origin` 字段。
- Relation 只能从正文双链解析产生。
- 页面没有手动添加关系入口。
- 页面没有手动删除关系入口。
- 页面没有 dirty 状态。
- 页面没有 draft 状态。
- 页面没有保存按钮和保存状态。
- 页面没有 composing 模式。
- 双链目标不存在时不会静默建关系。
- 双链目标重名时不会随意选一个目标。
- 关系目标是当前理解时不能建立关系。
- 重复关系不会重复展示。

### 7.3 非目标验收

- 页面不提供来源管理后台。
- 页面不提供关系管理后台。
- 页面不自动生成关系。
- 页面不支持手动添加关系。
- 页面不支持手动删除关系。
- 页面不强迫每条理解必须有来源。
- 页面不强迫每条理解必须有关系。
